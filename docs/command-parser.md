# A-003: разбор команд, черновик

Модули `firmware/protocol/mt_command.h/c` отделяют байты команды от её
исполнения. Автор — Dot A. Код и авторские тесты сохранены через GitHub;
компиляция, запуск тестов и независимое ревью **не выполнялись**.

## Что делает модуль

Парсер читает little-endian payload команд HELLO, GET_CAPS, CONFIG, ARM,
STOP, GET_STATUS и RELEASE_WINDOW. Каждая длина проверяется на точное
совпадение до первого чтения полей. Дополнительный хвост тоже запрещён.
Ненулевые reserved CONFIG отклоняются. HELLO с нулевым nonce отклоняется.

Типы сообщений устройства отделены от неизвестных типов, чтобы диспетчер
мог различить неверное направление и неподдерживаемую команду.
На отказе выходной объект не меняется. Это важно: старую принятую команду
нельзя по ошибке исполнить повторно после неудачного разбора новой.

Отдельная чистая функция проверяет CONFIG:
- профиль 1;
- Auto/Normal/Single и analog/external, rising/falling;
- наличие каждой возможности в реально реализованных масках;
- level_code от 1 до 4094, в том числе сохранённый при external;
- предысторию 0, 512 или 1024, с учётом поддержки;
- для Auto timeout от 100 до 60000 мс, для остальных режимов строго 0.

Внутренняя структура поддержки не равна сериализованному CAPS.
Она должна поступать из фактической реализации. Нельзя выставить все биты
ради прохождения теста и объявить эти функции доступными пользователю.
Тестовая маска all используется только для проверки чистой функции.

## Чего модуль не делает

Он не проверяет session, sequence, request, конфигурационное поколение,
текущее состояние или занятость буфера. Не создаёт config_id, не вооружает
АЦП, не останавливает DMA и не отправляет ACK/ERROR. Значения config_id,
generation и window_id декодируются без подмены; их допустимость определяется
текущим сеансом и состоянием. STOP(0) здесь разрешено разобрать, но это не
разрешение останавливать произвольное поколение.

Также это не USB-драйвер, не TX-очередь и не готовая прошивка.
Разбор payload не отменяет порядка проверки из wire-v0.1.md.

## Подключение будущего диспетчера

1. Сначала byte codec проверяет целостность/версию/reserved заголовка.
2. Проверяется направление. HELLO идёт по особому пути с проверкой
   session=0, sequence=1, request=1, payload и нового nonce.
3. Для обычных команд проверяются session, sequence и request.
4. Только после этих проверок решается вопрос об ERROR с request_id.
5. Синтаксический разбор CONFIG и проверка возможности принять CONFIG
   в текущем состоянии не заменяют семантическую проверку параметров.
6. При ошибке старые настройки, буфер и поколение остаются неизменными.
7. При успешной CONFIG будущая реализация должна вернуть реально принятые
   значения и только затем разрешить ARM с соответствующим config_id.

Предлагаемое отображение результатов:
- LENGTH / RESERVED: INVALID_PAYLOAD после достоверного обычного запроса;
- UNKNOWN_TYPE: UNKNOWN_TYPE после проверок сеанса и порядка;
- WRONG_DIRECTION: восстановление протокола без исполнения;
- INVALID_HELLO: игнорировать некорректный handshake, не менять сеанс;
- semantic CONFIG false: INVALID_CONFIG, если причина не в состоянии/BUSY;
- ARGUMENT: ошибка вызова внутри программы, не ошибка устройства пользователя.

При нескольких одновременно неверных условиях приоритет определяет
диспетчер по общему wire-контракту. Чистый parser его не выбирает.
Здесь нет самостоятельного разрешения отправлять ответы на мусор.

## Подготовленные тесты

`tests/protocol/test_mt_command.c` проверяет в исходниках:
точные длины всех семи команд, неверное направление, неизвестный тип,
неизменность output на отказе, endian-поля, все reserved CONFIG,
нулевой/ненулевой nonce, сохранение STOP(0), комбинации поддерживаемых
настроек, границы уровня/тайм-аута и неподдерживаемые маски/значения.

Будущая команда, не выполненная в этой итерации:

```sh
cc -std=c11 -Wall -Wextra -Wpedantic -Werror \
  firmware/protocol/mt_command.c tests/protocol/test_mt_command.c \
  -o /tmp/test_mt_command
/tmp/test_mt_command
```

NDEBUG не определять. Нужны разрешённый запуск с санитайзерами, независимые
векторы и отдельные интеграционные тесты сеанса/диспетчера. Чтение автором
не заменяет эти доказательства; результат остаётся draft.
