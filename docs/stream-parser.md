# A-002: накопитель потока, черновик

Автор реализации и этих тестов — Dot A. Это **не независимое ревью**.
Код написан через подключение GitHub средствами Dot. Сборка, исполнение тестов,
санитайзеры, ARM, USB и аппаратная проверка для этой итерации **не выполнялись**.
Никакой оценки 9,5/10 или готовности прибора не присваивается.

## Назначение

USB может вернуть часть сообщения или несколько сообщений сразу. Модуль
`firmware/protocol/mt_stream.c` сохраняет ненулевые байты до разделителя 0,
затем передаёт ровно один COBS-кадр существующему `mt_wire_decode`.
Он не зависит от размеров USB-пакетов, драйвера или наличия настоящего устройства.

Действия:
- Пустой разделитель игнорируется.
- До 543 ненулевых байтов хранятся в фиксированном массиве.
- Следующий ненулевой байт вызывает OVERFLOW; весь остаток до нуля отбрасывается.
- Ошибка декодирования возвращает REJECTED без изменения выходного сообщения.
- Межбайтовый интервал от 1000 мс или длительность кадра от 3000 мс
  вызывают TIMEOUT и тот же режим отбрасывания.
- Разделитель, пришедший точно на границе тайм-аута, завершает отбрасывание,
  но не делает просроченный кадр успешным.
- После разделителя следующий кадр можно принимать независимо.

Успех MESSAGE означает только прохождение byte codec. Направление, сеанс,
sequence, request, payload и состояние прибора проверяет отдельный диспетчер.
Не отправлять ERROR по повреждённому кадру с недостоверным заголовком.

## Подключение к будущему транспорту

1. Разместить один объект `mt_stream` в статической памяти.
2. Один раз вызвать init после настоящего сброса транспорта, затем feed на
   каждый байт принятого потока. Не сбрасывать объект между USB reads.
3. Принимать и декодировать в основном цикле, не в IRQ.
4. Регулярно вызывать poll даже при отсутствии входящих данных. Время —
   монотонный uint32 в миллисекундах; обычный переход через UINT32_MAX допустим.
   Обслуживание с паузами >= 2^31 мс или с нарушенным порядком времени не входит
   в контракт. После такого разрыва нужен явный transport reset.
5. На MESSAGE передать отдельный объект сообщения диспетчеру; на остальные
   события не использовать прежний message как вновь полученную команду.
6. USB detach/reset должен останавливать захват на уровне транспорта/сеанса.
   Один init накопителя не выполняет эту обязанность.

API побайтовый специально: нет скрытого callback, времени жизни указателя
на внутренний буфер или неопределённого количества обработанных кадров.
Оба объекта принадлежат одному foreground-контексту и не перекрываются.
NULL-аргументы feed возвращают ARGUMENT без потребления байта.

## Память

В объекте — массив 543 байта, счётчик длины, два uint32 времени и состояние.
Полный sizeof зависит от ABI и выравнивания, его следует измерить сборкой.
Существующий decoder дополнительно использует 540 байт локального массива.
Выходной mt_wire_message, USB-очереди и стек диспетчера считаются отдельно;
этот документ не подтверждает общий бюджет SRAM проекта.

## Подготовленные проверки

`tests/protocol/test_mt_stream.c` — авторские, пока не выполненные проверки:
- все позиции разделения максимального payload между двумя reads;
- два последовательных сообщения без reset;
- пустой разделитель и malformed COBS, сохранение output при отказе;
- точная граница переполнения и отбрасывание до нуля;
- межбайтовый и общий timeout, точные границы;
- rollover uint32 времени;
- NULL, отсутствие изменения состояния при неверном аргументе;
- явный reset незавершённого кадра.

В проверке используются assert; компиляция с NDEBUG запрещена.
Подготовленная команда для будущего разрешённого исполнителя из корня репозитория:

```sh
cc -std=c11 -Wall -Wextra -Wpedantic -Werror \
  firmware/protocol/mt_wire.c firmware/protocol/mt_stream.c \
  tests/protocol/test_mt_stream.c -o /tmp/test_mt_stream
/tmp/test_mt_stream
```

Отдельно нужны ASan/UBSan, независимые повреждённые CRC/version/reserved
векторы, проверки случайных разбиений/мусора и ARM sizeof/stack evidence.
Команды здесь — инструкция, а не журнал выполненного запуска.
Любой будущий запуск допустим только в среде, соответствующей актуальному
ограничению владельца на Work/Codex, API и дополнительные кредиты.
