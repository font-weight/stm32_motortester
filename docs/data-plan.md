# Данные, анализ сигналов и машинное обучение

Область применения от 10.10.2026: для текущего [MVP](mvp-spec.md) действуют правила сохранения исходных отсчётов, метаданных и происхождения записей. Разделы диагностических признаков, разметки, ML и DIAMAG сохранены для будущего развития; выполнять их до завершения регистратора не требуется.

## Проверяемые вопросы

1. Можно ли воспроизводимо регистрировать отклик стенда и измерять выбранные параметры?
2. Различаются ли сигналы выбранных образцов при сопоставимых условиях?
3. Сохраняется ли различение после переустановки датчика и нового сеанса?
4. При наличии нескольких экземпляров каждого класса — переносится ли модель на другую физическую катушку той же конструкции?

Положительный ответ на один вопрос не доказывает следующий. Перенос на автомобиль и другие модели катушек — отдельные эксперименты. Два графика для презентации — иллюстрация, не весь набор данных.

## Собственный стенд — основной источник

Методика пилота — в [bench.md](bench.md). Начать с проверки повторяемости и доступной пары. Количество новых экземпляров определять после пилота по доступности, бюджету и нужному утверждению о переносе.

Слова «неисправная катушка» требуют определения дефекта. Полный отказ, нестабильный разряд на стенде и пробой только при нагрузке двигателя не считать одним доказанным механизмом. Состояние без подтверждения маркировать unknown.

## Что именно размечаем

| Уровень | Значение и основание |
|---|---|
| Качество записи — capture_quality | Целостность, пропуски, перегрузка и пригодность для конкретного признака |
| Электрический отклик — response_observation | Обнаружен / не обнаружен / неопределённо; результат анализа сигнала, не диагноз |
| Разряд — discharge_observation | Независимое наблюдение разряда и способ наблюдения либо unknown |
| Катушка — coil_condition | Подтверждённое состояние экземпляра в указанных условиях и ссылка на основание либо unknown |

Перед ML выбрать цель: исход конкретной команды или состояние физического экземпляра. Неисправная катушка иногда даёт разряд; её состояние не является меткой каждого события «искры нет». Наш детектор не создаёт независимую диагностическую метку для обучения самого себя. Неизвестное значение хранить как unknown, не как ноль.

## Группы и метаданные

`coil_id` обозначает физическую катушку; `session_id` — общий сеанс измерений, включающий сравниваемые катушки; `mounting_id` — отдельное закрепление датчика; `condition_id` — документированный набор условий. Повторные окна без переустановки не образуют новые независимые сеансы.

Поля ниже относятся к стенду. Для LV-001 обязательны источник низковольтного сигнала, идентификатор записи, настройки захвата и тракта, шкалы и статусы качества; катушка, разряд и аппаратный запуск могут быть неприменимы. Различать «не применимо» и «неизвестно», не создавать фиктивную катушку или индекс запуска. Для любой записи явно указывать вид опыта: синтетика, низковольтный сигнал, стенд или автомобиль.

| Группа | Поля |
|---|---|
| Идентификация | record_id, coil_id, session_id, mounting_id, condition_id, command_id, время записи |
| Объект | Модель и маркировка катушки, происхождение, конструкция, состояние и основание метки |
| Условия | Питание и его ограничения, режим управления/dwell, частота команд, прогрев/температура если измерялась |
| Вторичная цепь | Свеча, зазор по принятой методике, провод, геометрия стенда |
| Датчик | Модель/конструкция, идентификатор, положение и повторная установка |
| Прибор | Версии аппаратуры/прошивки, канал, запрошенная Fs, номинальная Fs из установленных делителей и измеренная Fs при наличии проверки, разрядность, опора, масштаб, фильтр, калибровка |
| Синхронизация | Источник запуска, индекс запуска, временная привязка к команде, интервалы нечувствительности |
| Качество | Флаги записи и признаков, насыщение, шум, пропуски, обрезанное границей окна событие, питание вне условий, причина исключения |
| Разметка | Раздельные уровни из таблицы выше, кто/как установил состояние, дата, ручные границы событий |
| Происхождение | Собственная запись/внешний источник, ссылка и условия использования |

У каждой выданной команды есть сохранённое окно или причина его отсутствия. Условия можно хранить один раз на сеанс/конфигурацию со ссылкой из записи. Идентификаторы, даты, имена файлов и версии прибора — метаданные для проверки, а не признаки модели.

## Последовательность анализа

1. **Контроль качества:** число отсчётов, настройки, целостность, клиппинг и запуск.
2. **Шкалы:** перевести время по Fs с отметкой, проверена ли она независимо; амплитуду — по известной калибровке входа. Постоянный уровень и мультиметр не проверяют временную шкалу. Не подписывать кВ на свече без основания.
3. **Сегментация:** выделить окно относительно команды. Сохранять примеры без отклика.
4. **Обработка:** при необходимости оценить базовую линию и применить обоснованную фильтрацию. Показать влияние на пик и временные границы.
5. **Признаки:** начать с небольшого набора величин для одного окна: наличие отклика, длительность различимого участка вторичного отклика, относительная амплитуда. Повторяемость оценивается по серии, а не по одному окну. Интерпретация длительности как времени разряда требует отдельного подтверждения. Клиппинг пика может запрещать его амплитуду, но не обязательно все последующие временные измерения.
6. **Базовые правила:** простые пороги/логика, определённые на обучающей части или независимой калибровке.
7. **ML:** логистическая регрессия либо небольшое дерево по ограниченному набору признаков; выбор уточнить по пилотным данным.
8. **Сравнение:** ошибки правил и модели на одних проверочных группах. Преимущество ML не является обязательным исходом эксперимента.

Если отклика нет, его длительность может быть «не определена». Не подменять все такие признаки нулями без явного правила и отдельного признака наличия отклика. Нормировка каждой записи на собственный максимум может стереть полезную амплитудную информацию; её применение нужно обосновать.

Если участок продолжается за границу окна или скрыт восстановлением тракта, не выдавать видимую часть за его полную длительность. При неподтверждённых метках состояния классификацию неисправностей отложить; измерение признаков и повторяемости остаётся полезным результатом.

Синтетические сигналы пригодны для проверки программной логики, но не подтверждают диагностическую точность. Аугментации выполняются после разделения и только для обучающей части.

## Независимая проверка

| Проверяемое утверждение | Что оставить вне разработки и обучения |
|---|---|
| Различение знакомых образцов в новом сеансе | Целый session_id с обеими катушками |
| Перенос на новый экземпляр при представленных условиях | Целый coil_id со всеми его записями |
| Перенос на новый экземпляр в новом сеансе | И экземпляр, и проверочный сеанс |
| Перенос на другой режим, прибор или автомобиль | Отдельные записи соответствующего условия |

- Разделение делать до обучения нормировки, отбора признаков, порогов и модели.
- Настройка модели не должна использовать результат того же внешнего разбиения, которое затем выдаётся за независимую оценку.
- Дубликаты и соседние окна одной записи не распределять случайно между train и test.

Если доступна только одна катушка каждого состояния, класс совпадает с идентичностью экземпляра. Проверка на новом сеансе оценивает различение этих двух образцов, а не неизвестных катушек. При добавлении экземпляров заранее зафиксировать простую схему групповой проверки и настройки модели; количество катушек само по себе не гарантирует достаточность. Основания: [S11](sources.md#s11), [S12](sources.md#s12).

## Результаты для диплома

- Для измерений: ошибки временных параметров, повторяемость и условия сравнения.
- Для детектора: пропуски откликов и ложные обнаружения.
- Для классификатора: матрица ошибок, метрики по классам и результаты по отдельным катушкам/сеансам.
- Указывать отдельно число катушек, сеансов, выданных команд, сохранённых окон, пригодных примеров и отказов от решения; причины исключений показывать по группам.
- Не считать доверительные границы по тысячам зависимых импульсов как по независимой выборке.
- В презентации оставить два понятных примера с одинаковыми шкалами, настройками и указанием условий; в приложении сохранить полный протокол.

## DIAMAG — дополнительная ветка

Официальная страница публикует примеры зажигания hanter_ign.dm2 и niva164_ign.dm2 и сообщает о сжатии выложенных файлов ([S10](sources.md#s10)). Это не доказательство шифрования. Наличие записи не подтверждает метку «исправно» или конкретную неисправность.

Из официального архива руководства прочитаны HTML-страницы CHM: `_file_menu.htm` описывает сохранение .dm2 и экспорт PNG, `graffsave.htm` — PNG, `samopis.htm` — опцию сжатия. Поиск по справке не подтвердил численный экспорт; версия справки неизвестна, актуальный интерфейс программы не проверялся ([S16](sources.md#s16)). Это не доказывает отсутствие CSV во всех версиях.

Проверен заголовок официального `niva164_ign.dm2`: файл начинается с ASCII `DIAMAGZ`. Это наблюдение одного образца; оно не определяет алгоритм сжатия, поля контейнера или расположение отсчётов. Численные данные не извлечены. Контрольная сумма и границы исследования — [S17](sources.md#s17).

Первоначальное исследование ограничено двумя рабочими сессиями. Остаётся проверить численный экспорт в доступной версии программы и метаданные; при необходимости исследовать копии файлов. Импорт сверять по числу отсчётов, времени, амплитуде и контрольным участкам. Открытая спецификация, поддерживаемый парсер и условия использования для ML не подтверждены. Сообщения производителю без поручения не отправлять. Если воспроизводимого пути нет, продолжить на собственных данных; PNG не заменяет отсчёты.

Не смешивать записи разных приборов вслепую. Различия полосы, датчика, масштаба и фильтров могут стать признаком класса. Перенос DIAMAG → собственный прибор оценивается на независимых собственных записях.

Ограниченный поиск других открытых наборов пока не дал подтверждённой замены собственному пилоту. Для библиотеки Pico производитель указывает требования доступа, а найденные наборы с похожими словами могут описывать другой физический процесс. Результат проверки — [S19](sources.md#s19).
