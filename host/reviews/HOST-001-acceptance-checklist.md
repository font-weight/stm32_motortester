# HOST-001: критерии первого пути данных приложения

Дата: 10.10.2026. Версия критериев: 1.0, до ревью реализации.

Это checklist ограниченной задачи, а не PASS реализации, не утверждение общего протокола и не объявление готовности MVP. Исходный изученный commit: `3fe1a2d8c53f77e0510a3da9ddd125f68cb872fa`. Точный head реализации, base diff и номер issue/PR должны быть добавлены в отдельный отчёт при предъявлении результата.

Проверяющий: независимый Critic-B, модель `gpt-6-astra`, reasoning `xhigh`. Предыдущий критик заменён до реализации и выдачи вердикта исключительно из-за явного требования пользователя к модели, а не ради изменения оценки. Этот критик не пишет production-код или тесты проверяемой реализации; область записи — только `host/reviews/`.

## 1. Заранее ограниченная область

Результат: **внутреннее сообщение явно обозначенного эмулятора → массив одного канала → собственный версионированный файл → повторное открытие → простой график**. Уровень проверки — программа/синтетические данные на точно указанной доступной ОС.

Пока A и B не согласовали wire-контракт, сообщение эмулятора является внутренним входом приложения через заменяемый источник данных. Оно не называется USB-пакетом, эталоном общего wire-протокола или доказательством совместимости с прошивкой. Наличие такой границы позволяет проверить файлы и график без создания второго протокола.

Область реализации принадлежит B: точные файлы внутри `host/` и их владельцев фиксирует карточка задачи. Общие `protocol/`, firmware, hardware, CI и документы владельца A этим checklist не передаются. Формат записи принадлежит B; его описание и совместимость входят в эту задачу в объёме реализованного формата.

Основания: [задание B](../../DOT_PEER_START.md), [ТЗ MVP, разделы 2, 5, 8, 9](../../docs/mvp-spec.md), [FR-05/06, PERF-02/06, DATA-01, DOC-01/02](../../requirements.md), [происхождение записей](../../docs/data-plan.md), [координация](../../docs/coordination.md), [фиксированная рубрика](../../docs/quality-gate.md).

## 2. Обязательные проверки HOST-001

Отметка выполнения должна указывать команду/сценарий, фактический результат и артефакт. Количество тестов само по себе не является доказательством качества.

### H01. Сквозной путь воспроизводится

- [ ] Из чистого checkout указанного SHA выполняются документированные установка зависимостей, запуск проверок и демонстрация. Версии инструментов/зависимостей и ОС записаны; команды не предполагают скрытых файлов автора.
- [ ] Один воспроизводимый сценарий проходит все пять стадий, включая чтение файла с диска новым экземпляром загрузчика или новым запуском программы. График строится из заново открытой записи, а не из оставшегося массива эмулятора.
- [ ] Минимальный контрольный пример известен независимо от сериализатора: описаны ожидаемые отсчёты, метаданные, длина и точки графика. Есть пример проектного профиля 2048 отсчёта при номинальных 50 kS/s; это синтетический профиль, не опыт LV-001.

Связь: MVP-U06/U09, FR-05, DOC-01.

### H02. Исходные данные сохраняются точно

- [ ] Одноканальные коды 12-битного АЦП представлены целыми значениями, хранятся без потерь с документированным 16-битным представлением/порядком байтов. Сохранение и чтение возвращают тот же массив побитно в его определённом исходном представлении.
- [ ] Проверены границы 0 и 4095, промежуточные несимметричные значения и порядок отсчётов. Отрицательные, дробные и выходящие за диапазон значения не обрезаются и не округляются молча.
- [ ] Отрисовка, изменение масштаба и повторное сохранение не изменяют исходный массив. Изменение следующего окна или буфера источника не меняет уже полученную запись.

Связь: PERF-02, FR-05, MVP-U04/U06.

### H03. Формат и метаданные описаны

- [ ] Есть признак/версия формата, границы размера и длины, число/описание каналов, идентификатор записи и происхождение `synthetic` или однозначный эквивалент. Указана политика неподдерживаемых версий и расширений.
- [ ] Сохраняются применимые настройки, номинальная Fs и происхождение временной шкалы, разрядность, единицы амплитуды, статус калибровки, происхождение метки времени, сведения о запуске, версии источника/приложения и качество/ошибки. Неизвестные и неприменимые аппаратные значения явно различены и не выдуманы.
- [ ] После открытия совпадают обязательные метаданные. Отсутствующий реальный запуск остаётся отсутствующим: индекс не подставляется как 0. Не появляется фиктивная физическая катушка, измеренная Fs или версия работающей прошивки.

Связь: MVP-U06/U09, ТЗ §5, DATA-01, data-plan «Группы и метаданные».

### H04. Загрузчик не принимает недостоверную запись как исправную

- [ ] Проверены неизвестная версия, пустой/обрезанный/повреждённый файл, неверная длина или число отсчётов и противоречивые обязательные метаданные. Повреждение, которое обещает обнаруживать описанная проверка целостности, действительно обнаруживается.
- [ ] Fs обязана быть конечной и положительной; индекс запуска, если задан, находится внутри массива. Проверены нулевые/отрицательные/чрезмерные длины, нечисловые и неограниченные значения в тех полях, которые формат позволяет передать.
- [ ] До крупных выделений памяти проверяются документированные максимумы файла, метаданных и массива. Ошибка загрузки понятна пользователю, не приводит к падению и не заменяет последнюю корректную запись незаметно.
- [ ] Неполная запись либо явно отклоняется в рамках данного прототипа, либо показывается как неполная с корректными разрывами. Пропуски не достраиваются нулями и не изображаются непрерывным достоверным сигналом.

Связь: FR-06, MVP-U07, ТЗ §8 «повреждённый файл», требование ограниченных ресурсов quality-gate C2. Полная поддержка повреждённых wire-пакетов сюда не переносится.

### H05. Сохранение и пользовательские ошибки безопасны

- [ ] Успех сохранения сообщается только после успешной записи. Недоступная папка/отказ записи не уничтожают существующий исправный файл; стратегия безопасного обновления описана и проверена применимым сценарием.
- [ ] Отмена открытия/сохранения, повторное открытие и открытие неверного файла оставляют понятное состояние. Уже показанная запись не выдаётся за успешно открытую новую.
- [ ] Демонстрацию можно закрыть и запустить повторно. Имена файлов и сообщения на русском не ломают реализованный путь. Долгая или некорректная операция не оставляет интерфейс без возможности восстановления; проверка соотносится с заявленными максимальными размерами.

Связь: MVP-U06/U07 и общие требования §5 к отзывчивости. Это не приёмка всех режимов Run/Stop или Windows-установщика.

### H06. График соответствует данным и не преувеличивает измерение

- [ ] Реально запущенный интерфейс или заявленный графический просмотрщик показывает заново открытую запись. Сохранены снимок и сценарий, а численные опорные точки проверены отдельно от впечатления по картинке.
- [ ] Оси подписаны понятными единицами: коды АЦП и время с явным статусом номинальной/расчётной шкалы. Для непроверенной амплитуды не появляются вольты на произвольном входе или кВ на свече.
- [ ] При нулевом начале время точки `i` равно `i/Fs`; при привязке к запуску — `(i-trigger_index)/Fs`. Для 2048 точек и 50 kS/s расстояние между первой и последней точками — 40,94 мс. Оно не путается с длительностью 2048 периодов 40,96 мс.
- [ ] Если индекс запуска отсутствует, маркер реального события не выдумывается. Крайние коды и имеющиеся флаги качества видны текстом/обозначением; их наличие не объявляется доказанным аналоговым ограничением или состоянием катушки.
- [ ] Видно, что источник — симулятор; это сохраняется после открытия файла. Демо не записывается в журнал реальных измерений. Подписи и применимые ошибки на русском; простой график не выдаётся за завершённый интерфейс MVP.

Связь: MVP-U01/U04/U07/U09, FR-01/06, PERF-06, data-plan «Шкалы».

### H07. Доказательства можно повторить независимо

- [ ] Автор предъявляет точные base/head SHA, область diff, список команд с результатами, созданный пример записи и описание метаданных, снимок графика и список непроведённых проверок.
- [ ] Тесты сравнивают результат с требованиями и независимо заданными ожиданиями. Один round-trip собственных encode/decode не является единственным доказательством правильных единиц, диапазона, порядка байтов и метаданных.
- [ ] Критик повторяет доступные проверки точного SHA и отличает собственные наблюдения от представленных автором результатов. Снимок без воспроизводимого сценария и тест без фактического лога не превращаются в подтверждённый запуск.

Связь: DOC-01/02, quality-gate C3/C5.

## 3. Отдельные обязательства, не закрываемые HOST-001

Эти пункты не исключаются из MVP. Они заранее отделены от первой ограниченной задачи и должны остаться в очереди с владельцем и зависимостью.

1. **Общий wire-контракт:** владелец A, согласование с B и два независимых PASS. Нужны версии/capabilities, фактически принятые настройки, framing, порядок байтов, пределы, идентификаторы подключения/окна, состояния, ошибки, целостность и общие контрольные векторы. После этого отдельно проверяются фрагментация/склейка потока, неизвестная версия, повреждение/повтор/обрыв, тайм-аут, отключение/повторное подключение и недопущение старого окна как нового. Внутренний эмулятор HOST-001 не закрывает MVP-01 целиком.
2. **Остальные функции приложения:** Auto/Normal/Single, действительный Run/Stop, параметры/предыстория, полный zoom/pan/reset, два курсора, CSV/PNG, полный тёмный интерфейс и офлайн-справка. Если часть реализована в HOST-001 и заявлена как работающая, она также проверяется; необъявленная будущая функция не появляется как обязательный барьер задним числом.
3. **Windows 10:** выбор стека с первичными основаниями поддержки, архитектура ноутбука, воспроизводимый пакет, запуск на чистой заявленной Windows 10 без среды разработки, открытие записи и корректное закрытие. Linux/macOS, headless или offscreen-проверка не являются этой проверкой. Если сама карточка HOST-001 обещает работающий Windows-пакет, Windows-доказательство становится обязательным для неё, а не переносится после неудачи.
4. **Native USB и аппаратура:** реальный MCU, LV-001 с 20 окнами, фактические шкалы/запуск/предыстория, восстановление связи, аналоговый тракт и стенд. Генерируемые 20 окон не являются измеренными 20 окнами. Проверки V-01–V-05 не закрываются симуляцией.
5. **Уровни MVP:** `software-ready`, `low-voltage-verified` и `ignition-verified` требуют соответствующего комплекта и обоих критиков. Даже PASS HOST-001 с 10/10 не присваивает ни один из этих уровней.

## 4. Применение неизменной рубрики

Все пять критериев и их веса сохраняются из quality-gate v1.0:

- C1, 30%: точность массива/метаданных/шкал, сквозной путь и честные границы результата (H01–H04, H06).
- C2, 20%: валидация, ограниченные ресурсы, безопасное сохранение и восстановление после ошибок (H02, H04–H05).
- C3, 25%: независимые ожидания, отрицательные сценарии, фактический запуск и воспроизводимые доказательства (H01–H07).
- C4, 15%: ясные границы источника/модели/файла/графика, понятные ошибки и ограниченный объём; отсутствие лишней сложности (H03, H05–H06).
- C5, 10%: чистый запуск, версии, описание формата и точная привязка отчёта к артефактам (H01, H03, H07).

Итог: `0.30*C1 + 0.20*C2 + 0.25*C3 + 0.15*C4 + 0.10*C5`. Порог — 9,5 до округления; он не подгоняется под результат. Для каждого балла нужны конкретные основания.

PASS возможен только при выполнении применимых критериев HOST-001, наличии обязательных свидетельств и отсутствии P0/P1. При отсутствии обязательного свидетельства: `BLOCKED_EVIDENCE`, `score: null`; при одновременных дефектах они также перечисляются. При доказанном результате с дефектами/баллом ниже порога: `REWORK`. Новый SHA требует актуального заключения и повторения затронутых проверок.

На момент создания checklist реализация не предъявлена, оценки C1–C5 и вердикт не выдавались. Следующий вход для Critic-B — карточка ограниченной задачи и точный commit с полным пакетом доказательств H07.
