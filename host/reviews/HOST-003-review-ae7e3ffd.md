## Замечания

### PNG-01, P2 — допустимый длинный флаг качества обрезается по правому краю

Место: `host/motortester/gui.py`, `png_image`, расчёт `QFontMetrics.boundingRect`/`drawText` с `TextWordWrap`.

Воспроизведение: минимальное окно 1000×710, обычный scale=1, загрузить корректный Capture с `quality_flags=("flag0_" + "Ж"*56,)` или 16 такими флагами. Длина строки 62 символа разрешена моделью. Экспортировать PNG. Слово не содержит пробелов; WordWrap не разбивает его. В независимом изображении шириной 642 px текст имеет только 610 px полезной ширины, и окончание флага выходит за правую границу. Снимок с 16 флагами осмотрен лично; окончания и разделители скрыты.

Последствие: иллюстрация молча теряет часть предупреждения, хотя raw-файл и Capture не меняются. Обычные короткие предупреждения и прочие подписи показаны правильно.

Исправление: измерять и рисовать длинные непрерывные фрагменты с согласованным принудительным переносом либо иным явным способом сохранения полного читаемого предупреждения; добавить regression для максимально допустимых непрерывных Unicode-строк и визуально повторить экспорт. Простое увеличение числа тестов без проверки доступной ширины не закрывает дефект.

### PNG-02, P2 — описание формата отрицает уже добавленный PNG-экспорт

Место: `host/docs/format-v1.md`, раздел «CSV и иллюстрации», фраза «Экспорт PNG полного MVP пока не реализован».

README и help уже описывают работающую PNG-кнопку, но связанное основное описание формата оставлено в прежнем состоянии. Уточнить его: PNG — иллюстрация текущего viewport, численные данные сохраняются в MTCAP. Это непосредственно затронутая документация, не просьба переписывать весь документ или расширять MVP.

## Выполнено лично

Среда: Linux x86_64, CPython 3.12.14, закреплённые зависимости HOST-001; GUI — настоящее Qt/offscreen.

1. Полный suite из чистого снимка: **83 теста, 11,680 с, OK**. Включает 77 исходных и 6 новых feature-сценариев.
2. Отдельный feature suite при `QT_SCALE_FACTOR=2`: **6 тестов, 9,389 с, OK**. Это Linux high-DPI simulation, не Windows DPI-приёмка.
3. Независимая PNG-отрисовка и просмотр: текущий zoom −2…5 мс, курсоры, синтетическое происхождение, nominal/unverified scales, исходное число точек и напоминание `.mtcap` видны. PNG успешно декодируется Qt.
4. Побайтовый `encode(Capture)` до/после, identity объекта, `current_path` и `viewRange` не меняются.
5. Независимый экспорт длинных допустимых quality flags дал PNG-01. Обычная иллюстрация — 642×351 px, с длинными флагами — 642×623 px.
6. Независимо проверены недопустимые размеры 0×0, 4097×1 и превышение общего 16-миллионного лимита через 4096×4096: контролируемый `CaptureError`, Capture сохранён.
7. В полном suite проверены no-capture, no-clobber/явная замена, сбой атомарной публикации, отмена, неподходящее расширение, отсутствующая папка, Unicode и повторные экспорты; underlying atomic writer уже независимо проверен HOST-001.
8. Прочитаны четыре изменённых файла и связанное описание MTCAP. Истинный PNG не назван численной записью или аппаратной осциллограммой.
