Нулевой write сохраняет билет/sequence; первый положительный write выделяет sequence один раз; частичный кадр дописывается; 999 ms после последнего байта ещё допустимы, 1000 ms дают recovery; до последнего байта нет выдуманного write-stall timeout.
2. **Все 256 сочетаний 64 capability masks × 4 edge masks**. Согласованные возможности, включая неподдерживаемый/пустой путь, принимаются как CAPS; недоступный Normal/analog CONFIG отклоняется без изменения снимка.
3. **Все 256 message types в четырёх состояниях**, отдельно current/foreign nonce: неверное известное направление требует recovery; остальной чужой трафик не изменяет даже часы; текущие некорректные payload/type/request дают ограниченное recovery без необработанных исключений.
4. Stop за ещё не отправленными/частичными CAPS/CONFIG, CONFIG ERROR → STOP_ACK, ARM ERROR после прежнего успешного поколения → STOP ERROR. Stop не обгоняет кадр и не объявляет прежнее поколение остановленным после отказа нового ARM.
5. Неверные API-вызовы на уже наступившем дедлайне не меняют состояние и не подменяют timeout: следующий корректный tick выдаёт recovery.
6. DATA на границах 1/250 отсчётов, offset конца окна, коды 0/4095/4096; запрет любого второго terminal и последующих BEGIN/DATA того же удерживаемого окна.
7. **100 последовательных ARM → ранний ABORT → STOP_ACK**: window_id возрастает сквозь поколения, остаётся одна terminal-запись, старое поколение отвергается. Это синтетические отмены, не 100 измерений.
8. Резервирование последнего TX/request ID с обычной командой до первого байта, после частичного и полного write; UINT32_MAX не выдаётся, gaps/wrap не создаются.
9. END без массива остаётся только END_ADMITTED; downstream fault после него требует сохранения фрагментов/reset. Новый nonce очищает прежний terminal/config/window.

## Проверенные инварианты и границы вывода

- HELLO_ACK требует matching nonce/sequence/request и точных limits/version; CAPS проверяет весь фиксированный профиль, маски и предысторию. CONFIG_ACK требует следующий config_id и точное эхо, ERROR сохраняет принятую настройку.
- Один обычный запрос и Stop имеют отдельные command deadlines. Exact-last replay не повторяет событие; конфликт/gap/stale/MAX-ID, чужой ответ и ответ на неотправленную команду fail closed. Последний допустимый RX распознаётся как точный повтор.
- Stop рядом с ARM сохраняет порядок, использует request_id ARM как generation и подавляет событие ARMED до Stop barrier. STOP_ACK снимает барьер сразу; запоздавший STATUS(STOPPED) не отменяет pending rearm. STOP ERROR немедленно восстанавливает сеанс, автоматической повторной команды нет.
- Ранний ABORT — один факт отмены с generation/window/reason. BEGIN и samples не выдумываются. END/ABORT сохраняют window barrier до STOP_ACK; данные остановленного поколения не допускаются.
- **WINDOW_END_ADMITTED не является независимо проверенным полным измерением.** Контроллер не устанавливает полноту массива, порядок/перекрытие DATA и samples CRC; это обязанность отдельного сборщика. Проверка без полного DATA намеренно подтверждает только этот предел ответственности.
- **3000 ms без прогресса samples принадлежит WindowReceiver**, а не второму таймеру в контроллере. Normal waiting само по себе не timeout. Здесь лично проверен downstream-fault hook, интеграция с WindowReceiver не заявляется.
- Политика зависшей записи принадлежит внешнему транспорту. Pure controller может ждать partial/zero write без ограничения; неизвестный исход write немедленно требует recovery. Фактическое закрытие/открытие транспорта, сохранение фрагментов и генерация случайного свежего nonce выполняются внешним владельцем.
- Хранение структурно ограничено слотами: два запроса, один ticket, последний RX, одна terminal-запись, фиксированные immutable значения. Представленные bounded stress/tracemalloc лично повторены. Это не измерение абсолютной RAM/latency или ресурсов STM32.
