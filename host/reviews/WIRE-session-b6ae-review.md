## Приоритетные действия

### W-02, P1, не закрыто: Auto + реальный внешний фронт

`protocol/wire-v0.1.md:106,117,141`. Полное декартово произведение capabilities
допускает Auto с внешним source. Для реального принятого внешнего фронта строка
141 требует `external_edge_id` равным счётчику, но в той же строке «analog/Auto
имеют0». Auto — режим, а `auto_timeout` — причина окна; они не эквивалентны.

Пример: mode=Auto, source=external, принятый фронт №17 до тайм-аута.
`trigger_kind=external` и id=17 либо id=0 всё ещё следуют из разных фраз.
Указать id по **trigger_kind**: external — обнаруженный счётчик, analog и
самостоятельный auto_timeout — 0. Добавить два положительных вектора и
отрицательное несогласованное сочетание. До уточнения host не должен молча
выбирать один смысл и объявлять совместимость.

### E-01, обязательное свидетельство: TX/Stop только описаны

`docs/session-guard.md` прямо отделяет эти правила от mt_session и требует
отдельные исполняемые сценарии. RX guard не отправляет ни одного байта,
не знает об END/ABORT, USB FIFO, capture или ожидаемом STOP. Его успешный прогон
не подтверждает новые общие TX-правила.

Для следующего ограниченного доказательства нужен synthetic/mock transport
(не обязательна плата) с проверками:

- запись приняла 0 байт: отмена END сохраняет следующий sequence для ABORT;
- запись приняла хотя бы 1 байт: END завершается, ABORT того же окна отсутствует;
- начатые BEGIN/DATA завершаются до terminal/ACK, последовательность без gaps;
- Stop без окна/после terminal и повторный Stop не создают фантомный/второй ABORT;
- необходимый queued/started ABORT не теряется; ранний ABORT до BEGIN не создаёт измерение;
- ответ прежнему запросу предшествует STOP_ACK; ACK освобождает барьер по последнему принятому байту даже при queued STATUS;
- STOP ERROR завершает ожидание с отказом и переводит host в fresh HELLO, без ARM/STOP старого сеанса.

Общие payload-векторы, сквозные сценарии и 20 wire-окон из строки 150 также
остаются открытыми на уровне принятия **всего** контракта. 20 внутренних
HOST-001 окон не заменяют 20 проводных окон.

### D-01, P2: описание текущего состояния устарело

`protocol/wire-v0.1.md:7,41,150` всё ещё утверждает, что codec/stream не
компилировались, команды/управление сеансом отсутствуют и «этот PR» содержит
только byte codec/один вектор. На данном head уже есть parser и RX guard,
документы/логи native-сборок. Сохранить границы отсутствующего dispatcher/USB,
но пометить старые фразы историческими либо заменить ссылкой на актуальный
статус. Это не основание объявлять весь протокол реализованным.

## Что действительно исправлено и пригодно для B

- **W-01 закрыто на уровне текста**: sequence предварителен при сериализации,
  атомарно выделяется при первом положительном принятии байтов. Нулевая запись
  номер не расходует; неизвестный результат требует восстановления.
- Названы только объявленные device types 129..135, 144..147, 255;
  136..143 остаются неизвестными, а не неправильным направлением.
- RX sequence непрерывен с 2, request строго растёт с допустимыми gaps.
  UINT32_MAX запрещён; MAX−1 можно принять и распознать точный повтор.
- Только один дополнительный ожидаемый STOP; ERROR на STOP не означает Stop
  success, закрывает ожидание и требует немедленного восстановления.
- ABORT связан с реально выделенным нетерминальным окном; нет фиктивного id0
  и второго terminal outcome. Ранний ABORT до BEGIN разрешён как событие.
- Барьер Stop заканчивается последним принятым байтом ACK, не последующим STATUS.

Указанный в разделе порядка приоритет direction→HELLO→session соблюдён кодом.
Поэтому device-type с чужим nonce тоже вызывает RECOVERY; это отдельно покрыто
проверкой и не объявлено новым code bug. Общую фразу «неверный session
отбрасывается» следует читать после предшествующего direction gate.
