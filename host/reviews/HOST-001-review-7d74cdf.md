## Собранный список замечаний

### H-01, P2: загрузчик принимает запрещённую кодировку метаданных

Место: `host/motortester/recording.py:62–63`; требование UTF-8 в `host/docs/format-v1.md`, H03/H04 checklist.

`json.loads` получает bytes и автоматически распознаёт UTF-16/UTF-32. В контрольном `.mtcap` можно перекодировать только JSON, обновить его длину M и SHA-256; загрузчик принимает оба файла. Это воспроизведено для UTF-16 (1310 байт) и UTF-32 (2564 байта), коды остаются `(0, 1, 256, 4095)`.

Последствие: поддерживаемый формат шире документированного, и такой файл будет отвергнут независимым строго UTF-8-читающим инструментом. Потери данных, исполнения кода или выхода за лимиты в данном воспроизведении нет. Тем не менее обязательная валидация объявленного формата неполна.

Ожидаемое исправление: явно проверять UTF-8 до разбора JSON, сохранять понятный `CaptureError`; добавить отрицательные проверки UTF-16/UTF-32 с корректно пересчитанным контейнером/хешем. Не расширять молча спецификацию v1 ради уже принятого неправильного входа.

Минимальное воспроизведение из `host/`:

```python
from pathlib import Path
import hashlib, struct
from motortester.recording import decode

b = Path("evidence/control-synthetic.mtcap").read_bytes()
magic, m, n = struct.unpack_from("<8sII", b)
text = b[16:16+m].decode("utf-8")
samples = b[16+m:-32]
for encoding in ("utf-16", "utf-32"):
    metadata = text.encode(encoding)
    body = struct.pack("<8sII", magic, len(metadata), n) + metadata + samples
    print(encoding, decode(body + hashlib.sha256(body).digest()).samples)
```

Фактический результат обоих вызовов на проверенном SHA: успешный decode. Ожидаемый результат после исправления: контролируемый отказ.

### H-02, P2: собственное подтверждение замены файла не полностью русифицировано

Место: `host/motortester/gui.py`, `_choose_save_path`, вызов `QMessageBox.question`; MVP-U01, H05/H06 и C4.

Сценарий: создать демо, выбрать существующий файл для сохранения. Открыто настоящее окно подтверждения Qt в проверенной среде. Вопрос русский, кнопки имеют текст `Yes` и `No` (`&Yes`/`&No` в свойствах), а не «Да»/«Нет». Без установленного переводчика Qt это зависит от окружения. Кнопка отказа выбрана по умолчанию; отказ сохранил исходный файл, разрушительного поведения нет.

Ожидаемое исправление: обеспечить русские подписи именно в собственном подтверждении приложения независимо от языка ОС, либо документированно загрузить соответствующий Qt-перевод и включить его в комплект. Проверить настоящее окно и отказ/согласие, а не только mock возвращаемого ответа. Системные native-диалоги Windows и локализация их ОС отдельно проверяются на Windows; данный дефект воспроизведён в собственном QMessageBox прототипа.

### Статические проверки и внешние основания

Прочитаны модель/файл/эмулятор/SVG/GUI/CLI, тесты, описание формата, справка, Windows build/spec/lock/license-checklist. Код разделяет источник, неизменяемую модель, файл и отображение; внутреннее событие не объявляется wire. Размер чтения ограничен до JSON; хеш проверяется до модели; записывается временный файл с безопасной публикацией; ошибки сохраняют предыдущую запись и понятное состояние интерфейса.

Проверены заявленные внешние основания кандидата: [официальная таблица Qt 6.12](https://doc.qt.io/qt-6/supported-platforms.html) действительно перечисляет Windows 10 1809+ x64 и ограничение следующего обновления; [релиз CPython 3.13.16](https://www.python.org/downloads/release/python-31316/) содержит Windows x64 installer; [PySide6-Essentials 6.12.0](https://pypi.org/project/PySide6-Essentials/6.12.0/) и [PyInstaller 6.22.3](https://pypi.org/project/pyinstaller/6.22.3/) доступны. Это подтверждает обоснование pins/кандидата, не запуск готового Windows-пакета. Проверка лицензий явно оставлена открытой; юридическое одобрение не выдаётся.
