# Объединённый кандидат Windows-приложения

12.10.2026. Локальная композиция для повторной независимой проверки. Не релиз, не `software-ready`, не разрешение на физическое подключение и не перенос оценок отдельных компонентов.

## Основа и владение

Единственный родитель этого продолжения: main `4dc8389ed2cb9bfbc89504f81d253972dd003d6b`, проверенный 12.10.2026 в 05:29 UTC. Все 76 файлов вне `host/` взяты из этого main без изменения: навигация, исходный аналоговый пакет и отдельно поставленные исторические native-host/ADC component reproducer. Их включение не означает приёмку последней runtime/ADC политики. Firmware, hardware, общий protocol и CI принадлежат Dot A; слияние этой ветки не выполнялось. Прежняя локальная композиция `6a3bfef0a5e74e5370c912c0fc45f8cebba2ddd8` с родителем `e75e8c78e7042c63dd4c4e152cc4b7b40db7045b` и её независимые свидетельства сохранены.

Исходный замороженный host-кандидат `16c40a8434c33b4e02bb71bf21294d58a90c5a18` имел единственного родителя `da85d0aed68828214057797a5bd78f7b9f49ed35`. Здесь сохранены точные байты всех его 213 остальных host-файлов: код, тесты, зависимости и прежние материалы не изменены. Единственное изменение host — это уточнение происхождения в `host/docs/mvp-union.md`; предыдущий кандидат и его свидетельства сохраняются отдельно.

Ранее выполненные Linux/синтетические проверки относятся к неизменившимся исходникам, но не заменяют независимую проверку нового полного дерева, родителя и сохранности main тем же Critic-B. Публикация и повторное скачивание 14 закреплённых Windows wheels разрешены пользователем 12.10.2026; автор сообщает успешное скачивание без установки, но независимая проверка нового resolver evidence ещё выполняется. Привязка этого кандидата к опубликованному SHA, применимые Windows-проверки и совместная приёмка протокола остаются открытыми. Новая композиция не получает автоматически прежний вердикт и не объявляется `software-ready`.

Сначала берётся host-дерево GUI `25db86d83e878dd6e9ffbdd287c2c0ab23a97d43`, затем исходные дельты Stop, раннего RELEASE и упаковки из [точного манифеста](union-source-manifest.json). Только `device_emulator.py` пересекается у Stop и последующего RELEASE; применяется именно конечная версия `f733ab0fad14a443402a26f437a399fe69499ef1a68a8fa793a64d8d630daef5`. GUI/worker/runtime из этой композиции не переписываются компонентными дельтами.

README объединения описывает новую функциональность и сохраняет сведения о PNG, файлах, Windows и ограничениях main. Отдельный меньший кандидат согласования README `788863041a3c60a0a97af5fea258e3f0894198eb` сохранён; он не выдаётся за эту более широкую интеграцию.

## Что соединено

- Проверяемые COBS/CRC байты, handshake/CAPS, CONFIG/ARM/Stop и владение оконным буфером.
- Транспорт указанного COM-порта без автоматического поиска/переподключения; отдельно синтетический байтовый эмулятор.
- Аналоговые Auto/Normal/Single, выбор фронта/уровня, профиль LV-001, предыстория 0.
- Один Qt worker с ограниченными очередями; полное окно удерживается до точного потребительского ACK.
- График, курсоры, MTCAP, повторное открытие, CSV/PNG, офлайн-справка.
- Windows-рецепт с pyserial, проверкой импорта без открытия портов и материалами лицензирования.

## История выявленных отказов

Предыдущая интеграция `3712d418d0b0c9fda796c92293a09b9c941d5f83` прошла один normal-прогон, но затем дала Qt/GC-зависимые зависание и segmentation fault. Независимый пробник обнаружил преждевременное завершение: в 84 из 100 callback `finished` native thread ещё не прошёл `wait(0)`. Версия GUI `22eab1…` исправляет границу завершения неблокирующим ожиданием native join; отрицательные журналы сохранены. Отдельные успешные повторы не стирают эту историю.

При первом запуске тестов этой композиции не был добавлен путь уже проверенного pyserial: один тест завершился ModuleNotFoundError. Повтор использует существующие официальные байты wheel с SHA-256 `c4451db6ba391ca6ca299fb3ec7bae67a5c55dde170964c7a14ceefec02f2cf0`; все 28 serial-файлов отдельно сверены. Это историческое повторное использование установленных байтов, а не выполненная в том прогоне проверка Windows resolver; последующее разрешённое скачивание и его независимая проверка учитываются отдельно.

Ещё два отказа найдены независимым стресс-тестом объединения `a25285…`: Старт мог быть отклонён во время обычного idle-чтения COM, а ACK неполного окна терялся при одновременном отключении. GUI-продолжение `25db86…` отделяет выполнение управляющей команды от фонового чтения, сохраняет один ограниченный запрос и повторяет передачу уже удерживаемых неполных данных только после снятия барьера. Автоматического запуска/переподключения это не добавляет. Оба прежних отрицательных воспроизведения сохраняются; исправленная версия проверяется заново.

## Условия приёмки

Полный набор должен пройти normal и `python -O` на неизменных исходниках. Независимая матрица режимов повторяется на новом эмуляторе, включая 120 сохранённых/прочитанных окон и прежнюю runtime-ошибку как отрицательный контроль. GUI/жизненный цикл повторно проверяются отдельным критиком на этом объединении. Исходники/дерево/родитель и журналы должны быть привязаны к опубликованному SHA.

Общая совместимость требует отдельных заключений Critic-A и Critic-B по конкретным версиям. Кандидат не получает статус принятого до выполнения применимых условий и порога ≥9.5. Прежняя отмена проверки разрешений и её журналы сохранены; повторное скачивание 14 Windows wheels теперь разрешено, но закрытие обязательного resolver gate требует отдельного независимого заключения по свежим байтам и metadata. Реальная Windows-сборка, проверка Windows 10, USB платы, низковольтные измерения и безопасность аппаратуры остаются открыты.
