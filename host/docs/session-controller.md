# HOST-006: ограниченный контроллер управляющего сеанса

Статус: **DRAFT, общий контракт не принят, приёмка модуля не присвоена**.
Задача [HOST-006 #24](https://github.com/font-weight/stm32_motortester/issues/24).
База приложения: `c89c12df984390b34785eba81665abd6418658e2`.

## Источник и границы

Только `motortester/session.py` явно использует экспериментальный общий PR14
на **`b6ae8025baf1a47e8173997029d2d8b858ada74c`**:
[wire v0.1](https://github.com/font-weight/stm32_motortester/blob/b6ae8025baf1a47e8173997029d2d8b858ada74c/protocol/wire-v0.1.md),
[правила сеанса](https://github.com/font-weight/stm32_motortester/blob/b6ae8025baf1a47e8173997029d2d8b858ada74c/docs/session-guard.md).
Источники `wire.py` и прежних модулей этим не меняются; их прежнее описание
остаётся в [wire-adapter.md](wire-adapter.md). Принимается совместимость
заголовка и кодирования кадров для этой синтетической проверки, а не общий
протокол проекта. Позднейший `c54bd955aaf3cb863ef3df043ea237ea62e74ad4` уточняет
external ID; эта поправка не меняет данный путь Normal + analog и не подменяет
закреплённый источник модуля.

Контроллер реализует HELLO → GET_CAPS → CONFIG → ARM → STOP и запрос
восстановления. Поддерживаемая настройка: профиль 1, **Normal, аналоговый
источник**, объявленные устройством фронт и предыстория. CAPS разбирается
полностью: остальные известные возможности видны, но запуск Auto, Single,
внешнего источника и непрерывный RELEASE-цикл здесь не реализованы.
Согласованные маски без поддерживаемого пути, в том числе нулевые маски,
не объявляются повреждением протокола: `configure` возвращает `UNSUPPORTED`.

Модуль не открывает USB/COM, не закрывает порт, не собирает массив отсчётов,
не пишет файлы, не создаёт поток, GUI или автоматические повторные команды.
Это проверка программы на синтетике; Windows 10, плата, native USB, физическое
время, низковольтный опыт и зажигание не проверены. До независимого Critic-B
на точную версию результат остаётся черновиком; общий контракт требует
собственного совместного ревью. Это не `software-ready` MVP.

## Небольшой API

Импорт: `from motortester.session import SessionController, Config, FaultCode`.
Один владелец вызывает методы последовательно, без конкурентных вызовов.

- `start(nonce, now_ms)` — начальный запуск либо запуск после RECOVERY.
  Свежий ненулевой nonce передаёт вызывающая сторона. Реальный транспорт
  обязан генерировать случайный uint64 при каждой попытке; контроллер
  отклоняет только непосредственное повторение, не хранит историю nonce.
  После RECOVERY этот вызов означает, что внешний владелец уже выполнил
  сброс/переоткрытие транспорта и очистку старых очередей/декодера. Во время
  активного сеанса `start` запрещён, в том числе при частично записанном кадре.
- `configure(Config(...), now_ms)` — настроить после валидных HELLO_ACK/CAPS,
  в READY без обычного запроса, Stop или удерживаемого окна.
- `arm(now_ms)` — ARM с последним принятым config_id, при тех же барьерах.
- `stop(now_ms)` — один дополнительный STOP после HELLO_ACK. Допустим рядом
  с незавершённым GET_CAPS/CONFIG/ARM; второй STOP до ответа запрещён.
- `prepare_tx() -> TxTicket | None` — один неизменяемый билет передачи.
  Повторный вызов возвращает тот же объект, пока нет положительного прогресса.
- `written(ticket, accepted_count, now_ms)` — сообщить достоверное число
  принятых байтов из `ticket.encoded[ticket.offset:]`. Это число добавленных
  байтов, не накопительный итог. После частичного успеха снова вызвать
  `prepare_tx`; прежний билет уже недействителен. При нулевом успехе билет
  сохраняется. Нельзя создавать копию билета: проверяется идентичность
  выданного объекта, а не только равенство его полей.
- `receive(Frame, now_ms)` — принять один кадр после проверки wire codec.
- `tick(now_ms)` — проверить сроки команд; внешний цикл обязан вызывать его
  и при отсутствии входящих кадров.
- `transport_lost(now_ms)` — известный разрыв транспорта.
- `unknown_write(now_ms)` — неизвестно, сколько байтов приняла запись.
- `protocol_fault(FaultCode.VERSION | DECODE | DOWNSTREAM, now_ms)` — внешний
  владелец обнаружил несовместимость версии, ошибку декодирования, требующую
  восстановления, либо ошибку сборки/проверки окна. Аргумент — член enum,
  не произвольная строка; правила выбора ошибки остаются у соответствующего
  слоя. Например, одиночную CRC-ошибку codec можно отбросить, а последующий
  sequence gap уже вызовет восстановление. CRC-valid неподдерживаемую версию
  нельзя скрывать обработкой других кадров той же порции.
- `snapshot() -> Snapshot` — неизменяемый текущий снимок, без журнала.

Методы с `now_ms` возвращают tuple из 0…2 неизменяемых `Event`. Пустой tuple
после `configure`/`arm`/`stop` означает постановку команды, не её исполнение.
Никаких отложенных выходных очередей или callbacks нет. `prepare_tx` только
готовит байты, а `written` только принимает сведения внешнего транспорта.
Контроллер не подтверждает правильность этих сведений аппаратно.

`Config(profile=1, mode=1, source=0, edge=0, level_code=2048,
pretrigger_samples=0, auto_timeout_ms=0)` неизменяем. Конструктор проверяет
точные Python-типы и синтаксические пределы wire, включая связь mode/timeout.
`configure` повторно проверяет объект, объявленные CAPS и ограничение
Normal + analog. Другие корректные wire-режимы отклоняются как неподдержанные.

Все целые аргументы — именно `int`, без `bool` и неявного преобразования.
`now_ms` — монотонное uint64 в миллисекундах. Неверные аргументы, пределы,
состояние, устаревший билет и уменьшение времени дают `SessionError` с
фиксированным русским сообщением и `.code`: `ARGUMENT`, `RANGE`,
`CLOCK_ROLLBACK`, `STATE`, `UNSUPPORTED`, `STALE_TICKET`.
Такие ошибки проверяются до изменения состояния и до обработки тайм-аутов.

## События и состояния

`Phase`: IDLE, HELLO, CAPS, READY, ARMED, RECOVERY. HELLO_ACK автоматически
ставит GET_CAPS. READY означает завершённое согласование возможностей, но
не обязательно наличие принятой конфигурации. ARMED означает принятый ARM;
само ожидание запуска не является окном или измерением.

`EventKind`: HELLO_ACCEPTED, CAPABILITIES, CONFIGURED, ARMED, STOPPED,
COMMAND_ERROR, STATUS, WINDOW_BEGIN, WINDOW_DATA, WINDOW_END_ADMITTED,
WINDOW_ABORT, RECOVERY. События содержат request/generation/window ID,
фиксированный код причины и при необходимости исходный неизменяемый Frame.
Все `Event` и `Snapshot` содержат `source_sha` и
`validation_scope='draft_normal_analog_control'`.

В `Snapshot` доступны: phase, session, следующие TX/RX sequence и request ID,
ID ожидаемого обычного запроса и STOP (0 при отсутствии), принятые Config и
config_id, generation, stop_barrier, window_barrier, последний window_id,
одна запись terminal, capabilities, now_ms и смещение текущего билета.
Флаг Stop появляется при постановке команды и снимается только ответом
или переходом в RECOVERY. STATUS — проверенная телеметрия; он не заменяет
ACK, не вооружает контроллер и не отменяет новый ожидаемый ARM.

CONFIG_ACK должен содержать следующий config_id с 1 и **точное эхо** 16 байт
запрошенного CONFIG. Это явная fail-closed политика ПК: правила округления
или замены принятой настройки в данном wire draft не определены. Нельзя
молча приписывать устройству другую конфигурацию. ERROR CONFIG сохраняет
прежние настройки, config_id и generation. Generation нового ARM должна
равняться request_id команды; config_id в ARM_ACK обязан совпадать.

## Передача, порядок и Stop

HELLO имеет header session=0, sequence=1, request=1. Только matching
HELLO_ACK с session=nonce, sequence=1, request=1 и точными версией/пределами
начинает согласование CAPS. Проверяются весь профиль, тактирование и пределы,
допустимые биты и согласованность масок, а также точный набор предыстории.
Значения профиля — параметры draft, а не измеренная частота устройства.

TX sequence предварителен до **первого положительного** принятия байтов.
Нулевой результат не расходует номер; частичный результат расходует его
один раз. Нельзя начать следующий кадр, пока текущий не закончен. STOP не
удаляет и не обгоняет ранее поставленный CONFIG/ARM. Неопределённый результат
записи немедленно требует восстановления, без повторной выдачи номера.

Порядок RX: проверка аргументов → известное неверное направление → чужой
сеанс → тайм-аут → точный последний повтор → тип/sequence/request → payload
и состояние. Чужой сеанс не меняет даже часы контроллера; внешний `tick`
нужен независимо от старого трафика. Известная команда ПК, пришедшая с
устройства, требует восстановления даже со старым nonce. Неподдерживаемый
тип текущего сеанса, конфликт повтора, gap, старый порядок или чужой ответ
также вызывают RECOVERY. Точный непосредственно предыдущий Frame игнорируется;
история всех кадров не хранится.

Новые sequence/request/config/window ID не используют UINT32_MAX и не
оборачиваются. Последний разрешённый RX UINT32_MAX−1 ещё распознаётся как
точный повтор. Перед выдачей следующего недопустимого номера требуется новый
сеанс. Для данной области без RELEASE новое наблюдаемое окно должно иметь
следующий ID с 1; ранний ABORT учитывает это выделение. STATUS не создаёт BEGIN
и не расходует window_id повторно.

При Stop рядом с ожидаемым ARM используется request_id того ARM. Более
ранний ARM_ACK разбирается, но при поднятом барьере **не порождает событие
ARMED** и не разрешает новый пуск. Более ранний ответ обязателен до STOP_ACK.
Если ARM отвергнут, ERROR STOP завершает ожидание немедленно и требует
RECOVERY; остановка прежнего поколения не выдумывается.

STOP_ACK проверяет generation, last_window_id, status/reserved и отсутствие
незавершённого уже начатого окна. Он снимает барьеры без ожидания последующего
STATUS(STOPPED); новый ARM разрешён сразу. Запоздавший STATUS не отменяет
этот ARM. Повторный STOP — новый запрос, не повтор старых байтов.
Контроллер никогда не придумывает ABORT, если окна не было. После STOP_ACK
новые BEGIN/DATA/END/ABORT остановленного поколения отвергаются.

## Окна: только допуск событий, не готовое измерение

BEGIN проверяет связь с принятым CONFIG и параметры Normal + analog. Известный
quality bit2 сохраняется и на аналоговом пути: draft не требует, чтобы этот
бит встречался исключительно при внешнем запуске. Auto-timeout bit0 для этого
пути и зарезервированные биты отвергаются. DATA проверяется на длину, границы
и коды АЦП 0…4095; содержимое передаётся дальше без накопления массива.

Ранний ABORT допустим до BEGIN: фиксируются положительные generation/window
ID и reason; не создаются поддельный BEGIN, нулевой массив или успешное окно.
END допускается лишь для начатого окна с совпавшими ID/размером. Одна запись
`TerminalWindow` хранит тип terminal, ID, reason либо samples_crc32.
Точный последний повтор не создаёт второго события; новый sequence для
второго terminal того же окна отвергается. После END/ABORT барьер окна
сохраняется до STOP_ACK. Непрерывное продолжение через RELEASE отсутствует.

**WINDOW_END_ADMITTED не означает успешное измерение.** Даже BEGIN → END без
единого DATA может быть допущен этим управляющим слоем; нижележащий сборщик
обязан отвергнуть такое окно. Перед публикацией измерения отдельный владелец
сборки проверяет отсутствие пропусков/конфликтов, полный массив и CRC всех
исходных отсчётов. Он же обрабатывает повтор DATA с новым sequence.
Интеграция этого владельца в данной задаче не выполнена.

## Время и восстановление

Обычный запрос и дополнительный STOP имеют независимые сроки: 1000 ms с
**последнего принятого байта** соответствующего кадра. При elapsed ≥ 1000
наступает RECOVERY, в том числе если ACK пришёл точно на границе. Сравнение
использует разность uint64-меток без сложения дедлайна и переполнения.
Автоматических повторов ARM/CONFIG/STOP нет.

Normal/Single ожидание запуска само по себе не является тайм-аутом передачи.
Single здесь пока не запускается. Контроллер не пытается вычислять реальный
прогресс массива из количества DATA-кадров: точный повтор блока с новым
sequence не должен продлевать жизнь повреждённого окна. Проверка 3000 ms
без прогресса передачи из wire принадлежит отдельному сборщику окна;
при её отказе внешний владелец вызывает `protocol_fault(DOWNSTREAM, now_ms)`.

Wire не определяет срок зависшей **записи ПК**. До полного `written` нет
таймера ответа, а до первого принятого байта нет выделенного sequence.
Внешний транспорт обязан иметь свою политику зависшей записи и вызывать
`transport_lost` либо `unknown_write` с достоверной причиной. Без неё этот
чистый контроллер не обещает завершение I/O и может ждать запись бесконечно.

RECOVERY выдаёт один ограниченный запрос внешнему владельцу:
`preserve_fragments=True`, `reset_transport=True`. Ожидаемые запросы и билет
сразу удаляются; повторный вызов в RECOVERY не создаёт повторного действия.
Прежние проверенные настройки/terminal остаются в снимке для диагностики,
но использование в новом сеансе запрещено. Владелец сохраняет проверенные
фрагменты как неполные, сбрасывает транспорт/очереди/decoder и вызывает
`start` со свежим nonce. Контроллер сам этих внешних действий не выполняет.

## Ограниченность и проверки

Хранятся ровно два возможных запроса (обычный + STOP), один сериализованный
кадр, один последний RX Frame, одна запись terminal и фиксированное число
скалярных/неизменяемых объектов. Кодирование не превышает предел wire
544 байта. Один Event может ссылаться на Frame до 512 байт payload; один вызов
возвращает максимум два события. История, очередь окон и массив 2048 отсчётов
не создаются. Объекты Python имеют свои служебные накладные расходы;
это не оценка RAM микроконтроллера.

Из корня репозитория:

```sh
cd host
python -m unittest discover -s tests -p 'test_session*.py' -v
python -O -m unittest discover -s tests -p 'test_session*.py' -v
python -m unittest discover -s tests -p 'test_wire*.py' -v
```

Авторские сценарии — `tests/test_session.py`. Независимые транскрипты и
фиксированные wire-векторы — `tests/test_session_conformance.py` и
`tests/fixtures/session/`. Отдельные граничные тесты выставляют приватные
счётчики рядом с UINT32_MAX, чтобы не выполнять миллиарды команд; это
тестовая подготовка, не публичная возможность API. Проверки под `python -O`
не зависят от выполнения Python `assert`. Число тестов не заменяет независимое
ревью точной опубликованной версии и не подтверждает совместимость прибора.
