## Перенос длинных подписей после Windows run11 — 12.10.2026

[Windows run11](https://github.com/font-weight/stm32_motortester/actions/runs/38240077834)
проверил 25 целевых GUI-тестов PR132, source
`3bc7a251cd36714b1fec350c99e0e5b43ffc4950`, дерево
`d80d0d730a193480004382857375f5a0f6c65515`: сохранены 17 отказов горизонтальной
прокрутки. Диагностика установила minimum content 460: кнопка подключения
требовала 442 плюс 18 отступов. Флажки требовали 390/377 в Fusion и 391/378
в Windows style; форма — 290. Viewport 386/326 объясняет остаток 74/134.
Это измерения Windows Qt/offscreen, не снимок установленного приложения.
Фактическое семейство шрифта в QFontInfo пустое, pixelSize = −1; причина
разрешения шрифта остаётся неизвестной, конкретный fallback не установлен.

Ограниченное исправление разделяет три длинные подписи на две смысловые
строки обычных QPushButton/QCheckBox. Все слова, включая отсутствие запуска
при подключении и подтверждение физического сброса, сохранены. Размеры
рассчитывает Qt по полному многострочному тексту; шрифт, стиль, минимумы,
обработчики команд и ограничения состояний не изменены.

Регрессия сохраняет прежние условия нулевой горизонтальной прокрутки,
достижимости всех углов и читаемости при 420×360 и 360×300. Дополнительно
проверяются области полного текста кнопок, обе строки флажков мышью, Space,
фокус, доступные имена и отсутствие команд до явного подключения. Отдельная
синтетическая модель с моноширинным шрифтом и межбуквенным интервалом воспроизводит
измеренные 13px на знак и прежние ограничения ширины без подмены size hints.
Каждая прежняя однострочная подпись отдельно снова вызывает переполнение.
Это модель горизонтальных метрик: её высоты и растровое изображение не
объявляются воспроизведением Windows. Новый точный Windows-прогон и проверка
видимого интерфейса остаются обязательными; Linux/offscreen не закрывает их.

## Текущий интерфейс

- `acquisition.py`: один владелец транспорта и runtime в QThread, ограниченный
  обмен командами/результатами, отдельное завершение потока. Диагностика
  восстановления содержит русский смысл и точный имеющийся код reason/fault;
  отказ команды содержит числовой код прибора.
- `gui_acquisition.py`: явная прокручиваемая панель управления. Её скрытие не
  останавливает захват. Подробности CAPS идут после кнопок и статуса; небольшая
  высота окна не делает действия или сведения недоступными.
- Источник берётся из состояния соединения: «Эмулятор · синтетические данные»
  либо «Прибор · выбранный COM-порт». Ещё не отправленный выбор в списке не
  переименовывает уже подключённый источник. Неизвестный источник явно отмечен.
- Только при `connected`, фазе `READY`/`ARMED` и ненулевом объекте capabilities
  показываются принятые в текущем сеансе CAPS. В остальных состояниях, включая
  `HELLO`, `CAPS`, `RECOVERY` и отключение, старая сборка и возможности скрываются,
  даже если runtime сохранил прежний объект CAPS для диагностики.
- Показываются объявленный целочисленный `firmware_build` в десятичном и hex
  виде, `wire 0.1 (draft)`, профиль/окно/предыстория, перечисленные режимы и
  фронты, исходные маски capability/mode/source/edge, таймер и параметры АЦП.
  Числовая сборка не называется SemVer или SHA; серийный номер и SemVer этот
  контракт не передаёт. До CAPS версия прошивки и возможности неизвестны;
  wire 0.1 указан только как ожидаемый формат.
- Это объявленные значения, а не измеренная точность или проверка безопасности.
  Показ дополнительных битов/предыстории не включает новые настройки GUI:
  текущий путь захвата остаётся LV-001/analog/pretrigger0.
- Последняя ошибка не исчезает при обычном обновлении состояния. Новый диагноз
  заменяет предыдущий; принятая явная команда или переход к новому `HELLO`
  очищает прежнюю ошибку. Отклонённая команда оставляет своё объяснение.
  Если один пакет событий содержит отказ команды и затем восстановление,
  сохраняются и числовая причина отказа, и причина восстановления.
  Статус и сведения выводятся как plain text; CAPS можно выделить и скопировать.

### Диагностика несовместимой wire-версии

Runtime теперь сохраняет `PROTOCOL_FAULT / VERSION`, если все диагностические
коды порции декодера — `VERSION`. Это целостный COBS-кадр с проверенными длиной
и CRC, чья wire-версия отличается от поддерживаемой 0.1. Повреждённые кадры,
незавершённые байты и смешанные порции VERSION/CRC не объявляются достоверной
несовместимостью: их диагностические отказы остаются `DECODE`. Порядок проверки
декодера не меняется. Любая ошибка по-прежнему отклоняет всю порцию до допуска
кадров контроллером, включая соседние валидные кадры; автоматического ARM или
переподключения нет. Подробнее — [runtime.md](runtime.md).

Неверная версия в payload `HELLO_ACK` по-прежнему даёт `CAPABILITIES`,
некорректная длина HELLO — `PAYLOAD`. Типизированный `VERSION` теперь проходит
из реальных тестовых байтов через runtime и Qt worker до панели; причина
сохраняется после закрытия программного serial backend. Принятие другой
wire-версии не добавлено; полная приёмка MVP-U02 здесь не заявляется.

## Инварианты

Подключение не запускает ARM. Start выполняет CONFIG, ждёт подтверждения и только затем ARM. Stop отменяет отложенный запуск. Нет автоматических переподключений, повторов неизвестной записи или самозапуска после ошибки.

GUI удерживает точный неизменяемый Capture до подтверждения потребления. Следующее окно заменяет последнее, непрерывного архива нет. Normal/Auto не разрешают файловые операции до Stop; Single возвращает готовность после единственного окна. Неполные фрагменты остаются отдельными, без дополнения нулями и без выдачи за полный график.

Ввод/вывод COM и закрытие выполняются в рабочем потоке. Закрытие приложения ожидает его асинхронного завершения; не используется аварийное terminate потока. Ошибка закрытия требует явного повтора. Закрытие COM не называется физическим сбросом или подтверждённым Stop.

## Воспроизводимые проверки

Из корня с установленными закреплёнными GUI-зависимостями:

```sh
PYTHONPATH=host QT_QPA_PLATFORM=offscreen python -m unittest discover -s host/tests -p 'test_gui*.py'
PYTHONPATH=host QT_QPA_PLATFORM=offscreen python -m unittest discover -s host/tests -p test_acquisition_bridge.py
PYTHONPATH=host python -m unittest discover -s host/tests -p test_runtime_modes_integration.py
```

Повторить с `python -O`, затем полный discover. Запуск вне Windows не является Windows-проверкой. Фактические журналы, точный финальный SHA и независимый вердикт должны сопровождать публикацию; наличие этих команд само по себе не закрывает приёмку.

Тесты новой области разделяют:

- fake GUI snapshots: числовая сборка/маски/тайминги, отсутствие выдуманных
  режимов, честный источник, unknown/stale/recovery/disconnected, plain text,
  сохранение и сброс ошибки, достижимость сведений и кнопок в окне 420×360;
- настоящий Qt bridge с синтетическим byte-peer: принятые CAPS по handshake,
  альтернативные допустимые маски/предыстория, причины PAYLOAD/CAPABILITIES,
  потеря связи, числовой отказ CONFIG, совместное сохранение кода отказа
  GET_CAPS/STOP/RELEASE и `DEVICE_ERROR`, сохранение `VERSION` из целостного
  кадра неподдерживаемой версии через runtime до панели после закрытия backend;
- отдельный worker fixture: форматирование reason/fault `VERSION`; отдельно
  [runtime-проверки](runtime.md#проверки-и-границы) покрывают CRC, смешанные
  порции, фрагментацию, приоритет тайм-аутов и сохранность результатов.

Настоящий Qt bridge в этих тестах не означает настоящий COM/USB: serial backend
подменён локальным byte-peer. Проверяется отсутствие CONFIG/ARM после подключения
или ошибки, открытия serial из режима эмулятора и автоматического восстановления.
