# Проверка данных LV-ADMISSION-1 без аппаратного допуска

Это отдельная программная основа B: `motortester.lv_admission` разбирает
байты индекса и проверяет целостность явно перечисленных файлов.
Она не устанавливает достоверность документов, полномочия подписавшего,
актуальность разрешения или безопасность установки. Реального комплекта
допуска в этой поставке нет; все положительные тесты искусственные.

## Два разных результата API

- `parse_index(raw: bytes) -> ParsedIndex`: чистый разбор неизменяемых байтов.
  Не читает файлов, часы или внешние источники. Проверяет строгую форму,
  ожидаемые значения, порядок временных границ и заявленные размеры.
- `verify_bundle(directory: str | Path) -> InventoryCheck`: читает только
  `admission.json` и указанные в нём уникальные файлы в явно переданном
  абсолютном локальном каталоге. Возвращает результат только после всех
  проверок размера, SHA-256 и наблюдаемой стабильности файлов.

`ParsedIndex.original_bytes` сохраняет исходные байты буквально, включая
разрешённые пробелы и порядок ключей. `sha256` вычислен по этим байтам,
не по повторной сериализации. Результат содержит `ExpectedPlan`,
`ExpectedIdentities`, десять `EvidenceRole`, уникальные `EvidenceFile`
и сумму `unique_bytes`. `InventoryCheck.index` сохраняет тот же индекс,
а `files` перечисляет только полностью проверенную байтовую опись.
Тип результата явно различает разбор и завершённую проверку файлов.

Все эти записи — frozen dataclass со slots; вложенные коллекции — tuple,
значения — строки, целые и bytes. В результате нет изменяемого словаря
вызывающей стороны, открытых файлов, callback, полей `approved`, токена
запуска или доверенного решения. Самостоятельное создание такой Python-записи
тоже не создаёт полномочий. Результат не является бессрочным снимком файлов:
после возврата они могут измениться, поэтому будущий потребитель обязан
отдельно связать точные байты с принятой процедурой применения.

`issued_at` и `valid_until` проверяются только как календарные UTC-строки
и как условие `issued_at < valid_until`. Прошедшие или будущие даты не
становятся текущим разрешением. Текущие часы, срок внешнего решения, отзыв,
однократность и согласие оператора здесь вообще не проверяются.

## Строгость и пределы

- Индекс: 1..16384 исходных байта, UTF-8 без BOM, один JSON-объект.
  Повтор ключа, неизвестный или отсутствующий ключ, массив, `null`, boolean,
  float, NaN/Infinity и неподдерживаемая версия отклоняются. Нет defaults,
  преобразования строк в числа или «совместимого» пропуска полей.
- До общего JSON-декодера лексический проход ограничивает глубину тремя
  объектами, число объектов 14 и число пар 68. Это ровно максимальная
  структура текущего контракта. Числовой токен — не более десяти цифр,
  строковый — не более 1440 символов исходного JSON между кавычками:
  этого хватает для 120 символов, каждый представлен парой UTF-16 escapes.
  Затем проверяются точные длины и типы каждого поля.
- План: LV-001, отдельный прогрев 1, основных попыток 20, profile 1,
  mode 0, source 0, предыстория 0. Edge 0..1, level_code 1..4094,
  auto_timeout_ms 100..60000. Эти числа не измеряют частоту, напряжение
  или усиление.
- Build — uint32; VID 1..65534, PID 0..65535; serial — 1..31 ASCII
  букв/цифр. Source SHA — 40 строчных hex, SHA-256 — 64. Ожидаемые
  экземпляр, ПК и порт остаются утверждениями индекса, не наблюдениями.
- Ровно десять ролей. Каждый файл 1..32 МиБ, сумма уникальных файлов
  не более 64 МиБ. Заявленная сумма проверяется до открытия оснований.
  Размер индекса не входит в эту сумму и отдельно ограничен 16 КиБ.
- Один файл может покрывать несколько ролей только при точном совпадении
  имени, размера и hash. Он читается и учитывается один раз. Разные имена,
  совпадающие без учёта регистра, отклоняются. Разные перечисленные имена
  одного физического файла (hard link) также отклоняются.
- Имена оснований: 1..100 ASCII букв/цифр/`-`/`_`/`.`, первый символ
  буква/цифра, без `..`, конечной точки, путей, ADS, URL и Windows device
  names. `admission.json` в любом регистре не может ссылаться сам на себя.

Дополнительные ограничения этого потребителя объявлены явно:

- Для входного каталога не более 1024 символов и 64 компонентов вместе
  с корнем. При передаче строки нужны канонические разделители без `.`,
  `..`, лишних разделителей и конечных точек/пробелов компонентов.
  `Path` уже мог нормализовать часть записи до передачи; проверки реальных
  предков всё равно выполняются. Произвольные объекты с `__fspath__`
  не вызываются; принимаются обычная строка или конкретный класс Path.
- Все идентификаторы должны быть печатными по `str.isprintable()`, без
  пробельных краёв. Это также исключает управляющие/форматирующие Unicode
  символы и одиночные суррогаты. Bundle ID дополнительно только ASCII.
- Явные лексические заглушки `TBD`, `TODO`, `UNKNOWN`, `PLACEHOLDER`,
  `TEST`, `SYNTHETIC`, `FIXTURE` отклоняются как отдельные последовательности
  ASCII-букв без учёта регистра; например, `TEST-01` и `SYNTHETIC1`.
  Отклоняется и последовательность `NEVER_FLASH`, `NEVER-FLASH`,
  `NEVER FLASH` или `NEVERFLASH`. `motortester`, `latest` и имя
  `flash_readback.txt` не отклоняются по подстроке `test` или `flash`.
  Эта узкая проверка не распознаёт неизвестные заглушки и не доказывает
  реальность текста; содержимое файлов вообще не классифицируется.
- Временные строки используют годы 0001..9999 и обычные секунды 00..59;
  leap second `:60` не поддерживается. Смещения, дроби и сокращённые формы
  времени не принимаются. Это ограничение parser, а не решение о сроке допуска.
- Кроме стандартных зарезервированных имён консервативно запрещены `COM0`
  и `LPT0`. Для проверки уникальности нужны ненулевые file ID от `fstat`;
  файловая система без доступной идентичности получает отказ.

## Чтение и модель файловой системы

Модуль предназначен для стабильных кооперативных локальных файлов.
Он проверяет каждый предок, корень и явные файлы через `lstat`, запрещает
symlink/reparse, специальные файлы, UNC, device-пути и сетевые формы имён.
На Windows read-only запрос типа диска дополнительно отвергает mapped
network drive. Это не обнаружение всех удалённых mount points на любой ОС:
за предоставление действительно локального стабильного хранилища отвечает
вызывающая сторона. Из наличия локально выглядящего пути не выводится
доказанная локальность носителя или безопасность устройства.

Открываются только обычные файлы, с read-only flags; на POSIX при наличии
используются `O_NOFOLLOW` и `O_NONBLOCK`. Последний предотвращает зависание
на FIFO при наблюдаемой смене типа перед open. Нет обхода каталога или
поиска похожих имён; неперечисленные файлы не читаются. Два различных
регистра в самой описи запрещены, но поиск посторонних case aliases
в каталоге не производится.

Чтение оснований идёт блоками не более 64 КиБ с SHA-256 и дополнительной
однобайтной проверкой конца. В памяти не удерживается содержимое оснований;
сохраняются только исходные байты маленького индекса. До 11 дескрипторов
остаются открытыми до итоговой проверки всей описи и затем закрываются,
включая все пути отказа. При ошибке закрытия остальные дескрипторы также
обрабатываются; успешный результат не возвращается.

Отпечатки пути сравниваются только с последующими отпечатками `lstat`
того же пути; отпечатки handle — только с последующими `fstat` этого handle.
Между `stat` и `fstat` нет непереносимого требования равенства inode/ctime
или атрибутов Windows. Размер сверяется также с фактически прочитанными
байтами. У файлов контролируются identity/type/size/mtime/ctime/link count/
reparse attributes; atime не используется. У каталогов контролируются
identity/type/reparse attributes, а изменение размера/времени из-за
постороннего дочернего файла само по себе не считается перенаправлением.

Наблюдаемая замена, усечение, изменение метаданных или hash дают отказ;
итоговая проверка обнаруживает и изменения раннего файла во время чтения
последующих. Это не защита от злонамеренной подмены между наблюдениями,
восстановления метаданных или изменений после возврата. Блокировку ядра ОС
на настоящей файловой операции нельзя объявить отменённой по числу прочитанных
байтов; гарантия wall-clock timeout не даётся.

Ошибки имеют тип `AdmissionDataError` и короткий постоянный код, например
`index-keys`, `index-total-size`, `filesystem-changed` или
`filesystem-integrity`. Сообщения не содержат имён, байтов документа,
COM-порта или текста исключения ОС. После отказа нет частичного результата,
обозначенного как проверка всего комплекта. Модуль не пишет файлы,
не создаёт каталоги/receipts, не меняет разрешения и не исполняет документы.

## Проверки и границы следующего шага

Из `host/`, без установки зависимостей:

```sh
python -B -m unittest discover -s tests -p test_lv_admission.py -v
python -B -O -m unittest discover -s tests -p test_lv_admission.py -v
python -B -m unittest discover -s tests -p test_lv_runner.py -v
```

Тесты покрывают исходные байты/различающиеся hashes, все роли и aliases,
типы/ключи/дубликаты/границы, ограничение до JSON allocation, максимальные
размеры с потоковым чтением, отсутствующие/изменённые/необычные файлы,
путевые отказы, утечки дескрипторов и ограниченные ошибки. Отдельный свежий
Python-процесс проверяет отсутствие записи, сети, subprocess и импортов
операционного пути. Искусственные Windows-like `stat`/`fstat` различия
проверяют логику, но не заменяют запуск на Windows. Синтетический
`board_config` намеренно непрозрачен; его hash не превращает fixture
в реальный паспорт. Передача результата в неизменённый `run_device`
по-прежнему вызывает безусловный отказ.

Для включения нового модуля в будущий пакет нужен отдельно рассмотренный
преемник source inventory. Замороженная схема PR158/159 с 23 ключами,
packaging recipe, spec, lock и CI здесь не расширялись. Файлы admission
не добавлены в namespace каталога сохранённой серии collector/runner.

Канал внешнего решения на точный hash, полномочия человека, проверка
физических оснований, текущая применимость и поручение одной серии остаются
отдельной незавершённой задачей. Этот модуль не закрывает её и не является
операторской инструкцией подключения, прошивки или запуска. Успех тестов
не означает Windows qualification, физический LV-001 или приёмку MVP.
