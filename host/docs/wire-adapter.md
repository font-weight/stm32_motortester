Python-реализация независима от C-кода; в приложение C-код не переносится.
Новый вариант протокола этим документом не задаётся.

## Границы

`motortester/wire.py` кодирует и проверяет отдельные кадры и собирает их из
ограниченных порций байтов. USB/COM не открывается. Модель записи, эмулятор,
GUI, CLI, формат `.mtcap`, firmware и общая спецификация не изменяются.

Тип сообщения и payload остаются непрозрачными. Направление, HELLO, сеанс,
порядок sequence/request, команды, сборка окна, Stop и восстановление сеанса
принадлежат будущему диспетчеру. В частности, type 127 в эталонном векторе
проверяет byte codec, но не становится допустимой командой. Успешный `Frame`
не доказывает ни успешную команду, ни полное окно измерения.

Программные тесты на Linux не подтверждают совместимость устройства, Windows
10, физический USB, точность времени или аппаратный захват. Приёмка требует
независимого Critic-B на точный SHA; общий контракт требует также Critic-A
по [правилам проекта](../../docs/quality-gate.md). Статус `software-ready`
не присваивается.

## API

Модуль использует только стандартную библиотеку Python.

- `Frame(message_type, session, sequence, request_id, payload)` — неизменяемый
  объект. Поля соответственно uint8, uint64, uint32, uint32 и `bytes` длиной
  0…512. Принимается именно `int`, без `bool`, float, строк и подклассов;
  payload — именно `bytes`, без неявного копирования `bytearray`/`memoryview`.
  Конструктор и encoder проверяют поля до упаковки и выделения кадра.
- `encode_frame(frame) -> bytes` — один COBS-кадр **с** конечным нулём.
- `decode_frame(encoded: bytes) -> Frame` — ровно один COBS-кадр **без** нуля.
  Пустой аргумент, нуль внутри или переданный разделитель отвергаются.
- `WireError(ValueError)` содержит `.code: DiagnosticCode` и фиксированное
  русское сообщение. В текст ошибки не копируются данные входа.
- `StreamDecoder().feed(data: bytes, now_ms: int) -> StreamResult` — принять
  0…4096 байт. Все байты одной порции имеют переданную метку времени.
- `tick(now_ms) -> StreamResult` равнозначен `feed(b"", now_ms)`; его нужно
  вызывать регулярно даже при отсутствии данных.
- `reset() -> None` удаляет незавершённый кандидат, состояние отбрасывания и
  базу времени. Вызывать на явной границе отключения/нового транспорта, а не
  между чтениями. Сброс накопителя сам по себе не сбрасывает сеанс или прибор.

`StreamResult.frames` — tuple неизменяемых `Frame` в порядке байтов потока.
`StreamResult.diagnostics` — tuple неизменяемых `Diagnostic(code, count)`.
Ошибки агрегируются **только внутри текущего вызова** по коду, в порядке первого
появления; успешный кадр не добавляет диагностику. Внутреннего журнала, очереди
выходов, накопительных счётчиков или скрытого callback нет.

**Чередование кадров и ошибок в результате не сохраняется.** Будущий
диспетчер обязан сначала проверить diagnostics и применить политику
несовместимости/восстановления перед признанием порции успешной. Например,
наличие VERSION вместе с обычными кадрами нельзя скрыть обработкой только
`frames`. Сама политика сеанса не реализуется в HOST-002.

## Проверка кадра и диагностические коды

Все многобайтные числа little-endian; заголовок занимает 24 байта. CRC-32/ISO-HDLC
покрывает заголовок и payload, хранится четырьмя little-endian байтами и не
включает COBS/разделитель. Контроль ASCII `123456789` — `0xcbf43926`.
Это проверка случайного повреждения, не аутентификация.

Порядок отказа: тип/предел входного аргумента → структура COBS и предел
декодирования → длина 28…540 и соответствие payload_length → CRC → точная
версия 0.1 → reserved по смещениям 3, 6, 7. Кадр с неверной CRC и изменённой
версией сообщает CRC, а не подтверждённую несовместимость. Некорректная версия
с правильной CRC сообщает VERSION, даже если reserved также ненулевые.
Оба байта версии должны совпадать: новая minor не принимается автоматически.

| Код | Причина |
|---|---|
| ARGUMENT | Неверный Python-тип аргумента |
| RANGE | Числовое поле или время за допустимыми границами |
| PAYLOAD_SIZE | Payload при создании/кодировании больше 512 байт |
| FRAME_SIZE | Аргумент `decode_frame` длиннее 543 байт |
| FRAMING | Пустой прямой decode, нули или неверная структура COBS |
| LENGTH | Декодированная длина/поле payload_length неверны |
| CRC | Контрольная сумма не совпадает |
| VERSION | CRC-valid кадр с версией, отличной от 0.1 |
| RESERVED | Ненулевые reserved при правильных CRC и версии |
| CHUNK_SIZE | Вызов `feed` содержит больше 4096 байт |
| CLOCK_ROLLBACK | Время меньше метки предыдущего успешного feed/tick |
| TIMEOUT | Межбайтовый или полный срок кадра истёк |
| OVERFLOW | Получен 544-й ненулевой байт без разделителя |

Названия ошибок API Python не обязаны совпадать с C enum: например, для
пустого прямого decode используется FRAMING. Пустые разделители **потока**
игнорируются. Ошибка отдельного кадра не порождает ответ устройству; после
его разделителя следующий кадр проверяется независимо.

## Границы ресурсов и времени

Константы API: `MAX_PAYLOAD_SIZE=512`, `MAX_RAW_SIZE=540`,
`MAX_ENCODED_SIZE=543`, `MAX_CHUNK_SIZE=4096`,
`MAX_TIME_MS=2**64-1`, `INTERBYTE_TIMEOUT_MS=1000`, `FRAME_TIMEOUT_MS=3000`.

Накопитель имеет фиксированный `bytearray(543)` и несколько полей состояния.
Один вызов возвращает не больше 137 кадров: ранее накопленный короткий кадр
может завершиться первым байтом, затем остаётся не более `4095 // 30` полных
минимальных кадров. Видов диагностики не больше числа членов конечного enum
(13); счётчик отдельного кода не больше 4097. Повторные вызовы не увеличивают
историю. У объектов Python есть служебные накладные расходы; размер массива
не является утверждением о полном потреблении памяти или скорости приложения.

Порция больше 4096 байт отвергается целиком **до** копирования, обхода байтов,
истечения timeout или изменения состояния. Будущий транспорт должен ограничить
размер чтения либо сам разбить большие данные на порции. Внутренней скрытой
нарезки нет. Неверные типы, диапазон времени и откат часов также не меняют
буфер, временную базу и режим отбрасывания.

`now_ms` — именно целое число 0…`2**64-1`, монотонное без переполнения.
Одинаковые метки разрешены. Даже пустой успешный feed/tick обновляет базу
проверки монотонности, но **не** время последнего байта или начала кадра.
В отличие от uint32-часов C parser, переход через максимум здесь не считается
обычным rollover: требуется явный reset. Источник для будущего транспорта,
например, `time.monotonic_ns() // 1_000_000`; календарные часы не подходят.

Межбайтовый срок истекает при `now_ms - last_byte_ms >= 1000`, полный срок —
при `now_ms - first_byte_ms >= 3000`. Сроки отсчитываются с ненулевых байтов;
idle-состояние без кандидата не истекает. Они проверяются **до** обработки
новой порции, включая разделитель. Одновременное истечение обоих сроков даёт
одну TIMEOUT. После TIMEOUT или OVERFLOW весь остаток отбрасывается до первого
нуля включительно. Нуль на самой границе timeout восстанавливает синхронизацию,
но не завершает просроченный кадр успешно. Повторные tick в режиме отбрасывания
не создают повторной TIMEOUT. Следующий кадр после нуля принимается независимо.

Получение ровно 543 ненулевых байтов ещё не является переполнением; OVERFLOW
вызывает следующий ненулевой байт. Если 544-м байтом пришёл нуль, проверяется
накопленный кадр. Время поступления отдельных байтов внутри уже прочитанной
порции неизвестно: feed надо вызывать сразу после чтения, tick — регулярно.
Проверка не является измерением физических задержек USB. Объект рассчитан на
одного владельца без конкурентных feed/tick/reset.

## Воспроизводимая проверка

Из каталога `host/`, без сторонних пакетов:

```sh
python -m unittest discover -s tests -p 'test_wire*.py' -v
```

`tests/test_wire.py` — авторские регрессии. Фиксированный вектор A взят из
[vectors-v0.1.json на закреплённом SHA](https://github.com/font-weight/stm32_motortester/blob/124b3f32e1e7f7282bce283baa4c9406d4d72950/protocol/vectors-v0.1.json).
Дополнительные ожидаемые байты и повреждённые кадры собираются отдельными
побитовым CRC и COBS-сборщиком, а не только через round-trip проверяемого codec.
Проверяются long COBS blocks, все границы разделения, объединение, пустые
разделители, повреждение/усечение, версия/reserved, точные сроки, reset,
неизменяемость результатов и ограниченность повторного мусора.

`tests/test_wire_conformance.py` и `tests/fixtures/wire/` принадлежат
независимому автору проверок. Результаты запусков и привязка к финальному SHA
должны войти в отчёт проверки; наличие команды или файла не заменяет запуск.
Эти тесты не выполняют будущие handshake, Stop, сборку окон или реальные
отключения USB и не закрывают их критерии MVP.
