# Зависимости: уведомления, исходники и проверка замены

## Область и важное уведомление

Мотортестер использует Qt, PySide6-Essentials и shiboken6 версии **6.12.0**.
Их исходные лицензионные варианты и условия сторонних компонентов сохраняются;
лицензия авторского кода приложения их не заменяет. Для рассматриваемого
LGPL-варианта нужны соответствующие уведомления, доступ получателей к исходникам
и допустимый способ изменения/замены библиотек. Настоящий комплект фиксирует
технические сведения для проверки. Он не является юридическим заключением,
выбором лицензии за правообладателя или разрешением на распространение.

В собранной папке `licenses/` сохраняются прежние уведомления установленных
пакетов, CPython, полный pyserial 3.5 и три GNU-текста в `qt-6.12.0/`.
Дополнение `dependency-6.12.0/` содержит:

- `manifest.json`: источники, члены архивов, SHA-256, размеры, авторские
  уведомления и все **55** исходных attribution-записей;
- `notices/<SHA256>`: **41** буквальный upstream-файл, **163526 байт** суммарно;
- `dependency-sources.md`: копию этого руководства.

Те же входы находятся в исходниках в `host/packaging/licenses/dependency-6.12.0/`,
а руководство в `host/docs/`. Файлы названы по SHA-256, но их исходные названия
сохранены в `input_files[].source_path` и `proposal.literal_files[].path` manifest.
Поле `saved` внутри сохранённого proposal описывает исходный каталог свидетельств;
для этого комплекта фактический относительный путь задаёт `input_files[].path`.
Оба Qt-family дистрибутива ссылаются на один общий набор в `inventory.json`.
Это ссылка на совместный набор сведений, а не утверждение, что каждый компонент
скомпилирован в каждый wheel. `manual_review_required` остаётся `true`.

Коллектор работает офлайн и не исполняет исходники, заголовки или HTML из этого
набора. Их байты копируются без нормализации. В частности, `bufferprocs_py37.h`
содержит исходный текст, используемый upstream как attribution-вход; он не
добавляется в сборку как новый исполняемый код.

## Что остаётся незакрытым

Все 55 записей исходного proposal сохранены: 51 из достижимого графа QtBase,
две Shiboken и две TIFF/WebP. Mesa/LLVM top-level тексты учитываются отдельно
в списке буквальных файлов. **11 записей без LicenseFile остаются unresolved**:
`md4`, `md5`, `sha1`, `siphash`, `tika-mimetypes`, `tlexpected`,
`unicode-character-database`, `unicode-cldr`, `emoji-segmenter`, `wintab`, `libjpeg`.
Их copyright, License/LicenseId, версия и прочие исходные поля не потеряны.
Нужно проверить применимые source-file notices и их охват в фактической поставке;
один SPDX ID не заменяет недостающий текст. Для PSL data отдельно сохранён MPL-2.0.

Источники и заголовки, данные, CMake и тестовые зависимости в supplier-графе
не обязательно попали в машинный код. Например, запись Linux perf в QtTest
не доказывает наличие Linux runtime в Windows-приложении. Все исходные
`compiled_into_candidate: unverified` сохранены. Ни общий `DEPENDS_ON`, ни
совпадение версии не заменяют доказательство конкретной компоновки.

Для исходного app commit `1930f75b976be17a3df51da079b6d8ba275e3f73` (run17)
сохранились manifest/provenance, но исходный бинарный ZIP здесь не проверяется
повторно. Новый Windows-кандидат этим дополнением не создан.

- Для 20 QtBase DLL/плагинов имеется соответствие всем PE-секциям и всем
  остальным байтам официального SDK, кроме checksum/certificate fields.
  Целые файлы имеют разные хеши; проверка Authenticode не заявляется.
  Supplier source inventory совпал с 6974 файлами архива буквально и 16131
  только после LF→CRLF; различия release/Git-метаданных учтены отдельно.
  Это полезная связь поставщика с исходниками, но не доказательство всех
  compiler inputs и воспроизведения его бинарника.
- Для QtSvg, imageformats и PySide/Shiboken остаётся точная связь с конфигурацией
  сборки/патчами поставщика либо документированная проверенная пересборка.
- Для Mesa/LLVM остаются notice/source-file coverage фактически связанного кода
  и сведения об исторической сборке. Не утверждается, что каждая permissive
  зависимость сама по себе требует передачи всех исходников.
- Microsoft DLL, внешние OpenSSL DLL, CPython и прочие компоненты требуют своего
  отдельного review; этот supplement не подменяет их прежние уведомления.
- До распространения нужно проверить выбранный лицензионный маршрут, состав
  окончательного ZIP, права и условия поставки и достаточный доступ к исходникам.

## Пересборка и замена: порядок будущей проверки

Это план непроведённой проверки, а не обещание работающих команд замены.
[Upstream-сборка Qt for Python](https://doc.qt.io/qtforpython-6/building_from_source/index.html)
и [встраивание support-кода Shiboken](https://doc.qt.io/qtforpython-6/developer/embed.html)
описывают основу, но не являются выполненным рецептом этого Windows-кандидата.

1. Получателю должны быть доступны точные исходники приложения и выбранных
   библиотек, применённые изменения, необходимые build scripts/configuration и
   перечень инструментов. Сверить архивы по приведённым размерам/хешам. Исходный
   `source.zip` текущего рецепта содержит `host/`, а не все исходники зависимостей.
2. В отдельной Windows x64 среде собрать совместимое небольшое безопасное
   изменение библиотеки. Сохранить её исходный diff, версии инструментов,
   команды, конфигурацию, результаты и хеши до/после. Supplier QtBase сообщает
   MSVC 19.44.35227.0, CMake 4.3.2 и Ninja 1.10.2; это сведения о поставщике,
   а не уже проверенный нами полный рецепт.
3. В отдельной копии кандидата проверить native-library replacement. Подтвердить
   фактически загруженные путь, хеш и наблюдаемое изменение. Один неизменённый
   успешный запуск приложения не доказывает замену библиотеки.
4. Отдельно изменить и перепаковать PySide6/shiboken6 Python-модуль: текущий spec
   использует `noarchive=False` и `PYZ(a.pure)`, поэтому модуль может находиться
   внутри PYZ. Проверить изменённый член архива и поведение. DLL-only опыт этого
   не проверяет. Support Python, встроенный в native Shiboken, требует отдельной
   пересборки/проверки регенерации заголовков.
5. Повторить существующие GUI, serial-import и Record/Stop/Save/Open smokes без
   открытия физического порта; связать исходы, включая отказы, с точным новым
   кандидатом. Исходные Windows-свидетельства не перезаписывать.
6. После независимой проверки опубликовать действующие инструкции замены и
   способ доступа получателя к исходникам. Текущий hash-lock восстанавливает
   публичные wheels; запуск прежнего рецепта без изменения входов не проверяет
   использование модифицированной библиотеки. Требуется отдельно проверенный
   путь replacement/repack; этот supplement не меняет recipe/spec/lock.

[LGPLv3 §4](https://doc.qt.io/qt-6/lgpl.html) следует оценивать применительно к
выбранному способу объединения/замены. Побитное воспроизведение vendor-бинарника
не объявляется универсальным требованием лицензии; инженерные доказательства
и окончательное правовое решение различаются.

## Ограниченный комплект и срок доступа

Модель размера исходного набора: 63718814 байт ранее учтённых app/source/receipts
плюс 73622536 байт четырёх Qt/PySide архивов плюс 163526 байт notice-входов =
**137504876 байт**, ещё без нового manifest, этого руководства и накладных
расходов внешнего контейнера. Это расчёт выбранных файлов, не измеренный размер
нового готового ZIP. Дополнительные необходимые источники/метаданные учитывать
отдельно и измерить окончательный контейнер.

Не включать весь исследовательский каталог или SDK/reference binaries вместо
выбранных исходников. Настройка хранения артефакта на один день сама по себе не
обеспечивает требуемую доступность исходников получателю: способ и срок доступа
должны быть определены и проверены до распространения. Успешный offline collector
и source/fake-backed тесты не закрывают эти условия, Windows replacement или
общую приёмку выпуска.
