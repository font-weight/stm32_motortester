# HOST-007: интерактивный байтовый эмулятор

`motortester.device_emulator.DeviceEmulator` — ограниченный детерминированный
синтетический собеседник для проверки приложения. Он принимает и выдаёт настоящие
байты COBS/CRC wire v0.1, но не открывает USB и не выполняет прошивку.

Задача и неизменяемые критерии: [HOST-007, issue №42](https://github.com/font-weight/stm32_motortester/issues/42).
Источник payloads и правил сеанса — **непринятый** общий draft
[`c54bd955aaf3cb863ef3df043ea237ea62e74ad4`](https://github.com/font-weight/stm32_motortester/blob/c54bd955aaf3cb863ef3df043ea237ea62e74ad4/protocol/wire-v0.1.md)
и [описание session guard](https://github.com/font-weight/stm32_motortester/blob/c54bd955aaf3cb863ef3df043ea237ea62e74ad4/docs/session-guard.md).
Модуль написан по этим документам; реализация прошивки не копировалась.

HOST-006 `session.py` сохраняет собственный источник `b6ae8025baf1a47e8173997029d2d8b858ada74c`;
непрозрачный `wire.py` сохраняет свою более раннюю привязку. Их файлы и происхождение
не изменены. Совместимость ограниченного пути проверяется исполнением, а не заменой SHA.

## Поддержанный путь

- Профиль 1: 2048 исходных 12-битных кодов в 4096 байтах little-endian.
- Normal, аналоговый источник, нарастающий и спадающий фронт, предыстория 0.
- HELLO, GET_CAPS, CONFIG, ARM, STOP, GET_STATUS, RELEASE_WINDOW.
- Только объявленные возможности: `capability_bits=9`, `mode_bits=2`,
  `source_bits=1`, `edge_bits=3`, `pre_count=1`. `firmware_build=0` означает,
  что номер реальной сборки прошивки не заявляется.
- Детерминированный явный вызов `trigger()` вместо физического обнаружения фронта.

Auto, Single, внешний запуск, реальный транспорт, GUI и запись файлов не входят
в эту итерацию. Успешная проверка не подтверждает ADC/DMA, физическую частоту,
порог запуска, native USB, Windows или готовность MVP к выпуску.

## Публичный API

Все вызовы выполняет один владелец последовательно. Фоновых задач, ожидания
реального времени и внешнего ввода-вывода нет. Время — целое число миллисекунд
`0..2**64-1`, монотонное на всём протяжении жизни объекта, включая disconnect.
`bool`, подклассы чисел/bytes, отрицательные, дробные и слишком большие значения
не принимаются. Ошибка аргумента возникает до копирования данных или изменения
часов и состояния: `DeviceError` с фиксированным русским текстом и `ErrorCode`.

| Вызов | Результат и смысл |
|---|---|
| `DeviceEmulator()` | Новый эмулятор без согласованного сеанса |
| `write(data: bytes, now_ms: int)` | Неизменяемый `WriteResult(accepted_prefix, diagnostics, provenance)` |
| `read(max_bytes: int, now_ms: int)` | От 0 до `max_bytes` байт, **принятых виртуальным транспортом** |
| `trigger(now_ms: int)` | `True` при выделении окна из WAITING; иначе `False` |
| `tick(now_ms: int)` | Неизменяемый кортеж локальных диагностик текущего вызова |
| `disconnect(now_ms: int)` | Сброс RX/TX и сеанса; начатый кадр может оборваться |
| `snapshot()` | Неизменяемый снимок состояния и происхождения |

За один write/read допускается не более 4096 байт. `read(0)` не выделяет sequence,
не начинает END и не снимает барьер Stop; проверка времени всё равно выполняется.
Первый возвращённый байт фиксирует TX sequence. Первый байт END необратимо
фиксирует END и его tombstone. Последний байт STOP_ACK снимает барьер Stop;
ожидающий STATUS(STOPPED) не мешает следующей команде.

`accepted_prefix` — число принятых байтов от начала порции, а не число команд.
Вызывающий код хранит `data[accepted_prefix:]`, читает накопившийся ответ и затем
передаёт оставшийся суффикс. При недостатке места возвращается `BACKPRESSURE`;
команда не исполняется без места для обязательного ответа. Перепосылать уже
принятый префикс вместо сохранения суффикса нельзя.

Локальная `Diagnostic(code: str, count: int)` сообщает фиксированные коды ошибок
framing/CRC/версии/тайм-аута, отбрасывания чужого сеанса, дубликата, восстановления
и backpressure. Список и счётчики относятся только к текущему вызову; последняя
порция видна в snapshot. Повреждённые кадры не получают выдуманный wire ERROR.
`read` тоже проверяет сроки; его локальные диагностики доступны через snapshot.

Снимок содержит state/reason, session/negotiated, generation/window_id/config_id,
точные 16 байт принятого CONFIG, следующие RX/TX sequence, last_request_id,
stop_barrier, held_samples, terminal/tombstone, control_descriptors, rx_used,
tx_offset/tx_size, now_ms/hold_started_ms, dropped_windows, data_offset,
continuation, diagnostics и provenance. `Terminal` хранит outcome (`END`/`ABORT`),
generation, window_id, sample_crc32 и reason. Снимок не копирует массив отсчётов.

## Ограничение памяти и порядок передачи

Постоянно выделены один sample buffer на 4096 байт и существующий RX accumulator
на 543 байта. Сохраняются не более восьми небольших управляющих дескрипторов,
один текущий TX-кадр не более 544 байт, один последний RX-кадр для проверки
точного повтора и terminal/tombstone последнего окна. Истории окон и сообщений
нет. DATA создаётся по мере чтения блоками до 250 отсчётов; целое закодированное
окно не складывается в очередь. Временная порция результата read ограничена
4096 байтами; обработка write последовательна, без списка всех команд порции.

Перед приёмом очередного RX-байта резервируются три места управляющей очереди.
Не начатый устаревший событийный STATUS заменяется более новым; обязательные
ответы команд не удаляются при Stop. Начатый кадр всегда завершается первым.
Эмулятор не моделирует время передачи USB, DMA staging или карту памяти STM32.
Это ограничения памяти Python-модели, не доказательство вмещения прошивки в SRAM.

Новый HELLO с отличающимся nonce удаляет не начатый старый вывод и сбрасывает
настройки/счётчики. Уже начатый старый кадр допередаётся перед HELLO_ACK нового
сеанса; его завершение не меняет состояние нового сеанса. Одинаковый текущий
nonce не выполняет повторный сброс, включая состояние восстановления.
Ошибки направления, порядка sequence/request и исчерпание счётчиков запрещают
дальнейшую работу до свежего HELLO. Идентификаторы не оборачиваются.
Для sequence/request последний допустимый номер — `2**32-2`; для
config_id/window_id и dropped_windows предел — `2**32-1`. Попытка увеличения
за предел переводит в ERROR/COUNTER_SATURATED. При наличии доступного TX sequence
выдаётся соответствующий STATUS. У HOST-006 собственный более строгий предел
config/window; совместимость на миллиардах окон этой итерацией не заявляется.

## Синтетические отсчёты

Настройки таймера `72 000 000 / (71+1) / (19+1)` задают **номинальные** 50 kS/s.
Эмулятор формирует окно мгновенно при `trigger()`, не ждёт 40,96 мс и не измеряет
реальную частоту. Каждый индекс `i` от 0 до 2047 получает целый код:

- `i=0`: `level_code` для rising и `level_code-1` для falling;
- `i=511`: 0; `i=1023`: 4095;
- остальные: `(73*i + 19*window_id + 7*generation) & 4095`.

Воображаемый предыдущий синтетический отсчёт равен `level_code-1` при rising и
`level_code` при falling. Поэтому индекс перехода равен 0 и согласован с нулевой
предысторией. Это заранее определённое синтетическое событие, не свидетельство
работы компаратора или физического порога. WINDOW_BEGIN содержит trigger_kind=0,
channel=0, external_edge_id=0 и quality_flags=2: массив действительно содержит
крайние коды 0 и 4095. Rail flag не означает доказанную аналоговую перегрузку.
CRC окна вычисляется по 4096 исходным байтам кодов.

`Provenance` доступен в WriteResult и Snapshot, неизменяем и явно указывает
simulator/draft/nominal_timing/synthetic_waveform, SHA источника и спорное
толкование тайм-аута. Дополнительное поле происхождения в wire не изобретается.

## RELEASE, Stop и срок удержания

После END удерживается окно; CONFIG/ARM получают BUSY. Совпавшие generation,
window_id и CRC в RELEASE освобождают соответствующий буфер. Новое ожидание
Normal разрешается только после последнего байта первого RELEASE_ACK.
Повторный сознательный RELEASE с новым request_id получает ACK без повторного
вооружения. Точный повтор предыдущего входного кадра вообще не исполняется снова.

Tombstone сохраняет последнее committed END. Поздний RELEASE после Stop или
во время следующего окна подтверждает старое завершённое окно без освобождения
нового буфера. Следующий END заменяет tombstone; запрос для более старого окна
или с неверным CRC получает BAD_WINDOW_RELEASE. Это не разрешение автоматически
повторять запрос после неопределённого результата передачи.

Stop сохраняет необходимый прежний ответ, начатый BEGIN/DATA/END, нужный terminal
и RELEASE_ACK. Если окно выделено, а END ещё не начат, выдаётся единственный
ABORT перед STOP_ACK; без выделенного окна ABORT не создаётся. Начатый END
завершается без ABORT. После STOP_ACK старые данные не выдаются. Stop отменяет
продолжение, а поздний RELEASE его не возвращает. Повторный Stop не добавляет
второй terminal outcome.

**PROVISIONAL, отдельное проверяемое допущение:** 5000 мс отсчитываются от принятия
**последнего** байта END. При `elapsed >= 5000` без RELEASE/Stop эмулятор отменяет
продолжение, переходит в ERROR и выдаёт STATUS.reason=TRANSFER_TIMEOUT (3).
Сохраняются END и tombstone, второй END/ABORT не создаётся. RELEASE после этого
может освободить буфер, но не вооружает Normal. Stop может безопасно завершить
остановку. На точной границе срока сначала проверяется таймер, затем команда;
Stop переводит в остановку, RELEASE после истечения не возобновляет захват.

В draft указан срок 5000 мс, но точка отсчёта ещё ожидает ответа A в
[уточнении к PR №14](https://github.com/font-weight/stm32_motortester/pull/14#issuecomment-6097915092).
Этот текст и успешные тесты не объявляют толкование принятым wire-контрактом.

## Воспроизводимая проверка

Из корня репозитория, с установленными GUI-зависимостями для полной проверки:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=host:/tmp/motortester-deps QT_QPA_PLATFORM=offscreen \
  python -m unittest discover -s host/tests -p 'test_device_emulator*.py' -v
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=host:/tmp/motortester-deps QT_QPA_PLATFORM=offscreen \
  python -O -m unittest discover -s host/tests -p 'test_device_emulator*.py' -v
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=host:/tmp/motortester-deps QT_QPA_PLATFORM=offscreen \
  python -m unittest discover -s host/tests -v
```

`/tmp/motortester-deps` — текущая Linux-среда проверки, не обязательный путь
установки пользователя. Авторские проверки находятся в `test_device_emulator.py`:
20 полных циклов с неизменённым HOST-006, реконструкция исходных байтов/CRC,
Stop на границах кадров, RELEASE/tombstone, свежий HELLO при частичной передаче,
строгие аргументы/часы, backpressure и ограниченность памяти. Отдельно именованный
`test_provisional_hold_deadline_last_end_byte_exact_and_stop_release_races`
проверяет только описанное **PROVISIONAL** толкование срока.

Независимые бинарные векторы и проверки принадлежат отдельному автору
`test_device_emulator_conformance.py`. Запуск тестов под `-O` не удаляет подготовку
сценариев: действия не скрыты в bare assert. Фактические результаты, неизменные
хеши и оценка независимого Critic-B привязываются к опубликованному SHA отдельно.
Эта документация не выдаёт автору PASS, не принимает общий контракт и не закрывает
Windows, USB или физические испытания.
