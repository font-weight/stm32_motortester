# HOST-010: ограниченный цикл приёма

Ограниченный программный путь Auto/Normal/Single для аналогового источника в
[текущем объединении](mvp-union.md). Исходный HOST-010 и его отдельный отчёт
проверяли только Normal/analog; их оценка не переносится на расширение режимов.
Текущие программные проверки не подтверждают Windows, USB прибора или принятие
общего wire-контракта. Предыстория текущего профиля — 0 отсчётов.

## Входы и владение

`AcquisitionRuntime` принадлежит одному рабочему потоку захвата, не потоку Qt.
Конструктор принимает явно выбранное `origin="simulator"` либо `"device"`,
транспорт с `read(size)`/`write(bytes)`, монотонные часы `clock_ms()` и необязательные
часы UTC для метки приёма. Порт открывает и закрывает вызывающий код. В модуле нет
Qt, pyserial-import, файлового ввода/вывода, фонового потока и автоматического ARM.
Обычный `SerialTransport` из HOST-009 подходит этому интерфейсу; его ограничения
блокирования/размера и single-owner contract сохраняются.

За один `pump()` выполняется максимум одна запись оставшегося префикса команды
и одно чтение максимум 4096 байт. Нулевое чтение означает отсутствие данных.
Запись возвращает только известное число принятых байтов; исключение/некорректный
ответ означает неизвестное принятие, recovery без повторной отправки.
Часы проверяются до и после блокирующих операций. Неисправные часы после записи
также запрещают повтор команды: число уже переданных байтов восстановить нельзя.

Команды: `start(nonce)`, `configure(Config(...))`, `arm()`, `stop()`.
События контроллера возвращаются вызывающему коду, без скрытой очереди; это
ограниченная порция одной итерации. `snapshot()` даёт принятые настройки/состояние.

## Сохранность результата и RELEASE

Кадры сначала проходят декодер, затем admission контроллера сеанса. Только
допущенные BEGIN/DATA/END/ABORT передаются существующему WindowReceiver.
При ABORT до BEGIN приёмника ещё нет: контроллер сохраняет терминальное событие,
runtime не создаёт пустую запись и не передаёт такой кадр в несуществующий приёмник.
ExpectedContext строится
из уже подтверждённых CONFIG/CAPS/ARM, а не из недоверенного BEGIN. Та же копия
контекста используется для проверяющей фабрики WindowReceipt.

Полное окно проходит проверку количества 2048, метаданных, порядка и CRC. Только
тогда создаётся неизменяемый Capture с исходными кодами. `pending_capture` хранит
не более одного такого объекта. До `acknowledge(capture)` RELEASE не отправляется.
Потребитель сначала сохраняет/удерживает запись, затем передаёт именно этот объект,
а не равную ему копию. После подтверждения ожидается WINDOW_RELEASED; следующий
Auto/Normal-захват разрешается контроллером без нового ARM; Single требует
явного следующего ARM. Auto timeout сохраняется как `trigger_kind="auto_timeout"`
с `trigger_index=None`, без придуманного фронта. Повторное подтверждение
при текущем ожидании ACK запрещено.

Если Stop уже подтверждён, запись остаётся доступной, но её принятие не отправляет
RELEASE и не перезапускает захват. Во время неподтверждённого Stop принятие откладывается.
Если RELEASE/его ACK потерян, recovery сохраняет Capture даже после первого
подтверждения потребителем. Повторный `acknowledge` в recovery переносит владение
потребителю и очищает этот слот, без какой-либо команды прибору.

Неполные окна/отклонённые метаданные доступны через `incomplete_result` и
`take_incomplete()`: исходные фрагменты, отсутствующие диапазоны и причина,
никогда не дополненные нулями отсчёты. Даже результат с полными кодами, но неверной
меткой UTC/метаданными, остаётся диагностическим результатом, не выдаётся за Capture.
Результат необходимо забрать до нового запуска. Новое окно не заменяет старый слот.

## Время и восстановление

1000 мс без известного прогресса записи — локальная политика write-stall recovery.
Это не изменение wire-тайм-аута: контроллер отсчитывает ответ от полного принятия
команды. WindowReceiver проверяет 3000 мс без прогресса после BEGIN. Ожидание
реального триггера в Normal до BEGIN не имеет такого тайм-аута.

`disconnect()` переводит контроллер в recovery и сохраняет фрагменты. Открытие
того же COM-порта не доказывает аппаратный сброс. Повторный `start` после recovery
требует `reset_confirmed=True`, новый nonce и освобождённые результаты; этим
вызывающий код явно утверждает, что выполнил внешний reset boundary. Runtime
сам не устанавливает достоверность аппаратного сброса. Автопереподключения нет.

Повреждение любой части одной порции декодера отклоняет всю эту порцию до
передачи содержащихся в ней кадров контроллеру: порядок diagnostics/frames в API
декодера не выражен. Ранее принятые фрагменты сохраняются. Это консервативная
политика целостности, не попытка восстановить измерение по повреждённым данным.

Уточнение диагностики MVP-U02: если все ошибки порции имеют явный код декодера
`DiagnosticCode.VERSION`, событие recovery сохраняет `FaultCode.VERSION`.
Декодер выдаёт этот код только после проверки структуры, длины и CRC кадра;
байты версии в повреждённом или незавершённом кадре не доказывают несовместимость.
Любая другая ошибка, включая смешанную порцию VERSION/CRC, остаётся `DECODE`.
Порядок проверок декодера и приоритет уже истёкшего срока контроллера не меняются.
В обоих случаях вся порция отклоняется, состояние переходит в recovery, прежние
результаты сохраняются; новых ARM, RELEASE или переподключения не добавляется.
Принимаемая wire-версия остаётся 0.1. Это уточнение причины отказа, не расширение
поддерживаемого протокола и не подтверждение совместимости реального устройства.

## Проверки и границы

Авторский `test_runtime.py` проверяет 20 реальных byte-peer окон одной генерации:
байты → decoder → session admission → WindowReceiver → Capture → save → load,
с независимым ожидаемым массивом до consumer ACK; частичные байты, Stop,
потерю соединения, неизвестную запись RELEASE, монотонные часы и write-stall.
Отдельные conformance tests принадлежат другому автору; их итог фиксируется после
заморозки версии. Независимый Critic-B назначается для окончательного SHA.

`test_runtime_version_diagnostic.py` проверяет это уточнение настоящими COBS/CRC
байтами независимых fixtures: другую major/minor, повреждения и смешанные порции,
все границы разбиения кадра, незавершённый кадр и тайм-аут, отсутствие допуска
соседних валидных кадров, сохранность неполного и ранее полного окна. Транспорт
в этих проверках программный; реальный COM-порт не открывается.

Реальный порт/Windows не проверялись. Физическая шкала неизвестна, время номинальное,
симулятор подписан явно. Модули сохраняют собственные source pins. Новое правило
Stop из PR52 и 5000-мс политика удержания окна эмулятора не принимаются этим модулем
за окончательно согласованный аппаратный контракт.
