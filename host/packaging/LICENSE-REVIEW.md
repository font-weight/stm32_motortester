# Лицензии: обязательная проверка перед распространением

HOST-001 содержит только кандидат упаковки. Автоматическая копия license-файлов не является завершённым юридическим аудитом и не даёт разрешения на выпуск.

1. Проверить лицензию самого проекта и полномочия на распространение исходников/бинарников: окончательное решение владельца репозитория пока TBD.
2. Сохранить license/copyright/notice для CPython, PySide6, shiboken6, фактических Qt DLL/плагинов, pyqtgraph, NumPy и включённых в NumPy бинарных библиотек, colorama, pyserial, bootloader PyInstaller и остальных реально распространяемых компонентов. Общая лицензия NumPy не заменяет bundled third-party notices.
3. Проверить `licenses/inventory.json` и скопированные файлы. Пустой список `copied_notices` требует ручной проверки, а не означает отсутствие обязательств. Скрипт копирует обнаруженные уведомления установленных пакетов и `CPython-LICENSE.txt`; полнота DLL-зависимостей и Qt third-party компонентов проверяется отдельно.
4. Для LGPL-варианта PySide/Qt включить необходимые тексты и уведомления; обеспечить доступ к точным соответствующим исходникам библиотек/изменениям выбранным допустимым лицензией способом. Одна ссылка на главную страницу Qt не заменяет выполнение условий. Зафиксировать версию, источник и контрольные суммы такого комплекта перед релизом.
5. Проверить возможность замены/пересборки LGPL-библиотек и отсутствие запрещающих это условий распространения. onedir с отдельными DLL выбран для облегчения этой задачи; это не автоматическое доказательство соответствия. Не использовать компоненты с иными условиями незаметно.
6. Проверить исключение PyInstaller и уведомления bootloader; код упаковщика не передаёт автоматически свою лицензию приложению, но условия включённых зависимостей сохраняются.
7. Сохранить результат аудита рядом с точными source/ZIP SHA. До этого артефакт имеет статус candidate, а не принятого распространяемого релиза.

Первичные источники:

- [Qt for Python: лицензии](https://doc.qt.io/qtforpython-6/licenses.html)
- [Qt LGPL obligations](https://www.qt.io/development/open-source-lgpl-obligations)
- [PyInstaller license and exception](https://pyinstaller.org/en/stable/license.html)
- [CPython license](https://docs.python.org/3/license.html)
- [NumPy license](https://numpy.org/doc/stable/license.html)

`source.zip` от build-скрипта содержит исходники приложения `host/` из указанного Git commit. Он не содержит автоматически corresponding source всех сторонних библиотек и не закрывает пункт 4.

## Закреплённое уведомление pyserial 3.5

Свежая проверка 12.10.2026 подтвердила: официальный wheel
`pyserial-3.5-py2.py3-none-any.whl` (90 585 байт,
SHA-256 `c4451db6ba391ca6ca299fb3ec7bae67a5c55dde170964c7a14ceefec02f2cf0`)
не содержит отдельного полного license/notice-файла. Метка BSD в METADATA и
SPDX-комментарии исходников не заменяют полный текст уведомления.

В `licenses/pyserial-3.5-LICENSE.txt` сохранены без изменения 1885 байт из
[upstream v3.5/LICENSE.txt](https://raw.githubusercontent.com/pyserial/pyserial/v3.5/LICENSE.txt),
SHA-256 `f91cb9813de6a5b142b8f7f2dede630b5134160aedaeaf55f4d6a7e2593ca3f3`.
`collect_licenses.py` требует установленный pyserial ровно 3.5, проверяет этот
SHA-256 и копирует полный текст в пакет. При отсутствии pyserial, файла,
несовпадении версии или хеша сборка завершается ошибкой. Загрузок из сети при
сборе лицензий нет. Источник, версия, хеш уведомления и справочный хеш wheel
попадают в `licenses/inventory.json`; поле `manual_review_required` остаётся
`true`. Справочный хеш не является самостоятельной проверкой установленного
дистрибутива: wheel проверяется установщиком по lock-файлу.

Свежие сведения PyPI: [pyserial 3.5 JSON](https://pypi.org/pypi/pyserial/3.5/json).
Эта проверка полноты уведомления не означает юридического разрешения на релиз
и не закрывает остальные пункты аудита. Границы программной проверки и передача
Windows-сборки: [serial-packaging.md](../docs/serial-packaging.md).

## Закреплённые GNU-тексты Qt for Python 6.12.0

Восстановленный аудит [PR130, комментарий 6122558122](https://github.com/font-weight/stm32_motortester/pull/130#issuecomment-6122558122)
зафиксировал в закреплённых Windows wheels PySide6-Essentials/shiboken6 только
`LicenseRef-Qt-Commercial.txt`. Это условная ссылка на коммерческие условия,
а не полный GNU-текст и не доказательство коммерческой лицензии владельца.
Наличие этого файла также не означает, что wheels доступны только коммерчески:
их METADATA перечисляет LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only.
После последнего Windows diagnostic run11 нового готового пакета не получено;
исторический manifest run8 не считается текущим бинарным свидетельством.

Узкое исправление добавляет неизменённые тексты всех трёх перечисленных GNU
лицензий из `LICENSES/` upstream PySide tag `v6.12.0`, commit
`f50facb83fc3dc5f3240c854668c7a6dd93871b2`, в `licenses/qt-6.12.0/`.
Git blob и SHA-256 каждого текста пересчитаны по фактическим байтам:

| Файл | Байт | SHA-256 |
|---|---:|---|
| GPL-2.0-only.txt | 18092 | `8177f97513213526df2cf6184d8ff986c675afb514d4e68a404010521b880643` |
| GPL-3.0-only.txt | 35147 | `8ceb4b9ee5adedde47b31e975c1d90c73ad27b6b165a1dcd80c7c545eb65b903` |
| LGPL-3.0-only.txt | 7651 | `da7eabb7bafdf7d3ae5e9f223aa5bdc1eece45ac569dc21b3b037520b4464768` |

[Точное upstream-дерево текстов](https://github.com/pyside/pyside-setup/tree/f50facb83fc3dc5f3240c854668c7a6dd93871b2/LICENSES).
Отдельно проверены такие же Git blobs в Qtbase 6.12.0,
commit `025bdad181de241e81bf853c8a2d7bf3d19261a9`.
Теги в GitHub API не подписаны; проверка цифровой подписи не заявляется.

Коллектор требует ровно по одному установленному PySide6-Essentials и shiboken6
версии 6.12.0 с нормализованными именами. Отсутствие, дубликат, другая версия,
пропавший или изменённый GNU-текст прекращают сбор; успешный `inventory.json`
при ошибке не записывается. Уже существующий каталог результата не перезаписывается.
При поздней ошибке может остаться неполный каталог, который нельзя считать
готовым комплектом. Загрузка из сети и импорт Qt при сборе текстов не нужны.

В пакет копируется один общий набор трёх файлов `licenses/qt-6.12.0/`;
обе записи дистрибутивов ссылаются на него через `copied_notices` и
`vendored_notices`. Эти записи сохраняют upstream URL/commit/Git blob,
размер/SHA-256, версию и справочные имя/hash Windows wheel.
Поле `scope: upstream-license-text-only` означает происхождение **текста лицензии**,
а не наличие или соответствие полного исходного кода библиотеки.
Справочный wheel hash не проверяет установленный дистрибутив: фактическую
установку по hash-lock выполняет прежний рецепт. Найденные upstream notices,
включая коммерческую ссылку, сохранены; условия pyserial и CPython не ослаблены.

Тексты альтернатив не выбирают лицензию собственного приложения и не дают
разрешения на распространение. `manual_review_required` остаётся `true`.
Открыты полный состав copyright/third-party notices фактических Qt DLL/плагинов,
NumPy/CPython/OpenSSL/Mesa/Microsoft и данных графика, точные corresponding source
и доступ получателей к ним, работающая замена библиотек, полномочия/условия
лицензирования проекта и разрешение выпуска. Исходный `source.zip` по-прежнему
содержит только `host/`. Source/fake-backed тесты коллектора не заменяют
проверку следующего реального Windows-пакета, независимое ревью или пункты 1–7.

## Первоначальное дополнение компонентных уведомлений

Историческая стадия; повторное сопоставление 11 строк описано ниже.

Для app-базы PR158 `1930f75b976be17a3df51da079b6d8ba275e3f73` подготовлено
ограниченное offline-дополнение: `licenses/dependency-6.12.0/manifest.json`
и ровно 41 буквальный файл `notices/<SHA256>`, всего 163526 байт текстовых входов.
Архивы исходников, SDK и reference binaries в этот каталог не включены.
Коллектор также кладёт туда [руководство по исходникам и замене](../docs/dependency-sources.md).
Руководство содержит точные URL/размеры/хеши четырёх Qt/PySide source-архивов
(73622536 байт), а не заявление, что они уже переданы получателю вместе с ZIP.

Manifest сохраняет исходный proposal целиком: все 55 attribution-записей,
включая 11 без `LicenseFile`, их copyright и остальные исходные поля.
У `libjpeg` исходный attribution не задаёт `Copyright`; этот пробел не заполнен
выдуманным текстом. Все 11 записей явно остаются unresolved. Сохранены source
archive/member, metadata SHA, scope и `compiled_into_candidate: unverified`.
Source/header/data/build edges не объявляются доказательством компиляции каждого
компонента в каждом wheel. Общие ссылки двух Qt-family записей в inventory
обозначают совместный набор сведений. Идентичные буквальные тексты хранятся один
раз, а разные source/member associations сохраняются в исходных 55 записях.

Источник LLVM 3.6.2 дополнен новым свидетельством официального репозитория от
13.10.2026: неподписанный tag `llvmorg-3.6.2`, commit
`ee46064b83e7acd5a215ea5bb1c9708d75de6164`, точный текст 3281 байт/SHA-256
`e3bc36440fc927c62d5cc24efeefe225a14d4e34ffeb0c92e430625cce9ee444`.
Это новое подтверждение буквального текста, не восстановленная старая квитанция
и не доказательство полной Mesa/LLVM compiled-source или notice coverage.

SHA-256 и размер manifest/руководства закреплены вне этих файлов в collector;
manifest не хеширует сам себя. После проверки canonical JSON, schema/version,
уникальности путей и полного разрешённого набора файлов каждый буквальный вход
проверяется по размеру/SHA. Пропавший, изменённый, лишний или небезопасный файл,
дубликат, case alias, symlink/reparse/linked ancestor и выходная коллизия
прекращают сбор до успешной записи `inventory.json`. Неполный каталог после
ошибки не означает готовность. Обновление pinned manifest/руководства требует
нового review их содержимого и внешних хешей, а не автоматического перепиннинга.

Верхний формат `inventory.json` остаётся списком дистрибутивов. Новые записи
находятся только в прежних `copied_notices`/`vendored_notices`; build-manifest
и recipe/spec/lock не меняются. Прежние GNU/pyserial/CPython и discovered notices,
включая NumPy, не заменены; `manual_review_required: true` сохранён.

Это изменение закрывает только доставку конкретных закреплённых notice-входов
и source-guide при следующем успешном запуске коллектора. Оно не закрывает
11 unresolved records, точные QtSvg/imageformats/PySide build associations,
полноту исходников и доступ получателя, юридический выбор/распространение,
отдельную проверку Microsoft/OpenSSL/CPython или фактический состав будущего ZIP.
Изменённая native-библиотека, модифицированный PYZ-модуль и native-embedded
Shiboken support-код требуют Windows replacement/repack свидетельств.
Неизменённый успешный запуск не является такой проверкой. Однодневное хранение
артефакта само по себе не решает условия доступа к исходникам.


## Повторное сопоставление 11 строк: точные тексты и ключи metadata

На базе PR171 `60c3d262b5597794869b32e0aa27d6981b28e38b`, tree
`b276c2300a539876b0283ec3c515bd4ec4a5f398`, manifest schema 2 сохраняет
первоначальный `proposal` со всеми 55 записями и прежние 41 буквальный файл
без изменения. Отдельный `reconciliation` привязан к sealed input ledger
SHA-256 `5e73b2607fc1c67d3d9712237c1de114785e433be455f9bde87ae622e27906d7`.
Он содержит исходные строки/источники аудита, точные диапазоны выдержек,
сопоставления новых и повторно используемых текстов и оставшийся пробел.

Добавлено ровно 10 буквальных тел, 13079 байт; теперь всего 51 вход,
176605 байт. Полные source-файлы, архивы и SDK не добавлялись. Из ранних 11
строк три используют уже имеющиеся CC0/Apache-2.0 тексты, для семи сохранены
новые полные тексты или точные header-блоки, а Tika сопоставлена частично.
Unicode UCD и CLDR используют один общий новый текст. MD4/MD5 public-domain
заявления не объявляются новыми обязательствами или новым разрешением CC0.

Ранний признак «нет LicenseFile» был наблюдением о singular metadata key,
а не доказанным нарушением лицензии. Коллектор теперь различает `LicenseFile`,
`LicenseFiles` и `CopyrightFile`, проверяет их типы и пути относительно
соответствующего архива и связывает все объявленные файлы с буквальными телами.
Для libjpeg исходные plural/copyright keys дают три файла общей длиной 8498 байт;
метаданные upstream не переписываются. Явное IJG product acknowledgement
добавлено в поставляемое [руководство](../docs/dependency-sources.md).

Для Tika сохранены только применимые ASF/PRONOM фрагменты NOTICE точного commit
`c29724782854bb5a319f4a1940d0828a58ace3f9`, с хешем всего источника и диапазонами.
Чтение официального OGL3 вернуло 403; полный текст и независимая проверка
условий/атрибуции **остаются unresolved**. Это не повод автоматически объявить
закрытыми все 11 строк. Техническое сопоставление прочих текстов не закрывает
фактический compiled scope, source/build/replacement, получательский доступ,
юридическое решение и состав окончательного Windows ZIP.

Все прежние fail-closed гарантии сохраняются: canonical/schema/type/hash/size,
точный набор файлов, дубликаты/case aliases, ссылки/reparse/ancestors,
выходные коллизии и отсутствие успешного inventory при ошибке. Новые source
ranges проверяются как целые полуоткрытые границы внутри закреплённого источника;
каждое выбранное тело имеет точную длину и SHA-256. Коллектор не исполняет эти
заголовки и не делает сетевых запросов. Inventory API и `manual_review_required`
не меняются; нового build-manifest поля нет. Новый collector Git blob должен
быть отдельно закреплён для следующего проверяемого Windows-прогона.
