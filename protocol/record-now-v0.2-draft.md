# «Запись сейчас»: предложение wire 0.2

Статус: DRAFT для issue [#134](https://github.com/font-weight/stm32_motortester/issues/134).
Автор — Dot A, 12.10.2026. Это проверяемое предложение миграции, а не принятый
контракт или реализованная команда. Нужны независимые Critic-A и Critic-B на
точный совместимый набор firmware/host/emulator. `host/**` изменяет Dot B.

База для перечисленных ниже неизменных правил — [wire-v0.1.md](wire-v0.1.md)
из `192fbb2ef9369bb1c32e11f97263094fca52763f`, SHA-256
`c283560183594e17afc0a41d515a7090ab35726e898cabf8358582441df57dc4`.
Ссылка относится ко всему документу, включая WAIT_RELEASE, приоритет Stop
и ошибку ADC при исправном транспорте. Его прежний draft-статус сохраняется.
Исполняемые исходники и байты wire 0.1 этой поставкой не меняются.

## 1. Цель и граница

Пользователь оставил две функции:

1. «Запись сейчас»: запросить новое конечное окно без ожидания пересечения
   порога; начало — первый допустимый новый отсчёт после принятия запуска.
2. «Один разряд»: вооружить аналоговый Single, сохранить начало, горение
   и затухание разряда, затем остановиться. Полнота физического события требует
   отдельно проверенных порога, предыстории, длительности и полосы тракта.

Внешний запуск и управление стендом исключены. Внутренний TIM3 по-прежнему
задаёт выборки АЦП. Профиль 1 остаётся 2048 точек / номинальные 50 kS/s:
40,96 мс периодов, 40,94 мс между крайними точками. Ни эта длительность,
ни CRC полного массива не доказывают захват разряда целиком. Масштабирование
графика по X/Y не меняет записанные отсчёты, Fs, длину окна или усиление тракта.

## 2. Явная миграция версии

Предлагается точная envelope-версия **major=0, minor=2** во всех новых кадрах,
включая HELLO, и такое же значение внутри HELLO_ACK. COBS, CRC-32/ISO-HDLC,
24-байтовый заголовок, little-endian, размеры кадров и reserved не меняются.
Принимается только точное совпадение версии выбранного режима соединения.
Смешивать 0.1 и 0.2 в сеансе нельзя; minor не означает обратную совместимость.

Минимальный новый firmware поддерживает только 0.2. Новый host должен явно
различать режимы соединения; автоматический fallback/retry после молчания
не предлагается. Необязательный отдельный legacy-режим host является работой B
и не считается реализованным. В нём «Запись сейчас» недоступна.

| Host / firmware | Требуемое поведение |
|---|---|
| 0.1 / 0.1 | Прежний контракт, без type 8 и kind 3 |
| 0.1 / 0.2 | 0.1 HELLO отвергается на версии, без изменения состояния/ACK; захват не начинается |
| 0.2 / 0.1 | Аналогично для 0.2 HELLO; type 8 не посылается под видом 0.1 |
| 0.2 / 0.2 | HELLO → проверка HELLO_ACK → CAPS → CONFIG → ARM либо RECORD_NOW |

Timeout без ответа означает неизвестную причину, а не установленную
несовместимость. Только CRC-valid кадр неподдерживаемой версии позволяет
сообщить о несовместимости. Отказ byte codec не расходует sequence/request,
не меняет сеанс и не создаёт ERROR по непроверенному request_id.
Следующий валидный кадр подчиняется прежнему контролю непрерывности sequence.
Закрытие/открытие транспорта и свежий nonce при восстановлении обязательны.
Никакого автоматического переключения версии во время активной записи.

## 3. Возможности и CONFIG

Для этого нового MVP-профиля HELLO_ACK объявляет capability_bits=113 (0x71):
analog=bit0, Single=bit4, pretrigger=bit5, новое **record_now=bit6**.
Auto/Normal/external не объявляются. Все остальные биты нулевые.
Новая возможность объявляется только после её действительной реализации,
не из-за наличия этого документа или отдельного core API.

CAPS сохраняет прежнюю длину 30 байт и поля profile 1:
timer_clock_hz=72000000, PSC=71, ARR=19, ADC=12000000,
adc_sample_cycles_x2=143, window_samples=2048;
mode_bits=4, source_bits=1, edge_bits=3,
pre_count=3 и pre=[0,512,1024]. Полное декартово произведение этих масок
относится к **обычному ARM**. Более узкое ограничение RECORD_NOW описано отдельно.

CONFIG имеет прежние 16 байт. Разрешены только mode=2 (Single), source=0,
edge=0/1, level_code=1..4094, pretrigger=0/512/1024, auto_timeout_ms=0.
Auto/Normal/external дают INVALID_CONFIG; значения перечислений не перенумеровываются.
Недопустимые reserved/длина дают INVALID_PAYLOAD. CONFIG только в STOPPED без
удерживаемого окна и TX drain; успешный CONFIG получает новый ненулевой config_id.
Ошибочный CONFIG не подменяет прежний. HELLO_ACK/CAPS должны совпадать;
противоречие, неизвестные биты или неподдержанный профиль запрещают запуск.

## 4. Новая команда и ответ

**Type 8, RECORD_NOW, только host → device, payload ровно 4 байта:**
`config_id:u32`. Это обычный запрос действующего сеанса с очередным sequence
и новым возрастающим request_id. Нулевой/чужой config_id недопустим.

Обработка после общих byte/session/order проверок:

1. Активный TX Stop-барьер имеет прежний приоритет recovery без ERROR,
   включая malformed/unknown обычный запрос. HELLO и точный duplicate —
   прежние специальные случаи.
2. Неверная длина type 8: ERROR/INVALID_PAYLOAD (6).
3. Не STOPPED/idle, удерживаемое окно или TX drain: ERROR/BUSY (2).
4. Нет принятого CONFIG, config_id=0 либо не равен текущему:
   ERROR/STALE_CONFIG (3).
5. Текущий CONFIG не Single/source0/pre0/timeout0:
   ERROR/INVALID_CONFIG (1), без изменения CONFIG и без запуска.
6. Только после этого проверяются готовность профиля, постановка ACK,
   подготовка нового окна и запуск оборудования. Неуспешная аппаратная
   операция или невозможность обязательного ответа ведёт к прежнему recovery,
   а не к притворному успешному захвату.

Ответ использует существующий **ARM_ACK type132**, payload
`generation:u32, config_id:u32`; generation равна request_id принятого type8.
Header request повторяет запрос. Нового ACK-типа нет. Host различает смысл
по ожидаемому запросу; старый ARM_ACK после Stop не является новым запуском.
Успешная постановка ACK не доказывает физическое начало выборок или их получение.

Обычный ARM type4 сохраняет аналоговый Single и предысторию. Он не становится
«Запись сейчас», Auto timeout не подменяет непосредственный запуск.
Host хранит операцию начала (type4 либо type8) вместе с generation, сначала
как pending запрос, затем как подтверждённое поколение. Одного Single/pre0
CONFIG или capability недостаточно: одинаковая конфигурация допустима для
обеих операций. В поколении type4 допустим только kind0, в поколении type8 —
только kind3; несовпадение является protocol error с сохранением уже проверенных
фрагментов как неполных и восстановлением. ARM_ACK не содержит этого
дискриминатора, поэтому сопоставление с ожидаемым запросом обязательно.
В режиме RECORD_NOW edge/level остаются настройками CONFIG, но не участвуют
в выборе первого отсчёта. Таймеры команд/передачи и fault detection сохраняются.
Если новых отсчётов нет, нельзя создавать полное, пустое или заполненное нулями
окно: реальная ошибка драйвера/дедлайна обрабатывается прежним fault/recovery путём.

## 5. Метаданные и завершение

Для software-immediate окна WINDOW_BEGIN сохраняет 40 байт и имеет:

- trigger_kind=3 (software_immediate), source=0, channel=0;
- pretrigger_samples=0, trigger_index=0xffff, external_edge_id=0;
- sample_count=2048, profile=1, config_id текущей конфигурации;
- generation из принятого type8, window_id выделяется при первом допустимом
  новом отсчёте, не по нажатию кнопки и не при постановке ACK;
- quality bit0 (auto_timeout)=0 и bit2 (external timing)=0;
  bit1 допустим только по реально сохранённым кодам 0/4095;
- edge/level совпадают с CONFIG, но не описывают реальное событие запуска.

0xffff означает отсутствие индекса аналогового события, не пропуск нулевой
точки массива. Координаты software-immediate записи для просмотра считаются
от первого отсчёта (t[0]=0), без вычитания sentinel как индекса.
Точную привязку к времени нажатия кнопки/искре эта запись не предоставляет.
Краткое состояние WAITING перед первым допустимым отсчётом означает ожидание
данных АЦП, а не аналогового порога; без выделенного окна window_id ещё 0
(либо прежний last_window_id в последующем поколении). Затем идут CAPTURING,
TRANSFERRING и WAIT_RELEASE с прежними отдельными STATUS и порядком очередей.
Для обычного ARM остаётся kind0 с index=pretrigger_samples и прежней семантикой.
kind1/2 или внешние метаданные не соответствуют этому Single-only профилю.

Ровно 2048 последовательных новых кодов, затем заморозка; прежние DATA,
CRC массива, END/ABORT, удержание буфера, WAIT_RELEASE=5000 мс от завершения
передачи END, tombstone и поздний RELEASE не меняются. Single после RELEASE
остаётся STOPPED; следующее окно требует нового явного ARM/RECORD_NOW.
Окно с END — полное по транспорту, а не автоматически полный физический разряд.

## 6. Stop, восстановление, файл

Все ограничения для неотвеченного ARM распространяются на RECORD_NOW:
один обычный запрос плюс один дополнительный STOP, никаких новых обычных
запросов, пока STOP ожидает ответ. При ожидаемом ACK type8 используется
STOP(generation=request_id RECORD_NOW). Если type8 был отвергнут, приходит
STALE_GENERATION; ERROR на STOP закрывает ожидание с обязательным recovery,
но не подтверждает остановку. Автоматического повтора type8 после timeout нет.

Прежний порядок обязательных ответов, единственный terminal outcome,
необратимость END после первого принятого транспортом байта, дренирование
частичного кадра, отсутствие данных старого поколения после STOP_ACK,
приоритет неподтверждённого аппаратного Stop и свежий HELLO сохраняются.
После HELLO очищаются CONFIG и pending immediate request; старый nonce/duplicate
не запускает второе окно. Во время WAIT_RELEASE или ERROR новый запуск запрещён.

Wire-версия не является версией файла. Существующие файлы MTCAP v1 должны
по-прежнему читаться без изменения исходных данных/смысла. Нельзя молча записать
kind3 в прежнюю закрытую enum, назвать его analog/auto или считать complete
признаком полноты разряда. B должен предложить явное версионирование/представление
нового типа записи и отрицательные тесты старого reader; это блокер сквозной
реализации и не решено этой спецификацией. X/Y zoom не меняет сохранённые коды.

## 7. Векторы и реальные границы проверок

[vectors-record-now-v0.2-draft.json](vectors-record-now-v0.2-draft.json)
содержит явно закодированный пример полного обмена с 2048 синтетическими
кодами `code[i]=i`, а также legacy/ошибочные кадры. Это не измеренная искра.
Nonce, firmware_build и прочие идентификаторы — только тестовые значения.
Нативная проверка использует **неизменный** codec/parser 0.1:
CRC-valid 0.2 кадры должны дать VERSION и не менять выходной объект;
type8 под 0.1 должен декодироваться, но остаться UNKNOWN_TYPE у command parser.
Это доказывает ограниченную legacy-границу, не работу нового 0.2 устройства.

Команда: `python3 tests/record-now-contract/check_vectors.py`.
Скрипт проверяет фиксированные reference bytes/CRC/COBS и запускает строгий
C11 и UBSan legacy probe. Зависимости — Python3, C11 compiler; без платы,
нового firmware codec, USB и приложения. Неуспешный subprocess — ошибка проверки.

До принятия и production-интеграции необходимы:

- согласование B версии соединения, CAPS, pending-command и файла;
- независимые положительные/отрицательные проверки **реального** codec/parser
  0.2: длины type8, отсутствие/чужой CONFIG, busy/prehistory/unsupported config,
  unknown direction/type, inconsistent metadata, malformed/mixed versions;
- полный Stop/HELLO/fault/release/duplicate/counter-boundary прогон нового пути,
  включая Stop до первого отсчёта и до/после commitment END;
- реальные callbacks и ADC driver integration, fresh ARM image/resource/stack
  proof без переноса старых hashes/границ; затем A/B сквозные синтетические окна;
- физические LV/HV проверки применимого уровня отдельно от программных.

Неизвестный counterpart или отсутствующее доказательство сохраняют DRAFT /
BLOCKED_EVIDENCE. Этот пакет не разрешает объявлять bit6 в работающем wire0.1.
