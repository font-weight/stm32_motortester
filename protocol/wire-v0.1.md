## Область первой итерации

Реализовано преобразование одного сообщения в байты и обратно без динамического выделения памяти. USB, накопитель потока, управление сеансом, захват и команды пока **не реализованы**. C codec не компилировался: запуск выбранного executor завершился timeout. Аппаратных проверок нет.

Транспорт-кандидат: CDC ACM поверх native USB FS, отдельно от ST-Link. Библиотека и VID/PID ещё не выбраны окончательно. Нельзя копировать чужой VID/PID, startup или linker script без проверки условий. Windows-приложение и файловый формат принадлежат Dot B.

## Framing

Кадр: COBS(decoded_message), затем один байт 0x00. Пустые разделители игнорируются.
Граница USB packet/read не является границей кадра. Любой кадр может быть разбит между чтениями; одно чтение может содержать несколько кадров.

Обычный COBS: code 1..254 означает code−1 ненулевых байтов и восстановленный ноль, кроме конца кадра. Code 255 означает 254 байта без восстановленного нуля.
При переполнении накопитель отбрасывает текущие данные и ждёт следующего разделителя. Ошибка CRC, framing, длины или версии не применяется к состоянию прибора; следующий кадр разбирается независимо.

Все многобайтные числа little-endian. Проводной формат не является C struct ABI.

| Смещение | Размер, байт | Поле |
|---|---:|---|
| 0 | 1 | major = 0 |
| 1 | 1 | minor = 1 |
| 2 | 1 | message_type |
| 3 | 1 | reserved = 0 |
| 4 | 2 | payload_length, 0..512 |
| 6 | 2 | reserved = 0 |
| 8 | 8 | connection_session_id |
| 16 | 4 | sequence |
| 20 | 4 | request_id |
| 24 | payload_length | payload |
| 24 + payload_length | 4 | CRC |

CRC-32/ISO-HDLC: poly 0x04C11DB7, reflected polynomial 0xEDB88320, init 0xffffffff, refin/refout = true, xorout 0xffffffff. Check для ASCII «123456789» = 0xcbf43926.
CRC покрывает весь 24-байтовый заголовок и payload, исключая само поле CRC, COBS и разделитель. CRC передаётся little-endian. Это обнаружение случайных ошибок, не аутентификация.

Decoded length: 28..540 байт. Верхняя граница COBS: 543 байта; вместе с разделителем — 544.
Encode требует выходной буфер 544 байта независимо от фактического размера. Decode принимает ровно один кадр без разделителя. Ошибка не изменяет выходное сообщение. Области памяти должны быть действительными и неперекрывающимися согласно заголовку API.

## Проект политики потока и сеанса

Эти правила требуют review и ещё не реализованы:

- Межбайтовый timeout — 1000 ms; общий timeout кадра — 3000 ms с первого ненулевого байта. Monotonic clock, срабатывание при elapsed >= timeout. После timeout отбрасывать байты до нуля; не применять частичный кадр.
- Новый USB connection сбрасывает parser, незавершённые команды и окно. До handshake захват остановлен.
- HELLO предлагает session = 0, request = 1, sequence = 1 и новый ненулевой 64-битный nonce от ПК. Устройство использует nonce как connection_session_id. Это корреляция, не средство защиты.
- После HELLO кадры обеих сторон несут новый session. Каждая сторона нумерует sequence отдельно. Повтор или старый sequence не должен повторно выполнять команду. Переполнение идентификатора требует нового handshake.
- Числовая таблица команд, payloads, HELLO response, повторный HELLO, cache/ACK/retry пока **TBD**. Без них обе стороны нельзя объявлять совместимыми.
- Timeout ответа на команду, timeout передачи окна и Auto timeout различаются. Пределы первых двух будут зафиксированы следующим diff.
- Неподдерживаемый тип отклоняется dispatch-слоем. Byte codec намеренно не интерпретирует типы.

## Семантика последующего контракта

Auto ждёт событие после подготовки предыстории либо выдаёт принудительное окно с auto_timeout=true и отсутствующим индексом реального события; затем повторяет цикл по готовности.
Normal без события остаётся в ожидании до Stop или ошибки. Предыдущий график помечается как предыдущая запись.
Single: одно событие, одно окно, затем остановка.

Stop идемпотентен. ACK должен означать остановку новых захватов, фиксацию отмены активного окна и удаление его непереданных данных из очереди. Поздние блоки отменённого окна не создают успех. Окно, завершённое до обработки Stop, не переименовывается в отменённое. Точный порядок terminal event и ACK ещё требует согласования.

Для окна обязательны session/window/offset/count, ожидаемое число отсчётов и итоговый CRC исходного массива. Идентичный повтор блока не удваивает массив. Конфликт повтора не перезаписывает данные. Пропуски не заменяются нулями.

## Ресурсы и следующая фиксация

Используются только 64 KiB Flash и 20 KiB SRAM. LV-001: 2048 uint16 = 4096 байт, проектные 50 kS/s дают 40,96 ms. Сырые данные соответствуют 100 000 байт/с, но это не гарантия полезной скорости USB.

RAM включает окно, DMA staging, packet buffers, globals и стек. Byte codec использует локальный массив 540 байт; его надо учесть в стеке вместе с цепочкой вызовов. Не вызывать codec из IRQ.

Предварительно резервируются PA0 для ADC1_IN0, PA11/PA12 для USB, PA13/PA14 для SWD. Вывод внешнего запуска — TBD: PB12 EXTI не равнозначен аппаратному input capture. Распиновка конкретной платы не проверена.

Дальнейшие обязательные результаты: тактирование/ADC, карта выводов, допустимые Fs/window/pretrigger, все payloads и состояния, независимые векторы и реальные compile/tests, два проходных заключения критиков. Неполнота этого draft не уменьшает требования MVP.
