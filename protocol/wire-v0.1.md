# Wire v0.1 — DRAFT, не принят

Автор: Dot A. База: `3fe1a2d8c53f77e0510a3da9ddd125f68cb872fa`. Задача #3, координация #2.
Требуются независимые Critic-A и Critic-B с доказательствами на точный SHA. Это предложение framing и исходник codec, а не утверждённый общий контракт.

## Область первой итерации

Реализовано преобразование одного сообщения в байты и обратно без динамического выделения памяти. В этой ветке добавлен черновой накопитель потока (см. [stream-parser.md](../docs/stream-parser.md)); USB, управление сеансом, захват и команды пока **не реализованы**. Новый накопитель не компилировался и не запускался. C codec не компилировался: запуск выбранного executor завершился timeout. Аппаратных проверок нет.

Транспорт-кандидат: CDC ACM поверх native USB FS, отдельно от ST-Link. Библиотека и VID/PID ещё не выбраны окончательно. Нельзя копировать чужой VID/PID, startup или linker script без проверки условий. Windows-приложение и файловый формат принадлежат Dot B.

## Framing

Кадр: COBS(decoded_message), затем один байт 0x00. Пустые разделители игнорируются.
Граница USB packet/read не является границей кадра. Любой кадр может быть разбит между чтениями; одно чтение может содержать несколько кадров.

Обычный COBS: code 1..254 означает code−1 ненулевых байтов и восстановленный ноль, кроме конца кадра. Code 255 означает 254 байта без восстановленного нуля.
При переполнении накопитель отбрасывает текущие данные и ждёт следующего разделителя. Ошибка CRC, framing, длины или версии не применяется к состоянию прибора; следующий кадр разбирается независимо.

Все многобайтные числа little-endian. Проводной формат не является C struct ABI.

| Смещение | Размер, байт | Поле |
|---|---:|---|
| 0 | 1 | major = 0 |
| 1 | 1 | minor = 1 |
| 2 | 1 | message_type |
| 3 | 1 | reserved = 0 |
| 4 | 2 | payload_length, 0..512 |
| 6 | 2 | reserved = 0 |
| 8 | 8 | connection_session_id |
| 16 | 4 | sequence |
| 20 | 4 | request_id |
| 24 | payload_length | payload |
| 24 + payload_length | 4 | CRC |

CRC-32/ISO-HDLC: poly 0x04C11DB7, reflected polynomial 0xEDB88320, init 0xffffffff, refin/refout = true, xorout 0xffffffff. Check для ASCII «123456789» = 0xcbf43926.
CRC покрывает весь 24-байтовый заголовок и payload, исключая само поле CRC, COBS и разделитель. CRC передаётся little-endian. Это обнаружение случайных ошибок, не аутентификация.

Decoded length: 28..540 байт. Верхняя граница COBS: 543 байта; вместе с разделителем — 544.
Encode требует выходной буфер 544 байта независимо от фактического размера. Decode принимает ровно один кадр без разделителя. Ошибка не изменяет выходное сообщение. Области памяти должны быть действительными и неперекрывающимися согласно заголовку API.

## Поток

Черновой parser: firmware/protocol/mt_stream.c; авторские тесты подготовлены, но не выполнены. Межбайтовый timeout 1000 ms, общий 3000 ms с первого ненулевого байта; monotonic elapsed >= threshold. После timeout/overflow — discard-until-zero. Пустые разделители игнорируются. Единственные правила сеанса/Stop приведены ниже.

## Ресурсы и следующая фиксация

Используются только 64 KiB Flash и 20 KiB SRAM. LV-001: 2048 uint16 = 4096 байт, проектные 50 kS/s дают 40,96 ms. Сырые данные соответствуют 100 000 байт/с, но это не гарантия полезной скорости USB.

RAM включает окно, DMA staging, packet buffers, globals и стек. Byte codec использует локальный массив 540 байт; его надо учесть в стеке вместе с цепочкой вызовов. Не вызывать codec из IRQ.

Предварительно резервируются PA0 для ADC1_IN0, PA11/PA12 для USB, PA13/PA14 для SWD. Вывод внешнего запуска — TBD: PB12 EXTI не равнозначен аппаратному input capture. Распиновка конкретной платы не проверена.

Дальнейшие обязательные результаты: тактирование/ADC, карта выводов, допустимые Fs/window/pretrigger, реализация payloads и состояний, независимые векторы и реальные compile/tests, два проходных заключения критиков. Неполнота этого draft не уменьшает требования MVP.

## Полный кандидат сообщений для обсуждения A/B

Этот раздел дополняет draft, но не отменяет его непринятый статус. Числа ниже — ограничения проекта, не измеренная производительность. Контракт пока не принят; USB VID/PID, библиотека и физическая карта остаются отдельными открытыми решениями.

### Сеанс и порядок

Порядок: framing/длина/CRC/точная версия/reserved заголовка → направление типа → специальный HELLO → session → sequence → request_id → payload/state. Отказ byte codec молча отбрасывает кадр с локальным счётчиком; ERROR по недоступному request_id не формируется. Полученный CRC-valid кадр неподдерживаемой версии означает несовместимость. Отсутствие ответа означает неизвестную причину, а не доказанную несовместимость.

HELLO type1: payload nonce:u64 !=0; header session0, sequence1, request1. Он обрабатывается до обычного контроля порядка и допустим в любом состоянии. Новый относительно текущего nonce прерывает захват и не начатые TX frames, сбрасывает конфигурацию/счётчики. Уже начатый кадр старого сеанса допередаётся перед новым ACK (при физическом USB reset может оборваться). ПК игнорирует кадры старого nonce. HELLO_ACK type129 использует session=nonce, sequence1, request1; последующие sequence обеих сторон начинаются с2.

Устройство хранит только текущий nonce, не историю после сбросов. ПК обязан создавать свежий случайный 64-bit nonce при каждой попытке handshake, включая восстановление после timeout. Идентичный HELLO с текущим nonce игнорируется без reset и нового ACK. Некорректный HELLO не меняет сеанс. Nonce — корреляция, не секрет и не абсолютная гарантия уникальности. Экспериментальный session_id в файле — отдельное поле.

Host request_id строго возрастает и имеет минимум 2; пропуски допустимы. Sequence, в отличие от request_id, обязан быть непрерывным с 2. Ответ повторяет request_id, события имеют0. TX sequence окончательно выделяется атомарно при первом положительном принятии байтов кадра USB-транспортом. До этого сериализация использует предварительный номер без изменения счётчика; если запись приняла 0 байт, подготовленный кадр можно удалить или пересобрать с тем же следующим номером. Один владелец TX сериализует кадры по очереди; он не начинает другой кадр до завершения уже начатого. Удаление не начатых данных не создаёт gaps. Ошибка транспорта с неизвестным числом принятых байтов требует восстановления, а не повторной выдачи номера. Неверный session отбрасывается без изменения текущего сеанса. Идентичный повтор непосредственно предыдущего полного кадра игнорируется; хранится полный decoded образ для сравнения. Тот же sequence с другими байтами, gap, более старый sequence или неверный новый request_id требуют восстановления. Идентификаторы не оборачиваются; UINT32_MAX не используется для sequence/request_id, перед ним нужен новый handshake. Последний допустимый UINT32_MAX−1 может быть принят и затем распознан как точный повтор без нового исполнения.

Восстановление ПК: сохранить проверенные фрагменты как неполные, закрыть/открыть транспорт, очистить очереди, новый HELLO. Устройство отключает sampling, сбрасывает не начатый TX и ждёт HELLO. Потеря USB configuration делает то же. CRC failure не применяется, следующий sequence gap обеспечивает fail-closed восстановление.

Автоматического retry ARM/CONFIG нет. Допускается один обычный неотвеченный запрос и один дополнительный STOP. Второй STOP с новым request_id разрешён после STOP_ACK первого. Любой валидный ERROR, отвечающий на ожидаемый STOP, также завершает ожидание этого запроса, но не подтверждает остановку: ПК немедленно переходит к восстановлению с новым HELLO, не ждёт тайм-аута и не начинает новый ARM/STOP в старом сеансе. При тайм-ауте тоже применяется восстановление, а не накопление повторных STOP. Команды исполняются по приходу короткими атомарными обработчиками: STOP не обгоняет ещё не обработанный CONFIG/ARM, но прерывает длительное ожидание/захват. Ответ предыдущему запросу обязательно предшествует STOP_ACK и не удаляется вместе с данными окна. ПК продолжает разбор прежнего ответа, но не начинает новый ARM/CONFIG до STOP_ACK и не считает старый ARM_ACK новым пуском.

STOP при ожидаемом ARM_ACK использует generation=request_id того ARM. Если ARM отвергнут, STOP получает ERROR/STALE_GENERATION; ПК учитывает уже полученный отказ ARM, закрывает ожидание STOP и немедленно восстанавливает сеанс. STOP_ACK для этого отвергнутого запроса не ожидается; старое поколение не считается остановленным. До первого успешного ARM generation=0 и STOP(0) безопасен; после первого ARM ноль не является wildcard. Повторный STOP — новый request_id с той же generation, не повтор байтов старого запроса.

### Типы и точные payloads

Поля записаны в порядке байтов; u8/u16/u32/u64 — беззнаковые little-endian. Все длины должны совпадать точно, не только быть меньше максимума. Reserved заголовка отбрасывается byte codec без ERROR; reserved payload даёт ERROR/INVALID_PAYLOAD после успешного decode. Типы 1..7 идут только от ПК; объявленные типы 129..135, 144..147 и 255 — только от устройства. Остальные значения, включая 136..143, пока неизвестные типы, а не объявленные ответы. Известный тип неправильного направления требует восстановления без исполнения. Неизвестный тип от ПК после проверок session/sequence получает ERROR/UNKNOWN_TYPE; неизвестный от устройства — protocol error на ПК.

STATUS с request_id=0 является событием, с request_id GET_STATUS — ответом. Переходы состояния отправляются отдельным STATUS. Ошибка синтаксиса без достоверного header/CRC не получает ERROR с выдуманным request_id. Unsupported version не входит в текущий сеанс; ПК показывает несовместимость и не вооружает устройство.

CONFIG mode: 0 Auto, 1 Normal, 2 Single; source: 0 аналоговый канал, 1 внешний; edge: 0 rising, 1 falling. level_code 1..4094; поле сохраняется и при внешнем источнике, но не применяется к нему. Для Auto timeout допускается 100..60000 ms; для остальных режимов требуется 0. Pretrigger принимает только значения из CAPS. Фактический timeout начинает отсчёт после подготовки предыстории. CONFIG только в STOPPED без удерживаемого окна и без TX drain; при ошибке старые настройки неизменны.

config_id увеличивается устройством при успешном CONFIG с 1. ARM без принятого CONFIG или с чужим config_id отвергается. ARM только в STOPPED без удерживаемого окна/TX drain, иначе BUSY. Generation равна request_id успешного ARM и не меняется при автоматическом повторении окон. Window_id возрастает с 1 на каждое начало окна в сеансе. Числовые capabilities: bit0 analog trigger, bit1 external trigger, bit2 Auto, bit3 Normal, bit4 Single, bit5 pretrigger. Не реализованная возможность имеет 0; ACK не должен обещать будущую функцию. CAPS имеет фиксированную длину 30 байт. Mode bits 0/1/2 = Auto/Normal/Single, source bits 0/1 = analog/external, edge bits 0/1 = rising/falling; остальные биты0. Capability bits 2/3/4 повторяют mode bits, bits 0/1 повторяют source bits. При bit5=0: pre_count=1, pre0/pre1/pre2=0, только нулевая предыстория. При bit5=1: pre_count=3, pre0=0, pre1=512, pre2=1024. Поддерживается полное декартово произведение объявленных mode/source/edge/pre для profile1; иначе такая маска запрещена. Противоречие HELLO_ACK/CAPS — protocol error, ARM запрещён. Это требования к будущей реализации, текущий codec не объявляет capabilities.

### Окно

WINDOW_BEGIN payload (40 байт):
generation:u32; window_id:u32; config_id:u32;
profile:u16; sample_count:u16; pretrigger_samples:u16; trigger_index:u16;
trigger_kind:u8; source:u8; edge:u8; channel:u8;
level_code:u16; quality_flags:u16;
timer_clock_hz:u32; timer_psc:u16; timer_arr:u16; external_edge_id:u32.

trigger_kind: 0 analog, 1 external, 2 auto_timeout. Для auto_timeout trigger_index=0xffff и external_edge_id=0. Для analog index — индекс первого отсчёта перехода; внешний индекс — привязка к сетке выборок выбранным механизмом с неопределённостью TBD до аппаратной проверки. Без реального события индекс не выдумывается. Для реального события trigger_index=pretrigger_samples; если предыстория не готова, событие не запускает окно. Channel=0, один канал. Коды только 0..4095, остальные отклоняются как нарушение данных.

Window sample_count всегда 2048 для profile1. WINDOW_DATA содержит 1..250 отсчётов (12+2×250=512 байт). Offset/count не выходят за окно. Блоки следуют без пропусков по offset. Повтор с новым sequence и теми же session/generation/window/offset/count и кодами может быть проигнорирован; конфликт или перекрытие означает incomplete/error, не перезапись. Изменение идентификаторов посреди окна отвергается. CRC окна считается по исходным 4096 байтам little-endian кодов в порядке offset; metadata защищена CRC отдельных кадров.

Успешное окно публикуется только после полного массива, согласованного WINDOW_END и совпавшего CRC. Проверенные фрагменты неполного окна могут сохраняться отдельно с явной маской пропусков и причиной; они не дополняются нулями и не становятся полным измерением. Файловую сериализацию выбирает B.

Quality flags: bit0 auto_timeout; bit1 ADC rail code observed (0 либо4095, не доказательство отсутствия/наличия аналоговой перегрузки); bit2 external timing unverified; остальные0. Ошибка DMA/дедлайна не выдаёт полное WINDOW_END: окно отменяется с reason. Время между окнами включает подготовку, захват, передачу и подтверждение; непрерывность не обещается.

После WINDOW_END состояние WAIT_RELEASE, буфер удерживается до RELEASE_WINDOW с совпавшими id/CRC либо Stop/HELLO. CONFIG/ARM в WAIT_RELEASE дают BUSY. RELEASE_ACK разрешает Auto/Normal новую подготовку; Single переходит STOPPED. Сохраняется tombstone последнего завершённого окна (generation/window/CRC): поздний или повторный RELEASE с новым request_id получает RELEASE_ACK без второго вооружения, включая после Stop. Следующее завершённое окно заменяет tombstone; более старый RELEASE получает BAD_WINDOW_RELEASE. Это правило для сознательного позднего запроса, не разрешение автоматического retry после неопределённого результата. ПК отправляет RELEASE только после проверенной приёмки массива, не ждёт записи файла на диск. Срок ожидания RELEASE — 5000 ms; истечение отменяет продолжение и переводит устройство в ERROR. ПК при отсутствии прогресса передачи 3000 ms прерывает окно; ожидание Normal/Single само по себе не является таким timeout.

### Stop и отказы

Состояния: 0 STOPPED, 1 PREPARING, 2 WAITING, 3 CAPTURING, 4 TRANSFERRING, 5 ERROR, 6 WAIT_RELEASE. До ARM generation=0 и window_id=0. После Stop сохраняется последняя generation. Last_window_id — последний выделенный id либо0, если окна не было.

STOP чужой generation получает STALE_GENERATION и не останавливает новый захват. Для текущей/последней остановленной generation повтор безопасен. Stop отключает timer/DMA, запрещает новые окна. Единственная точка необратимости WINDOW_END — принятие первого его байта USB TX FIFO. Если существует выделенное нетерминальное окно текущей generation, до этой точки отложенный END удаляется без выделения sequence, создаётся ровно один WINDOW_ABORT, затем STOP_ACK. Если END уже начат, он допередаётся целиком, ABORT не создаётся, затем STOP_ACK. То же для полностью переданного END. Если активного нетерминального окна нет (начальный STOPPED, PREPARING/WAITING без захвата, уже переданный или поставленный к передаче ABORT, освобождённое окно), Stop не создаёт нового ABORT. Последний window_id сам по себе не доказывает наличие активного окна. Повторный STOP получает свой STOP_ACK, но не второй terminal outcome. Уже начатый/поставленный необходимый ABORT завершается перед этим ACK.

Начатый DATA/BEGIN допередаётся перед terminal/ACK, не обрывается посередине. После STOP_ACK не передаются данные остановленной generation. Stop освобождает buffer после terminal frame, не ждёт RELEASE. Tombstone committed END сохраняется; поздний RELEASE не возобновляет остановленный режим. Во время TX drain состояние TRANSFERRING; барьер Stop снимается после принятия последнего байта STOP_ACK транспортом, состояние становится STOPPED. Последующий STATUS(STOPPED) может ещё ожидать передачи; это не запрещает новую команду после ACK. Начатый STATUS допередаётся по порядку, а устаревший неначатый STATUS может быть заменён без расхода sequence. Обязательные ответы прежним командам не удаляются. Неподтверждённый Stop при TX timeout требует восстановления.

Порядок: ответ прежнему CONFIG/ARM/ERROR → нужный terminal frame → STOP_ACK → STATUS(STOPPED). На ПК STOP_ACK закрывает ожидание Stop; прежние запросы уже ответили и их timeout выключен. После успешного STOP_ACK разрешён новый ARM. ERROR на STOP завершает ожидание с отказом и ведёт к обязательному восстановлению; новый ARM возможен лишь после нового HELLO/CONFIG. У окна один terminal outcome: валидный END, ABORT либо локальная неполнота из-за потери связи. ABORT для реально выделенного окна может прийти до WINDOW_BEGIN, если захват отменён до передачи массива; ПК фиксирует отмену в текущей generation, но не создаёт полного или нулевого измерения. window_id=0 никогда не обозначает выделенное окно и не допускается в END/ABORT. Проверка идентификаторов и повторов обязательна и для раннего ABORT.

ERROR codes: 1 INVALID_CONFIG, 2 BUSY, 3 STALE_CONFIG, 4 STALE_GENERATION, 5 UNKNOWN_TYPE, 6 INVALID_PAYLOAD, 7 BAD_WINDOW_RELEASE, 8 NOT_NEGOTIATED.
Abort reasons: 1 STOP, 2 DMA_ERROR, 3 ACQ_DEADLINE, 4 TRANSFER_TIMEOUT, 5 DISCONNECT, 6 INTERNAL.
STATUS.reason: 0 NONE, 1 DMA_ERROR, 2 ACQ_DEADLINE, 3 TRANSFER_TIMEOUT, 4 PROTOCOL_RECOVERY, 5 INTERNAL, 6 COUNTER_SATURATED. Пространство независимо от ERROR/ABORT. Штатные состояния имеют reason0; ERROR указывает причину.

Счётчики сбрасывает HELLO, wrap запрещён. Observed_external_edges увеличивается на каждый обнаруженный выбранный фронт, включая busy/STOPPED. External_edge_id принятого внешнего запуска равен новому значению счётчика; при trigger_kind=external он ненулевой в любом режиме, включая Auto; при trigger_kind=analog или auto_timeout он равен0. Busy_external_edges увеличивается, если фронт не принят из-за состояния или аналогового source. Dropped_windows увеличивается при отмене выделенного окна; отсутствие аналогового события его не меняет. При насыщении любого счётчика — ERROR/COUNTER_SATURATED и новый HELLO; неоднозначный id не выдаётся. Число всех физических команд без измеренной границы частоты не гарантируется.

Отсоединённый прибор не обязан передать сообщение об отсоединении по уже разорванному USB; ПК фиксирует причину сам. Счётчики внешних фронтов считают обнаруженные аппаратурой события, а не гарантированное количество команд стенда. Их предел частоты и точность требуют измерения; пропуск/занятость не обозначает отсутствие искры.

### Сроки команд и проверка

Ответ на обычную команду ожидается до 1000 ms с завершения её записи в транспорт; Stop также1000 ms, независимо от ожидания запуска. Истечение означает неизвестный результат и процедуру восстановления, не автоматический повтор ARM.
Профиль50kS/s/2048 — кандидат для первого пути. Поддержка этого профиля должна подтверждаться сборкой/ресурсами, а реальная частота — отдельным измерением.

Для принятия требуются независимые положительные/отрицательные векторы каждого payload, fragmented/coalesced/oversize/CRC tests, сценарии handshake/reconnect/Stop/rearm и двадцать синтетических окон с побитным round-trip у B. Этот PR пока содержит только byte codec и один вектор; эти критерии открыты.

## Совместимость версии и источники

В этом draft требуется точное совпадение major=0 и minor=1. Любое другое значение возвращает MT_WIRE_VERSION после проверки целостности; низкоуровневый codec не отправляет ответ. ПК показывает несовместимость только при CRC-valid кадре неподдерживаемой версии; timeout без ответа имеет неизвестную причину. В обоих случаях новое вооружение запрещено. Обновление minor пока не считается автоматически совместимым: таблица миграции и новые векторы нужны отдельным PR.

Исследовательские основания (не аппаратные доказательства):
- [ST DS5319](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf): ресурсы, выводы, ADC/USB.
- [ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf): таймеры, ADC, DMA, USB.
- [ST ES096](https://www.st.com/resource/en/errata_sheet/cd00190234.pdf): ограничения DMA, ADC, таймеров и USB. Выбранные обходы должны попасть в реализацию и тесты.
- [Microsoft Usbser](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-driver-installation-based-on-compatible-ids): CDC ACM в Windows 10.
- [COBS, Cheshire/Baker](https://stuartcheshire.org/papers/COBSforSIGCOMM/): framing.

RAM проекта должна дополнительно включать полный последний принятый кадр для проверки дубля, RX accumulation, TX staging и стек. Источники не подтверждают полезную скорость конкретного готового прибора.
