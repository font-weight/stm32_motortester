# TIME002: единый источник millis для TinyUSB

Локальный draft Dot A; [область](https://github.com/font-weight/stm32_motortester/issues/2#issuecomment-6102267218).
Это узкий foreground-only адаптер к существующему TIME, без main и новой эпохи.

## Контракт

После настоящего system reset и успешного BOOT002/TIME вызвать один раз
`mt_usb_time_bind` с тем же объектом TIME, который использует runtime. Bind
проверяет latched health до и после настоящего `mt_timebase_now_ms`. Объект TIME,
его callbacks/context и связанные потребители сохраняются до system reset.
Повторный bind возвращает 0 и не заменяет прежнюю привязку. Первый неуспешный
bind, ранний numeric hook или обнаруженный reentry запрещают последующую привязку.

`tusb_time_millis_api` обновляет настоящий TIME и возвращает накопленные `ms`.
Это не `us32/1000`, не число вызовов, не SOF и не второй таймер. Перед и после
использования числового результата вызывающий проверяет `mt_usb_time_valid`.
На ошибке возвращается последнее успешно принятое значение только для
диагностики; оно не является допустимым временем. 0 и UINT32_MAX могут быть
нормальными значениями. Ошибка фиксируется до system reset; внутреннего reset API нет.

`mt_usb_time_valid/status` наблюдают сохранённое состояние и latched health TIME,
но не читают MMIO и не гарантируют свежесть времени. Изменение аппаратного clock
обнаруживается следующим настоящим TIME update в пределах его собственного
контракта. Первая ошибка сохраняется. Вложенный bind/hook из MMIO callback
отмечается как REENTRY; уже начатое обновление TIME не откатывается. Это не
разрешение reentry. Вызовы valid/status сами не запускают callbacks.

Один привилегированный foreground-владелец, без ISR, конкурентных вызовов и
произвольных writers. Адаптер не проверяет IPSR/PRIMASK и не делает TIME потокобезопасным.
Обычный runtime и hook должны обслуживать один объект последовательно.
Сохраняются ограничения TIME: реальный интервал <65536 тиков, наблюдаемый delta
не более 32000; несколько пропущенных оборотов не обнаруживаются. Для активного
ADC нужен более жёсткий срок обслуживания <2560 мкс. Эти интервалы не измерены.

## TinyUSB и границы

Зафиксированный OS_NONE/F103/CDC/bridge-профиль не вызывает эти hooks из init,
USB task или ISR. Единственная объектная ссылка на millis принадлежит weak
`tusb_time_delay_ms_api`, у которого в профиле нет вызывающей стороны. Адаптер
честно разрешает эту ссылку при no-GC линковке, но не делает delay пригодным.
Вызывать weak delay запрещено: у uint32 API нет канала ошибки, frozen clock
может оставить цикл навсегда, а обновление TIME не обслуживает ADC. Новые
callbacks, debug/class/OS настройки требуют новой проверки достижимости.

Общий enum ABI требует `-fno-short-enums`; BOOT-композиция также использует
`-Wa,--noexecstack`. Это metadata, не аппаратная защита стека. Данный модуль не
останавливает ADC/TIME, не очищает сохранённые объекты и не допускает CPU IRQ.
При TIME_FAULT runtime продолжает шаги ради настоящего Stop согласно своему
контракту. Числовой hook нельзя использовать для обхода этого состояния.

Исходники и исполненные проверки привязываются отдельно. До независимого
вердикта и обязательных доказательств результат остаётся draft. Плата, timing,
полный ELF/стек и Windows enumeration здесь не проверяются.
