# IRQ002: два USB-вектора STM32F103C8

Локальный черновик связывает настоящие HP/LP-векторы с TinyUSB rhport 0.
Каждый handler сохраняет PRIMASK, удерживает маску на протяжении всего вызова
DCD и восстанавливает ровно прежнее значение. Используется IRQ001, а не новое
управление маской. Внутренние guard-вызовы bridge корректно вкладываются.

Это только wrappers: здесь нет настройки RCC, NVIC, priority, GPIO, pull-up,
EXTI18 или boot. До включения USB вызывающая интеграция должна подготовить
runtime, descriptors и единственный DCD, назначить обоим IRQ одинаковый полный
реализованный priority и удерживать PRIMASK до готовности всей системы.
Одинаковый priority исключает их взаимное вложение ещё в прологе до enter.
Другие ISR, NMI и HardFault не должны обращаться к общему USB-состоянию.
Обычные C handlers требуют 8-байтного выравнивания стека при входе в исключение:
начальный MSP должен быть выровнен, а CCR.STKALIGN установлен до разрешения IRQ.
BOOT001 выполняет это; иной startup обязан обеспечить ту же предпосылку.

TIME sampler, runtime_step, controller и ADC service вызываются только из
foreground. ISR не должен обслуживать их для обхода временного ограничения.
Ни guard, ни два коротких wrappers не ограничивают число итераций DCD CTR loop
и не доказывают worst-case latency или бюджет обслуживания ADC/TIM2.

STM32F103xB: HP — IRQ19, слово таблицы35; LP — IRQ20, слово36. Оба strong
символа обязаны заменить weak defaults в итоговом ELF. USBWakeUp IRQ42 здесь
не реализован и не разрешён; STOP-mode wake не добавляется.

IRQ19/20 разделяются с CAN1 TX/FIFO0, но эти wrappers обслуживают только USB.
CAN1 исключён из профиля: все его interrupt sources должны оставаться выключены,
а ожидающего CAN1 TX/FIFO0 источника быть не должно. Иначе такой источник не
будет погашен USB DCD и возможен повторный вход в ISR. Проверка этой предпосылки
принадлежит настоящему boot/плате; короткая обёртка не проверяет CAN-регистры.

Проверки: strict/sanitized модель порядка enter → DCD(0) → leave с исходными
масками 0/1 и вложенными locks, ARM object/disassembly и реальная линковка
векторов BOOT001. Fake DCD годится только для проверки обёртки и обязательно
обозначается как fixture. Связь с реальным layered USB005 DCD проверяется
отдельно без заявления о полной прошивке. Исполнение на MCU, NVIC priority,
USB enumeration и длительность ISR остаются непроверенными.

Применять тот же Cortex-M3/Thumb/soft-float профиль и закреплённые TinyUSB/CMSIS
зависимости, что у IRQ001/USB005. Нет нового wire-протокола или heap/storage.
До независимого вердикта и immutable binding: BLOCKED_EVIDENCE, score null.
