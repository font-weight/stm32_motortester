# Черновой opt-in: квант CTR и возврат foreground-владельцу

Это отдельный patch поверх существующих reset-cleanup и USB005 FSDEV patches.
Исходный vendored TinyUSB не меняется. CFG_MT_USB_CTR_FAIRNESS по умолчанию 0:
прежний профиль продолжает использовать старый цикл. Новый opt-in ещё не включён
в startup, runtime, образ или пользовательский комплект.

При включении guarded F103-профиль обрабатывает за вызов IRQ не более одной
итерации endpoint CTR. Одна итерация может обработать одновременно RX и TX,
то есть создать два события. После неё устанавливается deferred и маскируется
CTRM, независимо от того, виден ли ещё CTR в этот момент. Только ограничения
счётчика цикла было бы недостаточно: немедленные повторные IRQ могли бы снова
лишить foreground времени для АЦП.

Пока deferred установлен, повторный IRQ, в том числе вызванный lifecycle,
не обслуживает CTR. Сам незавершённый CTR/PMA не очищается ради выхода из цикла.
Существующая обработка RESET/PMAOVR/SUSP/WKUP остаётся; physical reset убирает
старые transfer-ссылки прежним проверенным patch, сбрасывает deferred и
восстанавливает CTRM для новой эпохи.

## Обязательства будущего владельца

mt_usb_fsdev_ctr_rearm вызывается только foreground под тем же save/restore
IRQ guard, что и DCD. До нового grant владелец обслуживает TIME/ADC и проверяет
очередь USB. Если она не пуста, он обрабатывает ограниченное число событий,
возвращается к ADC и проверяет снова; не заменяет это бесконечным drain-loop.
При текущем одном событии task за шаг нельзя безусловно разрешать новый квант
из двух событий каждый шаг: так можно заполнить 16 слотов.

Rearm отклоняет наблюдаемые RESET/PMAOVR/SUSP, FRES/PDWN/FSUSP и выключенную
USB function. Это не receipt о завершённом cleanup и не разрешение app I/O.
Владелец отдельно сохраняет текущую USB epoch, lifecycle admission, исходный
actor, очистку при потере связи и запрет старого writer. Наличие API не доказывает,
что будущий runtime правильно соблюдает эти требования.

Профиль ограничен существующими одиночно буферизованными CDC/EP0 endpoint,
без CAN, iso и стороннего владельца USB/PMA. В opt-in ISO alloc/activate
и неподходящий тип generic endpoint отклоняются до изменения allocation/PMA;
значения опции кроме 0/1 запрещены при компиляции. Не переносить выводы на iso или
другие IRQ-линии/контроллеры. Тайминги EP0, PMA overrun, mask/unmask race,
реальное поведение NVIC и пропускная способность должны быть проверены отдельно.

## Воспроизводимость

После воспроизведения существующих reset и USB005 FSDEV слоёв:

python3 firmware/third_party/usb/patches/apply_stream_ctr_patch.py INPUT.c NEW_OUTPUT.c

Input, patch и output закреплены SHA-256 в stream-ctr-fairness.json. Патчер не
изменяет inputs, запрещает существующий output и проверяет результат без fuzz.
Затем новый source компилируется с CFG_MT_USB_CTR_FAIRNESS=1. Заголовок
mt_usb_ctr.h задаёт только интерфейс, не включает опцию автоматически.

Первые полные ARM object-компиляции actual patched DCD для опций 0 и 1 прошли
GCC 14.2.1, Cortex-M3/Thumb/soft, -Os, -Wall/-Wextra/-Werror. Это проверка
translation unit, не новая полная Flash/SRAM-сборка и не доказательство WCET.
Нативные проверки фактического обработчика и независимое ревью ещё выполняются.

## Что не доказано

Конечный CTR-квант не ограничивает произвольный поток lifecycle IRQ и не
доказывает aggregate interruption bound. Число операций не заменяет измерение
полной TX-транзакции, включая preemption, clock validation и финальный commit.
Требование ADC service <2560 мкс и достаточная частота TX-шагов сохраняются.
Случай нескольких бесконечных RESET/SUSP событий требует отдельной модели
допустимого трафика/fault и fail-closed поведения. Этот patch не объявляет
непрерывную физическую запись готовой и не разрешает новую прошивку.
