# Ограниченная очередь отсчётов: отдельный прототип

Задача #191, часть будущего потокового режима. Модуль пока не подключён к
действующей прошивке, USB или драйверу АЦП. Единственный владелец — основной
цикл; работа одновременно из IRQ и основного цикла не допускается.
Перед обращением объект должен быть инициализирован; его поля нельзя
изменять извне. init(NULL) и seal(NULL) ничего не делают.

Очередь хранит 16 блоков по 128 кодов uint16_t: 4096 байт исходных отсчётов
плюс метаданные. Размер всей структуры зависит от ABI и требует отдельного
учёта в итоговой карте ARM. Добавлять её поверх существующего окна без
проверки памяти нельзя: предполагается взаимоисключающее использование
хранилища окна/потока, которое ещё нужно реализовать.
На проверенной Linux x86-64 ABI sizeof очереди составляет 4168 байт,
из них ровно 4096 байт — отсчёты; это не размер структуры в ARM-сборке.
push проверяет не более 128 кодов и копирует не более 256 байт; peek/pop/seal
имеют постоянное число операций, init очищает одну структуру. Эти границы
работы не являются измеренными временными задержками.

Блоки имеют непрерывные абсолютные индексы. Проверяются код 0–4095,
размер 1–128, ожидаемый первый индекс и отсутствие переполнения uint64_t.
Укороченный блок допускается только как последний. Пустое завершение
закрывает очередь без блока нулевой длины. Новый wire0.2 поток начинает
индексы с нуля; ненулевой origin API предназначен для отдельного интервала
и граничных тестов, не для продолжения записи после сбоя.

При переполнении или неверных входных данных сохраняется первая причина,
приём закрывается, уже принятый корректный префикс можно дочитать.
Вызывающий код обязан остановить получение новых данных и сохранить
сведения о потере; сам модуль не выключает таймер/DMA и не определяет,
сколько отсчётов устройство успело получить после отказа.
Порядок отказов: NULL queue, закрытая очередь, NULL samples, размер/final,
первый индекс, переполнение конечного индекса, коды, ёмкость. Поэтому
неправильный код обнаруживается раньше FULL. final допускает только 0/1;
другое значение возвращает COUNT. Закрытая очередь не читает новые samples.

peek выдаёт неизменяемое представление головного блока. Оно действительно
до успешного pop или init. Закрытие приёма также не отменяет это
представление. Переданный неправильный индекс pop не удаляет блок. Нельзя удалять данные при простой постановке кадра в TX, если кодер
ещё использует представление. Очередь не доказывает завершение передачи,
получение на ПК или запись на диск. next_index — конец принятых очередью
отсчётов, не доказательство produced_end или prefix_end wire-протокола.

init разрешён только после внешней проверки остановки получения данных
и отмены всех старых ссылок. Идентификаторы сеанса/поколения, CRC, порядок
START_ACK/DATA/END/STOP_ACK, предел дренирования 500 мс и аппаратный барьер
остаются обязанностями будущей композиции состояния/транспорта.

Проверка этого шага — отдельная нативная FIFO-модель, граничные случаи и
sanitizers. Это не измерение скорости потока и не допуск новой прошивки.

Исполняемые проверки: tests/acquisition/sample-queue/README.md.
Из корня репозитория: sh tests/acquisition/sample-queue/run.sh .
Независимая эталонная модель использует сдвигаемый линейный FIFO, а не
копирует кольцевую адресацию модуля. Проверены ошибочные входы, все длины
последнего блока, заполнение/повторное использование, сохранение префикса
при отказах и дочитывание закрытой очереди. Это ограниченные программные
проверки, не доказательство отсутствия потерь в реальном приборе.
