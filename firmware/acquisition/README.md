# Ядро оконного захвата: ограниченный черновик

База требований: PR #4, `124b3f32e1e7f7282bce283baa4c9406d4d72950`.
Это программный модуль C11 для будущей прошивки, а не драйвер АЦП и не
подтверждение характеристик платы. Общий wire v0.1 остаётся черновиком.
Приёмка этого модуля требует независимого Critic-A по `docs/quality-gate.md`.

## Результат и границы проверки

Проверяется алгоритмическая часть MVP-F03/F04/F05/F06/F07:

- одно конечное окно из 2048 исходных кодов 12-битного АЦП;
- кольцевая предыстория 0/512/1024 отсчётов;
- аналоговый запуск по фронту и уровню, Auto/Normal/Single;
- неизменный полный буфер до явного освобождения;
- программные остановка, ошибка и повторное вооружение;
- отрицательные сценарии и побитное сравнение с независимым линейным массивом.

Модуль не закрывает эти требования целиком. Он не настраивает TIM/ADC/DMA,
не управляет USB, не считает идентификаторы сеанса/окон и не проверяет CRC.
Внешнего запуска пока нет: `source != 0` отвергается, соответствующую
capability нельзя объявлять. Отдельно остаются аппаратные MVP-F01/F02,
согласование общего протокола, сборка прошивки, карта памяти, частота/задержки,
проверка Windows и реальные LV-001/V-01–V-04.

Условие готовности этого ограниченного черновика: воспроизводимые native
тесты алгоритма и интерфейса; независимое ревью точного интегрированного SHA.
Статус `software-ready` всему прибору из этих тестов не следует.

## Память и время

Объект `mt_acq_t` содержит единственный массив `uint16_t[2048]` (4096 байт)
и состояние. На проверенном x86-64 ABI GCC 14.2.0 его размер 4156 байт.
Размер на целевой сборке следует проверять отдельно. Объект нужно выделить
статически, а не на стеке обработки каждого окна.

Нет heap, рекурсии, плавающей точки или второго массива окна. Добавление
отсчёта и чтение одного элемента имеют постоянное число операций; вращение
всего массива не требуется. Для передачи читают логические индексы 0…2047
через `mt_acq_read`, а не копируют физический `samples[]` как линейное окно.

Число крайних кодов хранится вместе с кольцом: при перезаписи старого кода
0/4095 счётчик уменьшается. Поэтому крайний код из давно отброшенной
предыстории не помечает более позднее окно. Это признак наблюдения кода,
а не доказательство аналоговой перегрузки.

Профиль 1 — проектные 50 kS/s, 2048 отсчётов. Период при этой номинальной
частоте 20 мкс. На 2048 периодов приходится 40,96 мс; расстояние между
первым и последним отсчётами — 2047 периодов, 40,94 мс. Предыстория
0/512/1024 соответствует 0/10,24/20,48 мс. Эти расчёты не измеряют Fs.
Ядро само частоту не задаёт и не проверяет.

В бюджет 20 KiB SRAM дополнительно входят DMA staging, USB/протокольные
буферы, остальные globals и полный стек вызовов. Ни размер этого объекта,
ни native `sizeof` не заменяют целевую linker map. Дедлайн обработки DMA
и максимальное время выполнения на Cortex-M3 пока не измерены.

## Точная граница подготовки и запуска

Пусть `P` — число отсчётов предыстории; входные отсчёты нумеруются с нуля.

- При `P > 0` отсчёты `0…P−1` относятся к PREPARING. Даже если на `P−1`
  есть пересечение уровня, оно не запускает окно. После него состояние
  становится WAITING; первым допустимым отсчётом запуска является `P`.
- При `P = 0` WAITING начинается в `arm`. Первый отсчёт только задаёт
  предыдущий код и сам по себе не является аналоговым фронтом. Самый ранний
  аналоговый запуск возможен на втором отсчёте.
- Rising: `previous < level && current >= level`.
- Falling: `previous > level && current <= level`.
- Уровень допустим в кодах 1…4094; гистерезис и интерполяция не реализованы.
  Переход с уровня на ту же сторону не считается новым пересечением.

Отсчёт реального запуска расположен в окне по индексу `P`. До него ровно
`P` последовательных кодов, после него — `2048−P−1`. События во время
CAPTURING не меняют начало уже выбранного окна. Никакого непрерывного
набора окон без интервалов нечувствительности этот механизм не обещает.

## Auto и часы

`arm`, `release` и `push` получают один и тот же монотонный счётчик
миллисекунд modulo 2^32. У `push` время относится к физическому получению
данного отсчёта, а не к более поздней обработке DMA-блока. Одинаковые
миллисекундные значения для последовательных отсчётов допустимы.
Каждый отдельный переход времени должен быть меньше 2^31 мс: обратное
время и скачок от этой границы дают ERROR/TIME_ORDER.

Отсчёт Auto timeout начинается после принятия последнего отсчёта подготовки;
при `P=0` — с времени `arm`. На первом отсчёте, для которого elapsed >= timeout,
выбирается окно с сохранённой предысторией и текущим/последующими кодами.
Флаг `auto_timeout` установлен, `trigger_index=0xffff`; реальное событие
не придумывается. Если на том же отсчёте есть допустимое аналоговое
пересечение, побеждает реальное пересечение и флаг timeout не ставится.

Timeout может принудительно выбрать уже первый отсчёт при `P=0`, но не
превращает его в аналоговый фронт. Если отсчётов вообще нет, ядро не создаёт
окно. Драйвер обязан обнаружить остановку потока/DMA-дедлайн и вызвать
`mt_acq_fail`; нельзя выдавать эту потерю данных за Auto-окно.

Эта точная семантика — предложение для интеграции. Она не меняет wire
контракт без отдельного согласования двух сторон и независимых критиков.

## Интерфейс и владение

1. `mt_acq_init` и `mt_acq_configure`: профиль 1, source 0, выбранные mode,
   edge, level и P. Auto timeout 100…60000 мс; для Normal/Single — строго 0.
   Ошибка configure оставляет прежнюю конфигурацию неизменной.
2. `mt_acq_arm`: только из STOPPED с принятой конфигурацией. Обнуляет
   предысторию/состояние предыдущего окна; прежнее пересечение не переносится.
3. `mt_acq_push`: по одному последовательному достоверному коду.
   `MT_ACQ_TRIGGERED` означает выбор начала окна; `MT_ACQ_WINDOW_READY` —
   наличие ровно 2048 кодов. Любая потеря между ними остаётся ошибкой.
4. FROZEN: `mt_acq_window` возвращает метаданные, `mt_acq_read` — код по
   хронологическому индексу. Дополнительные push игнорируются без изменения
   памяти/метаданных. Configure/arm запрещены. Выходные значения при
   неуспешном чтении не меняются.
5. Только после проверки RELEASE слоем сеанса вызвать `mt_acq_release`
   один раз. Auto/Normal заново готовят предысторию; Single становится
   STOPPED. Повтор RELEASE должен быть поглощён tombstone слоя сеанса;
   ядро не отличает дубли разных окон и не владеет этими идентификаторами.

У этого автомата нет TRANSFERRING/WAIT_RELEASE: оба состояния протокола
удерживают ядро FROZEN. Числа внутреннего enum состояния нельзя отправлять
как wire state; соответствие обязан явно задать слой интеграции.
Generation/window/config IDs, счётчики пропусков, little-endian сериализация,
CRC, новые HELLO и дедлайны TX/RELEASE относятся к слою сеанса/транспорта.

Все вызовы для одного объекта выполняются последовательно. Ядро не имеет
атомиков/блокировок и не предназначено для конкурентного вызова из IRQ и
основного цикла. Поля структуры открыты для статического выделения и
наблюдения; менять их вручную запрещено. DMA не должен записывать прямо
в этот массив: проверенный staging передаётся через push. Подмена времени
всем отсчётам задержанного блока временем его обработки недопустима.

## Stop и ошибка

`mt_acq_stop` идемпотентен: очищает состояние, делает полные чтения
недоступными, дальнейшие push игнорируются. Он не стирает физические байты
массива, но они больше не являются опубликованным полным окном.
Принятая конфигурация сохраняется для следующего arm. `mt_acq_init`
сбрасывает также конфигурацию и применяется при полном сбросе сеанса.

Stop не выключает железо. Интегратор обязан остановить TIM/DMA, определить
необратимость WINDOW_END, сохранить уже начатый сериализованный кадр для
TX drain и выполнить wire-порядок ABORT/END/STOP_ACK. Нельзя после Stop
дочитывать уничтоженное логическое окно, чтобы сериализовать новый кадр.

Недопустимый ADC-код или обратное время переводят активный захват в ERROR.
`mt_acq_fail` позволяет драйверу сообщить DMA_ERROR/ACQ_DEADLINE и также
запрещает полные чтения, включая ранее замороженное окно. Никакого
WINDOW_END это ядро не отправляет. Wire-ошибку и число потерянных окон
формирует интегратор. Для восстановления нужен явный stop или init;
из ERROR нельзя молча вооружиться.

## Воспроизводимая проверка

Из корня репозитория:

```sh
sh tests/acquisition/run_tests.sh
```

Нужен C11-компилятор GCC с UBSan; `CC` позволяет выбрать его явно.
Скрипт собирает две версии во временной папке и удаляет её при завершении:
строгую native-сборку и сборку с undefined-behavior sanitizer. Обе обязаны
пройти. Используются `-Wall -Wextra -Wpedantic -Wconversion
-Wsign-conversion -Werror`; assertions включены.

Проверки: недопустимые/предельные настройки и атомарность отказа; оба фронта
на границе готовности; все сочетания mode/P/edge; 120 детерминированных
псевдослучайных окон с полной сверкой с линейным эталоном; wrap кольца;
точный Auto timeout и wrap часов; приоритет пересечения; удержание/Release;
Single; Stop из каждого состояния; отсутствие устаревших чтений; ADC/DMA/
deadline/time-order ошибки; крайние коды внутри и вне итогового окна.

Начальный результат на Dot cloud x86-64: GCC 14.2.0, 153 сценария в каждой
сборке, `sizeof(mt_acq_t)=4156`. Это синтетика. ARM-компиляция, полный расход
Flash/RAM, ISR/WCET, DMA, USB, Fs и физические соединения не проверены.

Следующий шаг: интеграционный адаптер владельца прошивки и независимый
Critic-A на точный SHA после публикации. При появлении драйвера проверить
целевую сборку/карту, staging-overrun, остановку DMA и низковольтный опыт
по общей методике, не подменяя их этим native тестом.

## Черновой внутренний захват «Запись сейчас», 12.10.2026

По уточнению владельца в issue134 внешний запуск от отдельно разрабатываемого
стенда исключается. Наличие внутреннего таймерного запуска АЦП не меняется.
Новая функция `mt_acq_record_now()` пока является **только API ядра захвата**:
она не подключена к USB-команде, GUI или старому контракту wire v0.1.

Условия: остановленный и настроенный контекст, прежний режим Single,
предыстория 0. Следующий допустимый отсчёт без ожидания порога/тайм-аута
возвращает `MT_ACQ_TRIGGERED`; далее собирается ровно 2048 свежих отсчётов.
Это позволяет будущему адаптеру выделить window_id обычным способом.
Длительность при проектных 50 kS/s — 40,96 мс, не автоматически один период
или полная искра. Событие может отсутствовать или выходить за границы окна.

Метаданные: внутренний `MT_ACQ_TRIGGER_SOFTWARE=3`, индекс `0xffff`,
предыстория 0; флаг Auto-timeout не выставляется. Флаг предельного кода АЦП
считается обычным способом. Время команды ПК не объявляется аппаратной
отметкой искры. Вызывающий код обязан обеспечить свежую эпоху таймера/DMA.
После полного окна Single RELEASE останавливает ядро; Stop и ошибки
инвалидируют чтение. Обычный ARM сохраняет прежний пороговый запуск.

Код 3 не разрешён действующим совместным протоколом и старым приложением.
До отдельного согласования A/B нельзя направлять такие окна в USB как v0.1.
Принятие этого черновика как полной прошивки заблокировано: нужны обновлённый
wire-контракт/ПК-обработка, интеграционные проверки, ARM-пересборка и новые
пины источников/объектов в build/inputs.json. Старые image/RAM/stack доказательства
не относятся к изменённому ядру. Исторические пины оставлены без подмены.
