# Нативный прототип потокового endpoint устройства

Это отдельная реализация wire0.2 для программных проверок. Она использует
mt_wire_*_revision и mt_sample_queue, но не подключена к существующему
USB/ADC endpoint, загрузочному коду или сборке прошивки платы. Проверенный
оконный бинарник остаётся отдельным артефактом.

## Владение и интерфейсы

Один основной цикл владеет объектом mt_live_device. receive принимает не
более 544 байт за вызов, step выполняет не более одной передачи до 64 байт,
offer принимает сертифицированный полный блок из 128 отсчётов. Остаток при
остановке передаётся через snapshot драйвера. IRQ и повторный вход из callback
в эти функции запрещены. Поля объекта принадлежат реализации.

Init допустим на новом хранилище либо после внешней остановки/сброса,
изоляции записи и отмены старых представлений. Init сам не выключает АЦП
и не подтверждает физическую остановку.

В mt_live_io задаются синтетические границы адаптера:
- clock_ms: неубывающее целое время, без переполнения, до INT64_MAX;
- start: включает фиксированный профиль для поколения, возвращает 1 при
  успехе, 0 при отказе; отказ может потребовать очистки частично включённого
  оборудования;
- quiesce: реально проверяет аппаратный барьер и возвращает независимый
  снимок из 0–2 блоков, точный либо неизвестный конечный индекс и первую
  причину отказа отдельно от успеха остановки;
- write: копирует известный принятый префикс в упорядоченный FIFO, не хранит
  указатель; SIZE_MAX означает неизвестное число принятых байтов;
- isolate_tx: подтверждает отсутствие будущих добавлений старым writer и
  порядок уже принятых байтов относительно нового разделителя/ответа.

Подробные постусловия — в mt_live_device.h. Само наличие callback-функции
не доказывает выполнения этих условий настоящим драйвером.

## Состояние и доказательства

HELLO требует свежего nonce и настоящего подтверждения quiescence.
Смена nonce не очищает аппаратную неисправность автоматически. Старый
сеанс публикует только уже начатый кадр в пределах унаследованного срока;
не начатые старые ответы отбрасываются. Новый STOPPED появляется только
после своевременного завершения HELLO_ACK. Ошибка финальной проверки
времени сохраняет старые nonce, первую причину, проверенный префикс и очередь.

GET_CAPS предшествует START. Ответ START резервируется до обращения к
драйверу. При отказе START выдаётся только START_FAILED с request id попытки;
нет DATA, END или дополнительного ответа Stop. Новый START во время активного
потока/после терминала вызывает recovery. Старый nonce не потребляет
текущую последовательность. Дубликат сравнивается по точным encoded bytes.

Последовательность TX фиксируется первым реально принятым байтом. Префикс,
CRC и номер DATA фиксируются только после принятия целого кадра. Пока
текущий DATA использует головной блок очереди, тот не удаляется.
Остановка выдаёт START_ACK (если ожидался), DATA-префикс, END и допустимый
STOP_ACK. END после первого принятого байта неизменяем; поздний Stop ссылается
на него. Неизвестный или недоказанно остановленный producer имеет неизвестный
конечный индекс. При непроверенном hardware-off STOP_ACK не выдаётся.

Некорректный snapshot проверяется до добавления его хвоста. После отказа
очереди новый хвост не соединяется через потерянный блок. Сохранённая
длина очереди не подменяет фактически произведённые или доставленные данные.

## Временные границы

500-мс бюджет shutdown начинается до stop/barrier, HELLO имеет свой бюджет.
Унаследованный срок начатого кадра нельзя продлить новым HELLO. При равенстве
срок истёк. Проверки вызываются и без входящего трафика через step.

До TX проверяется now+B < deadline. B обязан покрывать всю транзакцию:
запись, обработку результата, проверку времени и финальную публикацию
состояния, включая вытеснение и инициализацию очереди. Без подтверждённой
границы адаптера такой вызов нельзя считать квалифицированным. Позднюю
видимую ACK невозможно отозвать; позднее обнаружение фиксирует нарушение
условий, а не обещает, что HOST обязательно распознал его.

В тестах время и границы callback заданы искусственно. Реальные задержки,
прерывания, FIFO, аппаратная остановка, ARM-память/стек и Windows COM пока
не проверены. Нативный успех не разрешает перенос этих предположений на плату.

## Проверки и оставшаяся интеграция

Независимые нативные сценарии и actual C ↔ HOST проверки выполняются на
точных исходниках. HOST — из PR195, commit
0e96e574c2ef5c7234a6cfc96665cb88ddca9911; отдельная HOST-модель не подставляется.
Тесты включают фрагментацию, частичную запись, остановку на границах кадров,
отказы/переполнение и сохранение старых данных при неудачном восстановлении.
Из корня исходников нативные проверки:
sh tests/protocol/live-device/native/run.sh .

Для сопряжения задайте SOURCE_ROOT (эти исходники) и HOST_ROOT (каталог host
точного внешнего PR195), затем запустите:
sh tests/protocol/live-device/peer/run.sh

Peer-проверка проверяет хеши трёх реально импортируемых файлов HOST и не
содержит копии его реализации. Итоговый запуск интегратора: 79 нативных
сценариев в строгом C11 и ASan/UBSan; 22 coupled-метода / 148 сценариев и
две проверки длины кадра в normal/-O/UBSan/ASan+UBSan. LeakSanitizer отключён
из-за ограничения ptrace; проверка утечек не заявлена. Счётчики описывают
охват, не являются оценкой качества и не подменяют независимое ревью.

Для платы ещё нужны адаптер ADC/DMA с устойчивым хвостом, расширение счётчика
источника до uint64, реальная изоляция TX, применение исправленного INLINE
clock-пути, режимные изменения загрузки/диспетчеризации и новая проверка всей
ARM-сборки. Затем обязательны измерения низковольтного потока, времени и
переполнения. До них новый бинарник не выпускается и непрерывность не заявляется.

На проверенной Linux x86-64 ABI объект endpoint занимает 6160 байт,
включая очередь 4168 байт; snapshot занимает 568 байт, таблица callback —
56 байт. Это не подтверждение размеров, размещения или стека ARM.

Корректный по CRC кадр другой версии фиксируется как локальная
несовместимость и вызывает recovery без нового типа wire-ответа.
Ранняя причина сохраняется, дополнительный флаг incompatible_seen остаётся
наблюдаемым до успешного нового HELLO. Повреждённый CRC по-прежнему
отбрасывается. Это не обещает, что старое приложение узнает причину вместо
своего тайм-аута; автоматического перехода на 0.1 нет.
