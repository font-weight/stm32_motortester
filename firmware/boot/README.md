# BOOT001: вход после reset и размещение памяти

Черновик для STM32F103C8T6: main Flash 64 KiB, SRAM 20 KiB.
Это самостоятельная граница startup/linker, не готовая прошивка прибора.
Старые файлы задачи A-005 не используются и не заменяются.

## Контракт

- Только настоящий системный reset с загрузкой из Flash. Вызов из приложения,
  SRAM boot и передача управления из bootloader не поддерживаются.
- Аппаратура загружает MSP = 0x20005000. Первая инструкция маскирует IRQ.
  NMI и HardFault остаются возможными; обработчик по умолчанию только зацикливается.
- Таблица содержит ровно 59 слов: 16 ядра и 43 внешних IRQ STM32F103xB.
  База 0x08000000 выровнена на 512 B. Специальный BootRAM-хвост не включён.
- Reset устанавливает VTOR и CCR.STKALIGN, копирует .data и обнуляет .bss
  словами, затем вызывает внешний int main(void). Padding входит в эти диапазоны.
  PRIMASK остаётся 1; разрешать IRQ может только будущая интеграция платы,
  когда часы, состояние программы, обработчики и периферия готовы.
- Возврат из main и необработанное исключение приводят к бесконечному циклу.
  Это не аппаратно безопасное отключение прибора: DMA/периферия здесь не гасятся.
- Обычный сильный обработчик с именем из таблицы заменяет слабый обработчик.
  Reset и таблица сильные. Не предоставляются main, SystemInit, time hook,
  настройка HSE, USB/ADC, приоритеты IRQ или библиотечные заглушки.

## Сборка и ограничения linker

Использовать Cortex-M3, Thumb, soft float, -ffreestanding, -fno-common,
-fno-short-enums, без unwind, LTO, profiling, stack protector и конструкторов.
В данной минимальной конфигурации debug-секции не размещаются: компилировать
с -g0. Требуются GNU ld --orphan-handling=error и --no-gc-sections; сохранять map.
GC в данном профиле не поддерживается: GNU ld может удалить неизвестную
неиспользуемую секцию до проверки orphan. Это обнаружено отказным тестом
первой версии; обязательная проверка всех входных секций сохраняется за счёт
отказа от GC, а не исключения этого случая из приёмки. Не подавлять неопределённые
символы или повторные определения. При драйвере GCC обязательно -nostdlib.

Перед -T stm32f103c8.ld передать --defsym=__boot_stack_bytes=N. N положительно,
кратно 8 и не больше SRAM. Значение по умолчанию отсутствует. Linker проверяет
непересечение статических данных с резервом [__StackLimit,__StackTop).
Резерв задаётся символами, не включён в .bss и не инициализируется reset.
Это геометрическая проверка, не защита от переполнения стека во время работы.

Для маленького test-only main можно явно выбрать 4096 B. Это не продуктовый
расчёт: известная вложенная Stop-цепочка после TX002 составляет 2552 B,
а полный максимум с main, callback, IRQ, NMI и запасом пока не доказан.

Конструкторы/деструкторы, TLS, noinit, COMMON, unwind, interworking/dynamic
stubs удерживаются KEEP как дополнительная защита. Неизвестные секции дают
ошибку в обязательном профиле без GC. Разрешены
только таблица, text/rodata, data/bss и явно перечисленные metadata.
Пустые синтетические stub-секции GNU ld допускаются, ненулевые запрещены.
Не добавлять всепоглощающее DISCARD, чтобы скрыть новую зависимость.

## Проверка и основания

Обязательны проверки ELF: все 59 слов и Thumb bits, выбранный IRQ override,
Reset disassembly, Flash load-диапазоны (включая data), SRAM/stack, секции и
PT_LOAD, отсутствие extern. Отдельно проверяются пустые/непустые и некратные
слову исходные data/bss, точные границы памяти и отказные сценарии linker.
До link обязательно проверять секции каждого входного object: metadata
(.comment, .note.GNU-stack, .ARM.attributes) не должны иметь SHF_ALLOC;
тип .ARM.attributes должен соответствовать ARM attributes. Поддерживаются
только явно перечисленные ARM ELF objects, без архивов и LTO. Проверять ELF
class/endian/machine/ABI flags и фактически выданные ARM build attributes через
закреплённый readelf: профиль Cortex-M3/v7-M, Thumb и soft float. Это не
доказательство пригодности каждого opcode или фактической модели MCU.
После link проверять тип, binding и исполняемый адрес main, Reset и всех
handler-векторов; main должен быть сильным Thumb FUNC в исполняемой Flash.
Границы __data_start/end и __bss_start/end должны точно совпадать с реальными
секциями, а не только лежать в допустимой памяти. Отдельно сверять символы
релокаций исходной таблицы: перестановка слабых IRQ не видна по одинаковым
адресам Default_Handler в финальном ELF.
Одного успешного ld недостаточно: он может принять weak main и удалить
allocating .comment через DISCARD. Финальный ELF уже не показывает удалённый
вход, поэтому последняя проверка не заменяет первую. Эти случаи сохранены
как контрпримеры и проверяются в обязательной цепочке input-audit/link/ELF-audit.
Переносимая проверка разделена на check_boot_image.py inputs (до ld) и elf
(после ld), обе с явным --readelf; стадия elf также получает --objdump,
--vector-map и точный --stack. Запускать Python с -I -B; sibling-модуль
загружается по явному пути. Контроль входов включает все objects и reset-object.
Fixture с искусственным main не заменяет полную component closure и не
доказывает реальное выполнение reset, работу USB или загрузку на плате.

Источники: STM32F103xB header/startup на ST CMSIS Device F1
c8e9a4a4f16b6d2cb2a2083cbe5161025280fb22; RM0008 Rev21 §3.4 и таблица 63;
PM0056 Rev7 §4.4.4 (VTOR) и §4.4.7 (CCR); AAPCS32 §6.2.1.
PM0056 задаёт для этого профиля VTOR bits[29:9]; поэтому выбран шаг 512 B,
несмотря на более общий CMSIS mask от bit7. Независимый вердикт и привязка
к неизменному commit ещё отсутствуют: BLOCKED_EVIDENCE, score null.
