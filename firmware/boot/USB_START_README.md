# BOOT003: подготовка USB до запуска DCD

Локальный draft Dot A, [область issue2](https://github.com/font-weight/stm32_motortester/issues/2#issuecomment-6102143721).
Helper готовит только USB gate/reset и приоритеты HP19/LP20. Он не вызывает
`tusb_init`, runtime/descriptors, не управляет pull-up, не разрешает CPU IRQ и
не является main или полной прошивкой. Старый A-005 и `host/**` не меняются.

## Предусловия и входы

- Настоящий system reset, привилегированный foreground, PRIMASK=1 у вызывающего
  кода; нет других MMIO writers, callback reentry, живых USB/CAN/STOP-wake users.
- Контекст CLK — неизменённый результат успешного `mt_clock_apply` с проверенными
  данными платы. Тот же read32/write32/context используется для всех обращений.
- Объект boot обнулён один раз; структуры/context не перекрываются и живут до
  завершения их использования. Callbacks выполняют aligned32 MMIO и возвращаются.
- `priority` — явное логическое число 0…15, одинаковое для обоих USB IRQ. Частота
  обслуживания или пригодность выбранного приоритета этим не доказывается.
- Обязателен общий 32-битный enum ABI CLK/BOOT (`-fno-short-enums`). Заголовок
  проверяет размеры enum. Для полной BOOT-композиции C objects также должны
  иметь согласованные non-executable GNU stack metadata; это не MPU-защита платы.

Helper не подтверждает физическую историю reset, частоту HSE, достоверность
переданных структур или фактический PRIMASK. Такие предпосылки обеспечивает
интегратор. Вызов после начала работы периферии запрещён.

## Последовательность

После проверки аргументов попытка становится одноразовой до настоящего reset.
Повторный/вложенный вызов возвращает BUSY, сохраняя прежний результат.

1. Проверить успешный CLK receipt и свежие CR/CFGR/Flash по его исходным полям.
   Ожидаются USBEN=0 и USBRST=0.
2. Отвергнуть CANEN/CANRST, enabled/pending/active IRQ19–22 и IRQ42, а также
   включённые для EXTI18 IMR/EMR/RTSR/FTSR/SWIER. CAN-регистры при выключенном
   gate не читаются: их внутреннее состояние этим не удостоверяется.
3. EXTI_PR имеет неопределённое reset-значение. Поэтому начальный PR18=1 сам по
   себе не отвергается. Записать ровно `0x00040000` в PR как W1C и подтвердить
   снятие PR18 и отсутствие SWIER18. Это не RMW: pending других линий сохраняются. EXTI18 остаётся
   невооружённой, её режимы не переписываются.
4. Aligned32 RMW IPR4 (`0xe000e410`, mask `0xf0000000`) и IPR5 (`0xe000e414`,
   mask `0x000000f0`) задают одинаковые implemented priority nibbles. Остальные
   поля сохраняются. Значения читаются обратно; AIRCR/PRIGROUP не меняются.
5. RMW только USBEN bit23 RCC_APB1ENR с readback. Затем USBRST bit23
   RCC_APB1RSTR: установить и подтвердить 1, снять и подтвердить 0; снова
   проверить USB gate. Другие gate/reset bits, включая TIM2, сохраняются.
6. До `ready=1` повторить clock, USBEN=1/USBRST=0, CAN/IRQ/EXTI и priority-проверки. NVIC enables
   остаются выключенными. Проверка группы read-only регистров не является
   атомарным снимком и не обещает фиксированный порядок чтений внутри группы.

Предполагается последующий настоящий `tusb_init`, который включает HP/LP NVIC.
До него runtime/USB bridge и descriptors должны быть готовы. Глобальные IRQ
вызывающий main допускает отдельно после всех проверок. IRQ002 уже предоставляет
strong handlers с корректным сохранением PRIMASK; подменять сохранённый guard key
нулём нельзя. BOOT001 входит в main с PRIMASK=1, простое восстановление этого
значения прерывания не включит.

## Отказ и границы доказательств

При любом отказе после начала попытки ready=0, cause сохраняет её причину.
Могут остаться изменённые priority, gate или asserted reset. Helper не маскирует
эту ситуацию cleanup, не разрешает retry и не запускает DCD; требуется настоящий
system reset. Нулевой enum cause в ещё не использованном объекте не означает успех.

Одиночные readbacks не измеряют reset pulse или длительность callbacks. Скрытые
transient и остановка CPU при потере HSE не устраняются C-проверками. Физические
pull-up/VBUS, реальные USB reset/attach, enumeration Windows, IRQ priority readback
на MCU, deadlines, общий стек и электрическая безопасность не доказаны.
Результат остаётся draft до независимого вердикта и обязательных доказательств;
конкретные исполненные проверки фиксируются отдельно.

Основания: RM0008 Rev21, RCC APB1ENR/APB1RSTR и EXTI §10.3.6; PM0056 Rev7,
NVIC IPR §4.3.7 (word access); pinned STM32F103xB IRQ/priority definitions.
USB mask `0x00800000`, CAN `0x02000000`, IRQ19–22 `0x00780000`, IRQ42 bank1
`0x00000400`. Новые аппаратные значения платы не назначаются.
