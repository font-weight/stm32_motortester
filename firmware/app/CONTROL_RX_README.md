# RX-001: байтовый вход контроллера

Черновик на базе CTRL-001 PR35 `0ddea1e5992caa6231203838c3956e19675867a8`. Модуль соединяет существующий stream parser с существующим контроллером, не меняя wire v0.1. Для дополнительной составной проверки используется IO-001 PR39 с тем же неизменённым контроллером; ветка RX накладывается на его финальный снимок. USB backend, endpoint/IRQ и полная прошивка в эту задачу не входят.

## Использование

После инициализации контроллера вызвать `mt_control_rx_init` с отдельным статическим объектом привязки. Все объекты, массив входных байтов и выход `consumed` должны быть действительными неперекрывающимися областями. Один последовательный владелец в foreground, без повторного входа из callbacks и без вызовов из IRQ.

`mt_control_rx_feed` принимает не более 64 байт. Размер USB-пакета не определяет границу сообщения: произвольные фрагменты сохраняются в существующем ограниченном накопителе. Вызывающий код дробит большие порции и перед каждым вызовом получает актуальное время из того же истинного миллисекундного счётчика, что используется для контроллера и привязки АЦП.

На допустимом вызове `consumed` всегда означает обработанный префикс. `MT_CONTROL_OK` включает проигнорированные команды и отброшенный некорректный вход; это не подтверждение исполнения команды. Ошибки decoder отражаются в локальных счётчиках, а подтверждение команды определяется её wire-ответом. Если валидная команда приводит к восстановлению, вызов останавливается на её нулевом разделителе и возвращает `MT_CONTROL_RECOVERY`. Остаток входной порции не теряется и не обрабатывается скрыто. Вызывающий код сохраняет этот остаток и передаёт его следующим вызовом; там может оказаться новый HELLO. Нельзя повторно подавать уже обработанный префикс.

Ошибочные аргументы возвращают `MT_CONTROL_ARGUMENT`, вход не потребляется. При доступном отдельном `consumed` туда записывается ноль. NULL вместо байтов разрешён только при нулевой длине; пустая порция выполняет только проверку тайм-аута RX.

## Отказы и состояния

Ошибка framing/CRC/длины/версии/reserved не вызывает контроллер. Старый выходной объект parser никогда не применяется повторно. Переполнение и тайм-аут отбрасывают кандидат до следующего нуля. Это сохраняет действующий wire-контракт: повреждённый вход сам по себе не исполняет команду и не меняет захват. Валидные кадры уже проверяются контроллером по nonce, sequence, request и состоянию.

Проверять `mt_control_rx_poll` надо и при молчании транспорта. Пределы parser неизменны: межбайтовый 1000 мс, общий 3000 мс, сравнение `>=`, корректное переполнение modulo 2^32, интервалы обслуживания меньше 2^31 мс. При получении порции байтов старый незаконченный кандидат сначала проверяется на тайм-аут.

Счётчики rejected_frames/overflows/timeouts локальны, насыщаются на UINT32_MAX и не отправляются как wire-счётчики. Они показывают события parser, а не число потерянных USB-пакетов или команд. Инициализация обнуляет их; явная потеря транспорта сохраняет.

При независимо обнаруженной потере транспорта вызывается `mt_control_rx_transport_lost`: сбрасывается только RX framing и вызывается реальное восстановление контроллера со Stop. Обычная работа возобновляется по новому HELLO. Начатый TX-кадр и занятая память DMA подчиняются прежним правилам контроллера; сброс RX не освобождает их. Возврат RECOVERY не доказывает успешную аппаратную остановку. Физический reset endpoint и доставка байтов ПК вне этого API.

## Ограничение времени и памяти

Ограничение 64 байта ограничивает объём входной работы, но не доказывает её длительность. Кадр на последнем байте может вызвать декодирование полного сообщения и синхронный аппаратный callback. Владелец main loop отдельно обеспечивает сервис АЦП строго чаще 2560 мкс, не блокируется на TX и проверяет время всех путей на плате. Этот модуль не опрашивает АЦП и не передаёт TX.

Привязка содержит собственные stream и decoded message. При интеграции их нельзя второй раз добавлять к модели RAM отдельными объектами, если используется этот owner. Размеры объекта и стека зависят от ABI и проверяются отдельно; успешный native-тест не заменяет ARM link/map.

## Проверка

```sh
sh tests/control-rx/run.sh
```

Авторский набор повторяет исходные регрессии контроллера и проверяет реальные закодированные команды, все разделения CONFIG, ARM/Stop, отсутствие изменения контроллера при отбрасывании, насыщение диагностик, rollover/тайм-аут/переполнение, границу потреблённого префикса при восстановлении и обработку нового HELLO в остатке. Strict C11 и ASan/UBSan выполняются отдельно. LeakSanitizer выключен из-за ограничения ptrace, его результат не заявляется. Лог: `tests/control-rx/evidence/native.log`.

Независимые поддерживающие тесты и Critic-A проверяют отдельные источники и окончательные SHA. До применимых вердиктов это только draft, без merge и без заявления о готовности USB/устройства.

## ARM object и ABI

```sh
TC=/path/to/toolchain/usr sh tests/control-rx/arm-check.sh
```

GCC 14.2.1, Cortex-M3/Thumb, `-Os -ffreestanding -fno-short-enums`: wrapper имеет 296 байт text, без собственных data/bss. Объект SHA-256 `2070737496f4dda694277c8a1786544751a3859bc53d6066a3c8a361e204d8c7`. `sizeof(mt_control_rx)=1128`, `sizeof(mt_control)=8888`. В 1128 уже включены stream 564 и message 544; при их замене в общей модели надо дополнительно учесть выравнивание содержащей структуры.

Кадр `mt_control_rx_feed` — 48 байт. К известной цепочке Stop контроллера 2944 байта он добавляет 48: 2992 байта известных кадров до runtime/caller/IRQ. Это ещё одна причина не назначать стек 2 KiB. Другие кадры wrapper: init 16, poll 8, transport_lost 8. Это статическое свидетельство компилятора, не stack watermark и не измерение времени. Полная RAM/Flash-компоновка с ADC/USB/startup остаётся отдельной проверкой.


Составной авторский `test_rx_io.c` повторяет регистровые проверки IO-001, перенаправляя его команды через реальное кодирование и RX порциями по 7 байт. Это проверяет связку «байтовый вход → контроллер → ADC/DMA-модель → исходные коды → COBS-выход», включая задержку часов, частичный последний блок и устаревший Stop. Исходные тесты IO-001 и драйвера не меняются. Этот тест также выполняется strict и ASan/UBSan через тот же run.sh; он не является независимым ревью или физической USB-передачей.
