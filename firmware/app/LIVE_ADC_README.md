# Черновая композиция ADC/TIME с потоковым endpoint

mt_live_adc связывает настоящие mt_adc_dma, mt_timebase и mt_live_device.
В native-проверке подменяется регистровая шина и транспорт, но не выдача блока
драйвером, не stop snapshot и не обработчик wire-команд. Это ещё не USB runtime,
не startup и не новый образ для платы.

## Владение и запуск

Владелец создаёт статические отдельные объекты драйвера, TIME, endpoint и binding.
Они не перекрываются и живут дольше всех обращений; callback context тоже живёт
до конца работы. Нельзя переинициализировать их при активных ссылках/передачах.
Один foreground-владелец; IRQ не вызывает binding/core и не меняет их поля.
Legacy mt_adc_control одновременно с этим binding не используется.

mt_live_adc_init требует уже инициализированный остановленный/unowned драйвер,
здоровый TIME и полный guarded-start интерфейс, включая timed_allowed.
Он включает stream mode, но не включает RCC gates, не захватывает чужую
периферию и не подтверждает cold hardware-off. Будущий board/startup-владелец
должен обеспечить зарезервированные ADC1/TIM3/DMA1 clocks до первого HELLO.

Start вызывается только callback-обёрткой того же board owner из mt_live_io.
Проверяются STARTING, точное поколение, свежий TIME и canonical profile1.
Сохраняется исходный actor/epoch через переданный timed guard. Успех возвращается
только после настоящего driver start и последующей проверки TIME. Отказ после
частичного enable означает, что endpoint обязан выполнить cleanup; он это делает.
Наличие интерфейса guard не доказывает реализацию правильного USB actor в будущем
runtime: её требуется проверить отдельно.

## Один блок и остановка

mt_live_adc_service читает максимум один реальный блок драйвера. Перед и после
read проверяется TIME. При BLOCK выполняется немедленный синхронный offer в
очередь endpoint, до следующего read/start/stop. Отказ offer может тут же вызвать
quiesce; после него старый driver view не используется. EMPTY не создаёт данных,
ошибка чтения не заменяется нулями. Caller обеспечивает epoch admission и
независимое обслуживание TIME/endpoint, включая периоды без RX/TX.

Quiesce сначала переносит внешний clock fault в историю драйвера, затем получает
настоящий stop snapshot и вновь проверяет TIME. Устойчивый хвост разбивается на
0–2 wire-блока, только последний может быть коротким. Исходные коды копируются
в выходной снимок; указатели на ring/driver view наружу не передаются.
stop_scratch находится внутри статического binding и убирает дополнительный
544-байтный автоматический массив из вложенного стека callback.

В этой первой композиции produced_known всегда 0, produced_end всегда 0.
Известная граница DMA не объявляется доказанной границей всех ADC-преобразований.
Поэтому даже обычная остановка выдаёт END с unknown/incomplete; подтверждение
STOP_ACK доказывает только предусмотренное программным контрактом завершение
и подтверждённый off, а не lossless acquisition. Это ограничение должно быть
видимым в приложении; не переименовывать такой результат в полную чистую запись.

Драйверный first_fault отображается в wire reason отдельно от hardware_off.
Переданный в endpoint уже наблюдённый acquisition fault фиксируется до следующей
проверки часов. Причина из stop snapshot тоже фиксируется до post-quiesce clock.
Raw recovery сохраняет допустимую причину, но не принимает cached tail повторно.
Успешный новый HELLO очищает историю старого сеанса только при финальном commit.

## Проверки и пределы

Композиционный рецепт после интеграции тестов находится в tests/live-adc/.
Отдельно повторяются прежние native endpoint, actual C↔HOST и stream-clock
проверки на исправленных зависимостях. Manifest clock-теста явно обновляется,
а ранний PASS отдельного модуля не выдаётся за вердикт всей композиции.

Будущему stream-only runtime ещё нужны USB lifecycle/actor admission,
изоляция writer, сохранение принятого префикса, fairness IRQ и подтверждение
полной длительности TX-транзакции. Требование ADC service <2560 мкс остаётся
аппаратным обязательством; один read за шаг не доказывает этот интервал.
Native регистровая модель не квалифицирует реальный off, ADC drain, MCU/кварц,
DMA/USB под нагрузкой, ARM map/stack, Windows COM или сигнал.
