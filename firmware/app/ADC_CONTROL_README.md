# IO-001: связь АЦП/DMA с контроллером команд

Статус: черновик. База контроллера — PR35 `0ddea1e5992caa6231203838c3956e19675867a8`; драйвера — PR27 `5215177100453c6f77e5c5a637197fd626e57aec`. Независимая приёмка, полный образ прошивки, USB и измерения на плате пока отсутствуют. Новые файлы не превращают эти зависимости в принятые модули.

## Порядок вызовов

1. Зарезервировать ADC1/PA0, TIM3, DMA1 channel1 за этим трактом. Настроить и проверить частоты вне этого модуля. Передать драйверу реальную номинальную частоту HSE, если она используется; значение по названию платы не угадывать.
2. Статически разместить отдельные неперекрывающиеся объекты `mt_adc_dma_t`, `mt_control`, `mt_adc_control` в SRAM. Инициализировать драйвер с MMIO и часами. Не переинициализировать объекты до подтверждённой остановки периферии. При ошибке Stop память DMA остаётся занятой и должна жить дальше.
3. Вызвать `mt_adc_control_init` один раз до обработки команд. Он связывает объекты и сбрасывает программное состояние контроллера, не выполняя MMIO. Исходная периферия должна быть неактивна; исключительное владение обеспечивается вызывающим кодом.
4. Подавать только проверенные `mt_wire_decode` сообщения в `mt_control_receive`. Фрейминг, тайм-ауты RX и USB пока вне этого модуля. HELLO проверяет остановку и профиль; CONFIG/ARM сохраняют порядок контроллера. Старый STOP с неверным поколением не вызывает MMIO.
5. Во время захвата вызывать `mt_adc_control_service` с интервалом строго меньше 2560 мкс, учитывая также время копирования, разбора RX, обработки блока и TX. За вызов обрабатывается не более 128 кодов. Между блоками драйвер также надо обслуживать: вызов только по окончании очередного блока уже не удовлетворяет строгому бюджету.
6. Вызывать `mt_control_poll` с настоящим текущим временем и ограниченным неблокирующим выводом. После замораживания окна драйвер останавливается, оставшаяся часть снимка блока не читается. Освобождение корректного окна запускает следующий захват только по правилам режима.

Все операции выполняет один последовательный владелец в foreground; ISR не вызывает эти API. При ошибке драйвера включается восстановление контроллера: обычные команды и вывод заблокированы до нового HELLO, остановка повторяется. Успех Stop нельзя подменять освобождением памяти или только программным флагом.

## Проверка профиля

`mt_adc_dma_profile1_ready` читает регистры и обновляет только кэш параметров частоты. Он не пишет MMIO и не запускает АЦП. Требуются остановленный незанятый драйвер, неактивные ADC/TIM/DMA, TIM=72 МГц, PSC=71, ARR=19 и ADC=12 МГц. Сам драйвер при запуске программирует PA0, ADC sample time=71.5 цикла и период 20 мкс. Иные поддерживаемые отдельно драйвером частоты не принимаются как профиль приложения 1.

Повторная проверка после запуска не позволяет продолжить захват с изменившимся профилем. Изменение RCC во время работы проверяется драйвером. Эта проверка номинальных делителей не является измерением Fs.

## Время отсчётов

Нельзя назначать отсчётам время чтения заполненного DMA-блока: оно зависит от задержки foreground. Привязка использует индекс отсчёта от начала текущего запуска, период 20 мкс и нижнюю границу чтений часов вокруг записи CEN. Первый отсчёт соответствует первому обновлению таймера через один период.

`now_ms` и `now_us` должны описывать один монотонный ход времени. Все аргументы времени в `mt_control_receive` и `mt_control_poll` берутся из того же настоящего миллисекундного счётчика, который передан привязке; callbacks выполняются быстро и последовательно. Оба счётчика имеют собственное корректное переполнение modulo 2^32. Получать `now_ms` делением уже переполняющегося 32-битного `now_us` на 1000 нельзя: через примерно 71 минуту такой «миллисекундный» счётчик прыгает неверно. Реализацию часов предоставляет startup/платформенный код, которого здесь ещё нет.

В момент запуска чтение эпохи миллисекунд заключено между двумя чтениями микросекунд. Если разность показаний больше 20 микросекундных тактов, запуск отклоняется до обращения к старту драйвера. Нижняя граница этой пары используется для задержки калибровки до CEN; это ограничивает, но не устраняет неопределённость корреляции. При квантовании часов до 1 мкс реальный интервал может приближаться к 21 мкс; дополнительно сохраняется квантование миллисекунд. Это не гарантированно более ранняя оценка физической апертуры: на границе миллисекунды округлённая отметка может перейти в следующий миллисекундный интервал. Сохраняются эпоха миллисекунд и эта задержка; затем время вычисляется из индекса без 64-битного деления. Времена номинальные: квантование чтений часов, корреляция ms/us, длительность записи CEN, апертура АЦП и фактическая частота генератора требуют аппаратного измерения. Миллисекундная отметка нужна автомату состояний; шаг оси окна задаётся профилем, а не этой округлённой отметкой.

## Воспроизведение

Из корня дерева:

```sh
sh tests/adc-control/run.sh
sh tests/control/run.sh
```

Первый сценарий включает исходные регистровые проверки драйвера, проверку профиля без MMIO-записей, составной путь «регистровая модель → драйвер → контроллер → COBS», все 2048 исходных кодов и CRC, остановку на частичном последнем блоке, переполнение часов, старый Stop и DMA transfer error. Второй повторяет тесты контроллера. Выполняются строгая C11-сборка и ASan/UBSan. LeakSanitizer отключён, поскольку он несовместим с ptrace данного исполнителя; это не означает проведённую проверку утечек.

Авторский тест переиспользует модель регистров драйвера и не является независимым аппаратным стендом. Сохранённый лог — `tests/adc-control/evidence/native.log`. Поддерживающий независимый тест, независимое ревью и ресурсный расчёт ARM оформляются отдельно. Нужны полный link/map, startup, реальный USB, подтверждение временного бюджета и низковольтные измерения; до них нельзя утверждать готовность прибора.

## Предварительные ресурсы Cortex-M3

На финальных C/H с ограничением корреляции часов две строгие сборки GCC 14.2.1 для Cortex-M3/Thumb с `-fno-short-enums` дали одинаковый relocatable object: SHA-256 `ae149ec3c091cf67d7ba3a94b5b3f16d2905b8b772f721ff106cf1957a9a9e2b`. Суммарно `.text`/`.rodata` модулей — 11 281 байт; привязка — 438 байт. Неопределены только стандартные функции memcmp/memcpy/memmove/memset, реализация которых ещё должна попасть в конечный link.

Модель владельца занимает 10 880 байт: один контроллер 8 888, драйвер 860, привязка 24, RX stream 564 и RX message 544. В контроллер уже входят TX/сеанс/окно; повторно складывать их нельзя. Наибольшая найденная сумма известных стековых кадров — 2 944 байта (receive → link Stop → TX Stop → append), без libc, вызывающего кода и IRQ. Стек 2 KiB для этой цепочки недостаточен.

Арифметический остаток от 20 KiB SRAM после модели владельца и этой цепочки — 6 656 байт. Это не доказанный свободный запас: startup, USB, прочие globals, стек прерываний/вложенность, runtime и итоговая раскладка ещё не учтены. Object-сборка не является полной прошивкой и не подтверждает размещение по linker map.
