# INT-001: передача замороженного окна (черновик)

Модуль связывает программный захват acquisition с ограниченной очередью mt_tx.
Это не полная прошивка: USB, обработчик команд, драйвер периферии и реальные
измерения здесь не реализованы. Зависимости ещё не приняты общим quality gate.

## Ответственность вызывающего кода

- Один последовательный владелец; вызовы из прерываний и перекрывающиеся аргументы запрещены.
- Сначала проверить HELLO, session, sequence, request и payload штатными парсерами.
  После нового HELLO синхронно остановить оборудование и вызвать init после
  mt_tx_hello. Хвост старого кадра может допередаваться, его события игнорируются.
  Смена nonce без init приводит к RECOVERY.
- До CONFIG/ARM_ACK проверить все параметры, идентификаторы и состояние.
  Только после успешной предварительной проверки допустить именно успешный ACK
  в очередь и без промежуточного изменения состояния выполнить переход.
  Нельзя выдавать успешный ACK для вызова, который затем вернёт BUSY/STALE.
  config_id/generation задаёт внешний диспетчер по общему контракту.
  Link не заменяет проверки уникальности request/generation.
- Пока link активен, вызывать mt_tx_poll только через mt_capture_link_poll.
  Backend обязан безвозвратно принять упорядоченный префикс байтов, а не сохранить
  его в очереди, которую затем можно молча очистить. ACK означает принятие байтов
  транспортом, не доказательство получения ПК.
- Время sample_ms относится к моменту выборки, а не позднему чтению DMA.
  При WINDOW_READY остановить таймер/АЦП/DMA. Для Stop сначала проверить целевую generation и состояние, не останавливая
  оборудование при чужой generation. Затем успешно остановить оборудование
  до вызова link Stop и допуска STOP_ACK. Отказ аппаратной остановки требует
  восстановления без успешного STOP_ACK. При новом HELLO аппаратная остановка
  также должна завершиться до сброса link. Все RECOVERY требуют
  остановки периферии и восстановления сеанса, ERROR формирует диспетчер.
- Только analog source и profile1: 2048 кодов, номинально 50 kS/s. BEGIN сообщает
  проектные TIM=72 MHz, PSC=71, ARR=19. Диспетчер разрешает этот профиль только
  после подтверждения именно этой настройки драйвера. Это не измеренная Fs.
  Внешние события не реализованы; их счётчики в STOPPED STATUS равны нулю.

## Передача и освобождение

После полного захвата буфер неизменяем. По одному кадру на poll добавляются
BEGIN, девять DATA (до250 кодов каждый), END. Исходные коды сериализуются little-endian;
CRC считается по тем же4096 байтам. Переполнение очереди не продвигает offset/CRC.
Один poll делает не более одного backend write длиной до64 байтов.

После полной передачи END ожидается RELEASE до5000 ms. Проверка срока выполняется
и в poll, и непосредственно в release. Верный RELEASE сначала допускает ACK,
потом разрешает Auto/Normal новую подготовку; Single останавливается. Ошибочные
id/CRC не освобождают буфер. Tombstone последнего committed END отвечает на поздний
или повторный RELEASE без повторного запуска, в том числе после Stop.

Stop до первого байта END отменяет выделенное окно: один ABORT, STOP_ACK, STATUS.
После первого байта END завершается END, затем ACK/STATUS без ABORT. Без выделенного
окна ABORT не создаётся. Счётчик dropped_windows увеличивается только при отмене
нетерминального окна и не оборачивается. Барьер снимается после полного STOP_ACK;
отложенный STATUS может ещё находиться в очереди. Старый ACK другого nonce
не снимает барьер нового сеанса (исправление CA-TX-1 в mt_tx).

## Доказательства и пределы

Из корня кандидата: `bash tests/app/run.sh`. Журнал: tests/app/evidence/native.log.
Строгая C11-сборка и ASan/UBSan проверяют20 последовательных полных окон,
Stop до/после END, tombstone, Single/Auto и сроки. LeakSanitizer отключён из-за
ограничения среды; это не проверка утечек. Независимые44 окна/24 группы сценариев
хранятся отдельно вместе с исходными воспроизводителями трёх исправленных дефектов.

ARM объект собирается Cortex-M3 GCC14.2.1 с -fno-short-enums. Это объектная проверка,
не связанная прошивка. Учесть стек Stop (три сообщения), буфер acquisition,
контекст TX, DMA, USB и стек вызовов в общей карте памяти. Полный linker map,
USB/Windows путь и20 реальных LV-окон остаются открытыми.
