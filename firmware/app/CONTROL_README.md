# CTRL-001: диспетчер команд (черновик)

mt_control связывает проверенный decoded кадр, guard сеанса, разбор команд,
захват и ограниченную очередь TX. Это программный контроллер с обязательными
аппаратными callback-функциями, не реализация USB или готовая прошивка платы.

## Граница ответственности

Сначала вызвать init с отдельным, неперекрывающимся io. До успешного init остальные
API использовать нельзя. Вход receive должен пройти mt_wire_decode; накопление
байтов, межбайтовые сроки, ошибка версии и физическое USB отключение обслуживаются
внешним адаптером. Все операции выполняются одним foreground-владельцем.
При фатальном отказе внешнего адаптера вызвать recover.

profile_ready подтверждает именно TIM72MHz, PSC71, ARR19, ADC12MHz/71,5 cycles,
PA0 и выделенную периферию. Предположение о 50kS/s само по себе недостаточно.
Низкоуровневые варианты backend24/48MHz сюда не допускаются. Проверка выполняется
при HELLO, ARM и возобновлении после RELEASE. Калибровка/параметры драйвера должны
соответствовать его собственному контракту; измеренная частота остаётся отдельным
свидетельством. Все callbacks ограничены по времени и возвращают1 только при
подтверждённом успехе. Start не вызывается для неверного ARM.

Stop чужой generation возвращает ERROR/STALE_GENERATION без аппаратных действий.
Для действительного Stop сначала требуется успешный hardware.stop, затем очередь
terminal/ACK/STATUS. При отказе оборудования успешный ACK не выдаётся. Recover
повторяет аппаратную остановку, запрещает обычные команды и TX до свежего HELLO;
даже при отказе Stop контекст DMA и его буфер должны оставаться живыми.

Сначала проверяются состояние и параметры CONFIG/ARM; затем допускается правильный
ответ в очередь, затем производится переход без промежуточной гонки. Если start
после допуска ARM_ACK отказал, дальнейший вывод блокируется: не начатый ACK удалит
новый HELLO. Старый частично переданный кадр сохраняется до восстановления;
неудачный вызов не выдается за успешный запуск.

## Поддерживаемые сообщения

HELLO, GET_CAPS, CONFIG, ARM, STOP, GET_STATUS, RELEASE_WINDOW. Объявляются только
аналоговый запуск, Auto/Normal/Single, оба фронта и предыстория0/512/1024.
config_id начинается с1; generation равна request_id успешного ARM. Повторы
не выполняются повторно. Настройки/счётчики сбрасывает новый nonce, не повторный
HELLO с тем же nonce.

Оригинальные отсчёты идут через mt_capture_link. При полном окне оборудование
останавливается до дальнейшей передачи. RELEASE запускает оборудование повторно
только при освобождении текущего WAIT_RELEASE окна в Auto/Normal. Ответ на старый
tombstone, в том числе во время передачи следующего окна, не перезапускает АЦП.

До8 ожидающих изменений STATUS хранятся компактно. Перед GET_STATUS и успешным
изменением состояния более ранние статусы ставятся в TX, чтобы старый
WAIT_RELEASE/PREPARING не пришёл после актуального ответа. Отказы ERROR и
неизменяющие состояние GET_CAPS/повтор RELEASE используют резерв ответа напрямую:
чужой STOP не должен из-за очереди наблюдательных статусов останавливать захват. Если предыдущие события и обязательный ответ нельзя допустить
в ограниченную очередь, выполняется fail-closed recovery без обгона и без нового
действия. STOP отменяет устаревшие неначатые события согласно контракту и сохраняет
порядок terminal → ACK → STOPPED. Это ограниченная очередь, не обещание отсутствия
backpressure при произвольном потоке команд; требуется регулярный poll.

## Проверки и ограничения

`bash tests/control/run.sh` запускает авторские strict C11 и ASan/UBSan проверки.
Проверяются20 полных синтетических окон через настоящее кодирование/декодирование
COBS и CRC, отсутствие hardware.stop при чужой generation, неверный ARM, отказы
start/stop и восстановление с новым HELLO. Независимый набор и Critic-A проверяют
более широкие перестановки сообщений; их отчёт привязывается к конкретным SHA.
LeakSanitizer отключён; тесты не являются USB/Windows/аппаратными измерениями.

Не использовать прежнее предположение о стеке2KiB: цепочка receive→link Stop→TX
уже превышает его ещё до библиотек и прерываний. Окончательный linker map, WCET,
ISR/stack watermarks, слой stream/USB/ADC-adapter и20 настоящих LV-окон пока отсутствуют.
Контроллер остаётся draft до независимых заключений и применимых доказательств.
