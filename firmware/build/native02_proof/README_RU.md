# Повторение черновика доказательства

Сначала прочитайте THEOREM_RU.md. Это проверка точной пары образов и внешней
условной леммы, а не новый production image gate. Обычный build_image.py
по-прежнему отклоняет текущие native0.2 objects. Прошивка на плату запрещена
самим назначением этих синтетических артефактов.

Нужны:

-33 старых объекта по неизменному stack_reference.json, повторённые старой
рецептурой на main c4d4dc2966656b324518c8d0061811d1241870a3;
-33 новых объекта по inputs.json текущего cleanup, включая .su для пяти
затронутых C translation units;
- старый квалифицированный synthetic ELF/map и соответствующий board.o;
- новый строго скомпонованный, но неквалифицированный ELF/map с резервом3104,
теми же linker script, порядком33 объектов и synthetic board.o;
- точное тело публичного исходного review, проверяемое по SHA256;
- закреплённый arm-none-eabi-objdump и обычный Python3.

Хеши двух ELF, объектов, инструментов, исходников, helper-файлов и внешней
леммы заданы inputs.json. Входы наблюдаются также после выполнения. Пути
должны быть абсолютными, нормализованными, без symlinks. Каталог результата
должен отсутствовать. Не заменяйте входные хеши для получения успешного
ответа: новый предмет требует нового доказательства и независимого review.

Пример с заранее подготовленными абсолютными переменными путей:

    python3 -I -B firmware/build/native02_proof/verify.py \
      --old-objects "$OLD_OBJECTS" --new-objects "$NEW_OBJECTS" \
      --old-elf "$OLD_ELF" --old-map "$OLD_MAP" \
      --new-elf "$NEW_ELF" --new-map "$NEW_MAP" \
      --board-object "$BOARD_OBJECT" --old-review "$OLD_REVIEW" \
      --objdump "$OBJDUMP" --out "$FRESH_OUTPUT"

Map должен называть именно переданные файлы объектов. Для другого размещения
каталогов нужно заново получить map обычным линкером с теми же входами;
произвольная перепись доказательств не допускается. Вариации board-data в этой
узкой паре не разрешены. Их проверка относится к следующей стадии image gate.

Семантические контроли без зависимости от внешних object paths:

    python3 -I -B firmware/build/native02_proof/test_semantics.py
    python3 -I -B -O firmware/build/native02_proof/test_semantics.py

Контроли проверяют допустимую проекцию ARM/record-now и отказ при неизвестном
узле/ребре, reentry, лишнем стягиваемом ребре, изменении callback target/context/
now/base, неверном типе branch relocation. Они обходят внешний hash gate,
проверяя непосредственно соответствующие семантические функции. Это не весь
набор обязательных независимых негативных проверок машинного доказательства.

Результат DRAFT_INCREMENTAL_PROOF_REPLAY_PASS сохраняет все флаги принятия,
переноса стека, аппаратной проверки и flashing в false. В RESULTS.json есть
команды, входные SHA, локальные кадры, проекция и relocation evidence. Ручные
конечные обязательства из THEOREM_RU.md нельзя заменить этим JSON.
