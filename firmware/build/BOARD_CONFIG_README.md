# Явное описание платы: data-only генератор

Локальный draft. Независимое ревью data-only генератора завершено;
приёмка всего дерева и аппаратные доказательства остаются открытыми. Генератор проверяет формат
входных данных и создаёт одну C translation unit с `const mt_board_inputs
mt_board`. Он не измеряет плату, не компилирует, не линкует, не выбирает стек
и не выпускает образ для прошивки.

## Что требуется от входа

Все поля заданы явно в `board-input.schema.json`; значений по умолчанию нет.
Python-проверка дополнительно запрещает duplicate keys, floats, NaN/Infinity,
boolean вместо integer, неизвестные поля, неправильные BCD nibbles и ввод
длиннее 8192 bytes. UTF-8 обязателен. JSON schema служит описанием; штатный
entry point выполняет полную семантическую проверку без сторонних библиотек.

- HSE: только частоты, дающие точные 72 МГц для текущего planner; режим
  crystal/bypass задан явно. Poll budget — число ограниченных чтений, не ms.
- IRQ priority 0..15; build ID uint32; require_dtr 0/1.
- Поддерживается только фиксированный pull-up (`verified_fixed_pullup=1`).
  Название поля и это число не доказывают топологию физической платы.
- VID 1..65534, PID 0..65535, четырёхзначный BCD device revision; USB bus power
  2..500 мА с шагом 2. Это формат и заявленный бюджет, не измерение потребления.
- Manufacturer/product: 1..31 печатных ASCII-символов; serial: 1..31 ASCII
  букв/цифр. Физическая уникальность и постоянство serial проверяются отдельно.

`input_kind=caller_board` требует все шесть `caller_attestations=true`.
Это утверждения предоставившего данные, не заключение программы: MCU/память,
HSE/режим, pull-up, USB power, право на VID/PID, физический serial.
Нельзя проставлять true только ради прохождения генератора.

`input_kind=synthetic_fixture` требует все шесть attestations=false.
Синтетические значения предназначены исключительно для теста программы;
они не являются назначением параметров пользователю или USB-идентичности.
Генератор не содержит готового паспорта или заполненного production-примера.
Для проверки самого инструмента поставлен
[искусственный NEVER_FLASH fixture](examples/SYNTHETIC_NEVER_FLASH.json);
его значения не описывают Blue Pill и не разрешают подключение устройства.

## Основания для заполнения

Паспорт экземпляра остаётся в [HW-001A](../../docs/hardware.md), физические
критерии — в [validation](../../docs/validation.md). Здесь связываются только
поля JSON и необходимые основания. Диапазон валидатора не рекомендует
значение и не подтверждает физическое свойство.

| Поле | Основание, которое сохраняют вне JSON |
|---|---|
| `schema_version`, `input_kind` | Версия формата и реальное происхождение входа: данные экземпляра либо искусственный тест. |
| `verified_hse_hz`, `hse_mode` | Связанные с экземпляром сведения об источнике, номинале и crystal/bypass; отдельно статус проверки фактической точности частоты. Допуск planner не измеряет HSE. |
| `verified_fixed_pullup` | Подтверждение фиксированной USB pull-up топологии конкретной платы. Число 1 не управляет резистором и не заменяет проверку. |
| `usb.bus_power_ma` | Обоснованный бюджет USB-потребления для указанного питания/конфигурации, охваченные условия и ограничения. Это значение дескриптора, не измеритель тока. |
| `usb.vid`, `usb.pid` | Проверяемое основание права использовать именно эту пару для проекта и назначения. Чужой пример, STM32 или успешная сборка не дают такого права. |
| `usb.serial` | Связь строки с физическим экземпляром, правило стабильности и предотвращения дубликатов. Генератор не читает MCU UID и не проверяет реестр. |
| `clock_poll_budget` | Решение интегратора о числе чтений для каждого ожидания startup, его обоснование и отдельно статус проверки времени; не ms. |
| `usb_irq_priority` | Программная политика одного логического приоритета обоих USB IRQ с учётом предпосылок IRQ/стека; не измерение обслуживания. |
| `firmware_build` | Назначенный uint32 и связь с версией исходников/сборки; не идентификатор физической платы. |
| `require_dtr` | Явная политика допуска CDC, согласованная с ПК-стороной; не свойство модели платы. |
| `usb.bcd_device`, `usb.manufacturer`, `usb.product` | Выбранные версия и описательные строки ПО/устройства. Они не доказывают производителя MCU или право на USB ID. |

Все поля таблицы, кроме первых двух, находятся внутри `board`.
Assertion `physical_mcu_and_memory` ссылается на паспорт экземпляра и
применимые подтверждающие материалы; отдельных Flash/SRAM полей в JSON нет.
Геометрия linker script не обнаруживает память платы. Остальные assertions
соответствуют HSE/режиму, pull-up, USB power, праву на VID/PID и serial из
таблицы. Даже шесть true — только наличие утверждений: parser не открывает
их основания, не устанавливает авторство и не проверяет аппаратную часть.

Краткая запись основания: поле; значение или TBD; экземпляр/версия ПО;
факт/решение/синтетика; источник; кто и когда подтвердил; что не проверено.
Паспорт и решения связывают с SHA-256 фактически переданного JSON.
Основания, комментарии и TBD хранят вне строгого JSON: лишние поля и null
запрещены. Строка `TBD`, даже синтаксически допустимая, остаётся заглушкой.

Частично неизвестная реальная плата не становится подтверждённой через
false assertions или смену `input_kind`. Пока оснований нет, паспорт остаётся
неполным. Синтетические тесты сохраняют все false и тестовое назначение.
Reserve/margin — отдельные входы [полного recipe](BUILD_IMAGE_README.md),
не поля board JSON; синтетические 3024/0 не выбирают запас реальной плате.
Эта передача не является инструкцией включения, подключения или прошивки.

## Запуск

```sh
python3 -I -B firmware/build/board_config.py \
  --input /absolute/input-folder/board.json \
  --out /absolute/existing-parent/new-generated-board
```

Используйте канонические абсолютные input/output пути без symlink, `..`, `.`,
лишних разделителей, перевода строки и символов : # $ обратной косой черты,
кавычек или апострофа. Output должен отсутствовать, его родитель существовать;
пересечение с исходниками генератора, input-файлом и Python запрещено.
Работа рассчитана на стабильную кооперативную файловую систему, не на
противодействие одновременной злонамеренной подмене файлов.

Валидируется весь JSON до создания output. Строки в C представлены массивами
числовых ASCII bytes с завершающим нулём: кавычки и обратная косая черта внутри
допустимых manufacturer/product не превращаются в код. Нет функций,
конструкторов, динамического выделения или произвольного C от пользователя.

Создаются `TEST_ONLY_mt_board.c` либо `CALLER_ASSERTED_mt_board.c`, а также
`RESULTS.json` с input/source/generator hashes, типом входа и attestations.
Во всех случаях hardware_verified и flash_approved равны false.
Предварительный отказ не создаёт output; начатые неудачные результаты
сохраняются и не перезаписываются. Для нового запуска нужен новый каталог.

Импортируемые функции являются внутренними деталями инструмента. `generate`
получает только успешный результат `parse_board`; публичный способ применения —
CLI выше. Изменение C/H контракта требует повторной сверки схемы/валидатора.

## От генератора к образу

Отдельный локальный [static-link/export recipe](BUILD_IMAGE_README.md)
связывает pinned objects, явный board input, инструменты и reserve/margin,
проверяет BOOT/ELF/map и условную оценку стека, затем BIN/HEX bytes.
Генератор сам по-прежнему выполняет только свою data-only задачу.
Геометрия linker, caller assertions и успешный рецепт не заменяют
инженерный запас, USB identity или аппаратную проверку. Во всех результатах
hardware_verified=false и flash_approved=false; физический допуск открыт.
