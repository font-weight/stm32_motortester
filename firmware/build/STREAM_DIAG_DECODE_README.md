# Офлайн-разбор диагностической записи STREAM

Черновой инструмент для ABI v1: ровно 136 байт (34 little-endian uint32) из
mt_stream_diagnostics. Программа не подключается к плате, не прошивает её,
не запускает измерение и не читает COM-порт.

Вход: два сохранённых бинарных дампа одного frozen record и ожидаемые build,
generation, nonce из отдельно проверенных образа и журнала попытки. Требуется
Python 3.10+. CLI использует только стандартную библиотеку. Реальная работа
на Windows проверяется отдельно; Linux-тесты не доказывают Windows-готовность.

Пример формы команды, НЕ команда чтения памяти платы:

```
python decode_stream_diag.py first.bin second.bin --build BUILD --generation GENERATION --nonce NONCE
```

Заменять параметры нужно точными значениями опыта; поддержаны десятичные числа
или префикс 0x. Приём CLI ограничивает build до uint32, generation до ненулевого
uint32, nonce до ненулевого uint64. Не подставлять синтетическую identity.

Вывод — JSON в stdout; исходные файлы не изменяются. Exit 0 означает только
согласованный frozen record с ожидаемой identity. Exit 2 означает ошибку чтения,
аргументов или записи. При structural validation failure JSON сохраняет raw
поля и перечень errors, если удалось прочитать правильный размер. При ошибке
открытия argparse выводит сообщение в stderr. Для неверного размера SHA-256
не выдаётся: ограниченное чтение не является хешем всего oversized файла.

accepted_frozen_record НЕ означает успех измерения. Проверяйте warnings,
normal_stop_record_shape, исходный HOST журнал END/STOP_ACK и проверку прошивки.
При first_fault, saturation, replacement HELLO или invalid DWT запись остаётся
полезным свидетельством ограниченного/неуспешного опыта. Флаги physical_identity_verified
и timing_qualified всегда false. Переданные ожидания и совпавшие файлы не
доказывают, какой образ действительно записан в плату.

Поля raw — исходные uint32 без изменения; UINT32_MAX сохраняется как число,
в соответствующих result-полях это unknown sentinel. Полный nonce выведен
также строкой hex, чтобы избежать потери точности uint64 в JSON-потребителе.
Неупражнённые метрики выведены null; raw maxima сохранены. Интервал между polls
требует хотя бы двух наблюдений. Количество копий включает впоследствии
отвергнутые copy/validation attempts.

Циклы не переводятся в секунды; wrap разрешён, но полный оборот или debugger halt
по этому файлу установить нельзя. TX bracket не равен qualified transaction
или точному IRQ-off интервалу. Нулевые/малые максимумы не доказывают WCET.

Читаются только обычные локальные файлы; конечные symlink/FIFO/device/directory
отвергаются. На платформах с O_NOFOLLOW/O_NONBLOCK используются эти флаги,
проверяется открытый inode и изменение size/mtime во время чтения. Это не
защита от враждебной конкурентной файловой системы и не обещание ограничения
времени чтения недоступного сетевого диска. Сначала сохраните дампы локально.

До выдачи владельцу нужны отдельная привязка к окончательному ELF/адресу,
точная инструкция безопасного получения дампов и самостоятельный HOST collector.
Синтетические адреса и NEVER_FLASH ELF не являются разрешением прошивки.
