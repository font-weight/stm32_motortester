# INT-001: воспроизведение независимых проверок

Это выбранные текстовые материалы независимого испытателя для issue #18.
`REPORT.md`, harness, исходные журналы и hash-файлы сохранены без изменения.
Отчёт является дополнительным свидетельством, а не итоговым вердиктом Critic-A.
Зависимости остаются UNACCEPTED; аппаратные измерения не выполнялись.

## Запуск на опубликованном checkout

Нужны GCC с ASan/UBSan, Python 3 и POSIX shell. Из корня checkout:

```sh
ROOT=$(pwd)
SOURCE="$ROOT" sh tests/app/independent/run.sh
SOURCE="$ROOT" sh tests/app/independent/run-sanitized.sh
```

SOURCE должен быть абсолютным путём: скрипты переходят в свой каталог.
Каждый запуск проверяет 24 группы, включая 44 полных окна. Библиотеки
`test_link.so` и `test_link_sanitized.so` создаются локально при запуске;
они не входят в публикацию. LeakSanitizer отключён, как описано в отчёте.

`REPORT.md` описывает исторический рабочий каталог испытателя. Его команды
без SOURCE используют `fixed-snapshot`, а воспроизведение прежних дефектов
использует `revised-session-snapshot`. Эти копии исходников здесь не дублируются:
для текущего кандидата используйте команды выше. Исторические failure logs и
`revised-session-sha256.txt` показывают прежние результаты, но не заменяют
воспроизводимый checkout той старой реализации. `initial-tests.log` с прежними
ошибками harness и `complete-initial-tests.log` не включены в эту выборку.

## Идентичность источников и границы

- Единственный родитель: исправленный TX PR #19,
  `826bef255362b258d5dcde2100c90dc7d591edb3`.
- Шесть файлов `firmware/acquisition/**` и `tests/acquisition/**` импортированы
  точными blob из PR #16, `11f63ebb12fb9fb45cfcc1735782dd5405bf331b`.
- Только `protocol/wire-v0.1.md` импортирован точным blob
  `c62e6fa14062596abd0b1ed013f4f8fdcb43e373` из PR #14,
  `c54bd955aaf3cb863ef3df043ea237ea62e74ad4`: актуальная формулировка
  `external_edge_id` заменяет более старую формулировку базы PR #19.
  Это зависимость общего непринятого контракта, не новое решение этой публикации.
- Исполняемый link C совпадает с независимым final snapshot:
  `f01beedd3c77e4373a7e6778b5551e8e82f4b70b378ae0ec70991c75dda272bd`.
- После независимого отчёта автор уточнил только комментарии header и README:
  предварительная проверка CONFIG/ARM перед успешным ACK; проверка Stop target
  до аппаратной остановки; успешная аппаратная остановка до link Stop/ACK.
  Новый header SHA-256:
  `df48006feed3e470dc09a06c57d1c56db90fdcd08ef3f3a7b4996b33a3a97ccf`.
  Поэтому header hash в неизменённом историческом `fixed-sha256.txt` отличается.
  Исходные C, declarations и layout этим уточнением не менялись.

`test-artifact-sha256.txt` проверяется из этого каталога командой
`sha256sum -c test-artifact-sha256.txt`. Он связывает исходный отчёт, harness
и два исходных итоговых журнала. Для текущих исходников опубликован отдельный
`publication-source-sha256.txt`, проверяемый из корня checkout.

Публикующий проверил текущую сборку повторно после уточнения комментариев:
авторские 20 полных окон в strict и ASan/UBSan; независимые 24 группы / 44 окна
в strict и ASan/UBSan; acquisition 153 сценария в strict и UBSan; TX 14 suites.
Повторные журналы имеют префикс `publication-`; авторские журналы не заменены.

ADC backend и верхний диспетчер здесь не интегрированы. Профиль 1 допускается
только после подтверждения настройки TIM=72 MHz, PSC=71, ARR=19; 50 kS/s
является номинальной конфигурацией, не измеренной частотой. USB, Windows,
полный ARM linker map и реальные LV-окна остаются вне этих native проверок.
