# Регрессия MMIO-порядка при inline TIME helpers

Проверка только программной эквивалентности `mt_timebase.c` при принудительном
inline пяти внутренних helpers. Условия чтений, fault, предел 32000, владение
TIM2 и временные шкалы должны остаться прежними. Это не измерение быстродействия
MCU, не доказательство WCET/IRQ и не аппаратная приёмка.

Из корня исходного дерева, включая распакованный ZIP без `.git`:

```sh
OUT=/tmp/motortester-timebase-inline-tests sh tests/timebase-inline/run.sh
```

Раннер выполняет strict C11 `-O2`, затем ASan/UBSan `-O1` и сравнивает их полные
транскрипты. LeakSanitizer отключён, проверка утечек не заявляется. Результаты
создаются только в `OUT`.

`test_trace.c` включает существующий `tests/coherent-clock/test_snapshot.c`,
который сам повторно использует `tests/timebase/test_timebase.c`. Поэтому
сохраняются одна регистровая модель, прежний набор TIME и весь набор согласованных
временных пар: CNT16/us32/ms32 rollover, независимый uint64 oracle, 32000/32001,
недействительные аргументы, sticky faults, модель preemption и демонстрация
необнаружимого alias пропущенного полного оборота. Единственное изменение
существующего coherent-теста — переименовываемая точка входа для включения.

Дополнительный независимый oracle задаёт буквальные адреса/значения MMIO, а не
копию production-логики. Проверяются:

- Успешный snapshot: точные 27 чтений в прежнем порядке, один CNT, ни одной
  записи. Возвращённые us/ms и остаток проверяются на границе us32 rollover.
- Каждый из 13 конфигурационных отказов до CNT и каждый после CNT: точный
  префикс операций до отказавшего регистра включительно, без последующих
  чтений/записей. Выходы и все остальные поля контекста неизменны; разрешены
  только ожидаемые state/fault. Отдельная последовательность проверяет изменение PSC сразу после успешного
  snapshot. Восстановление регистра не снимает fault;
  последующие snapshot/now_us/now_ms не читают MMIO и сохраняют старое время.
- Ошибка конфигурации имеет приоритет над одновременно превышенным service
  delta; service fault после полной проверки также не публикует время.
- Init: точный порядок 48 чтений и 13 записей; повторный init занятого контекста
  и неверная частота без MMIO; шесть ранних RCC/busy отказов до владения;
  каждый из 13 readback-отказов сразу после CEN с сохранением владения TIM2.
- Stop: точные пять чтений и одна запись; все пять ранних выходов
  (gate/reset до записи, CEN readback, gate/reset после записи); повтор после
  устранения причины, сохранение fault и освобождение владения только при
  успехе. Повторный Stop и snapshot остановленного контекста не читают MMIO.

91 сценарий записывают все фактические MMIO-операции и итоговые поля состояния
в `current.trace` и `sanitized.trace`. Сравниваются именованные поля, а не
байты C-padding; callback/context представлены проверенными признаками
идентичности, без зависимых от ASLR адресов. Канонические утверждения работают
самостоятельно. Для прямого сравнения с доступным старым исходником:

```sh
TIMEBASE_BASELINE_SOURCE=/absolute/path/to/old/mt_timebase.c \
OUT=/tmp/motortester-timebase-inline-compare sh tests/timebase-inline/run.sh
```

Это компилирует указанный старый `.c` с текущим совместимым заголовком и тем же
тестом, затем требует побайтового совпадения `baseline.trace` и `current.trace`.
Для исходной правки baseline — commit `86577225059f396d39718ffb00c4347028c31933`,
SHA-256 старого `mt_timebase.c`:
`d9dd3c3f027b5b7082c7c50b53643f01b4daa8448441401dd990cb06a1c35b7c`.
Старый production-файл не дублируется в тестах; Git и baseline-файл для обычного
запуска не требуются. Тесты не заявляют исчерпывающую формальную эквивалентность
всех возможных состояний или реального hardware.

Негативные контроли, не изменяющие production-дерево:

```sh
python3 tests/timebase-inline/negative_controls.py /tmp/motortester-timebase-inline-negative
```

В отдельном `OUT` создаются четыре изменённые копии: пропуск чтения, перестановка
двух чтений с одинаковыми здоровыми значениями, дублирование Stop-readback и
лишнее чтение RST при уже отсутствующем gate. Каждая обязана завершиться
ошибкой утверждения теста. Лог сохраняет исходный SHA-256 и полные команды.
