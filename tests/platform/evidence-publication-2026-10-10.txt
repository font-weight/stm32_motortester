Проверены окончательные SHA-256 автора, включая уточнение README о квантовании

Дополнительный файл публикации — этот текст. Бинарные файлы не публикуются.

Это личное повторение публикатором авторского набора, не независимый вердикт.
Critic-A отдельно связывает свой отчёт с точным опубликованным commit SHA.
До такого заключения: BLOCKED_EVIDENCE, score: null; draft, без merge/приёмки.
Базовые acquisition/protocol drafts также не принимаются этой публикацией.

  OUT=$(mktemp -d)
  ASAN_OPTIONS=detect_leaks=0 BUILD_DIR="$OUT" \
    ARM_CC=/path/to/arm-none-eabi-gcc \

  arm-none-eabi-size "$OUT/adc_timer_dma.o"

  arm-none-eabi-nm -u "$OUT/adc_timer_dma.o"
  cat "$OUT/adc_timer_dma.su"

Для только host-прогона опустить ARM_CC и ARM_NEWLIB_INCLUDE.
Strict C11: -std=c11 -Wall -Wextra -Werror -Wpedantic -Wconversion -Wshadow
-fno-short-enums -O2. Второй host-прогон: -O1 -g, ASan+UBSan.
ARM: -mcpu=cortex-m3 -mthumb -mfloat-abi=soft -Os -ffreestanding,
-fno-short-enums, strict warnings, function/data sections и stack-usage.
Все приведённые команды завершились с exit code 0.

Интерпретация и незакрытые границы:
- text = 2324 B; data = 0; bss = 0 относятся лишь к одному relocatable object.
- ARM ABI: context 856 B, block 28 B, I/O callbacks 16 B. Контекст выделяет
  вызывающий код: bss=0 не означает отсутствие потребления RAM.
- Неразрешён memset; runtime/линкер должен предоставить реализацию.
- Наибольший собственный compiler frame 40 B не равен полному stack budget:
  callback chain, вызывающий код, runtime, IRQ и USB здесь не учтены.
- Не доказаны полный firmware link/map/stack, startup, USB/Windows, реальная Fs,
  DMA arbitration, аналоговая точность, плата, LV-001, зажигание или автомобиль.
- Никакой уровень готовности MVP не присваивается. CI не запускался.
