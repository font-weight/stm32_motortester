## Source and reference-manual review

I read the exact upstream and patched reset, initialization, EP0-open, endpoint
write and ISR paths, then inspected the complete generated ARM reset path.
[RM0008 Rev21](https://www.st.com/resource/en/reference_manual/cd00171190.pdf),
§23.5.2 pp.644–647, distinguishes retained completion flags from the other endpoint
fields reset by bus/FRES. Clearing both CTR flags requires writing zero; the same
zero preserves toggle-on-one STAT/DTOG fields during ordinary operation. Section
23.5.1 p.643 states that EF=0 prevents transaction handling. These rules support
the patch only after the hardware-reset postcondition, not as a generic close or
software-reset operation. The corresponding cached official PDF was checked
against SHA-256 `4c1b8ac2729cc1f45a4685eea9e91e6139e24e58804fba21e27201dfcc2ad149`;
web rendering of the full 13 MB document exceeded that tool's size limit.

The patch is confined to `handle_bus_reset`, under `STM32F103xB`. Existing
DADDR=0 precedes eight physical endpoint writes; software transfer ownership is
cleared before the existing EP0 rebuild; existing EF enable remains last. Original
vendor bytes are retained and the build copy is generated by hash-pinned patching.
The old allocation/PMA reset and EP0 behavior are preserved.

The issue is real under the documented model: original reset leaves nonzero-slot
CTR while EA becomes zero. The next ISR can route that physical slot through
logical EP0 and stale transfer state. Merely assigning a new software epoch when
such an event reaches the core would not establish its original hardware identity.
The patch removes this particular retained-flag source before publishing reset.
It does not identify already queued events or revoke a callback already executing.

No remaining P0/P1/P2 implementation finding in the stated scope. The author
explicitly requires a real bus/FRES reset and exclusive reset handling. Neither
DADDR=0 nor this patch creates a target-wide critical section. HP/LP nesting,
SOF-before-reset, a reset arriving after the ISR's initial snapshot, reset inside
an active callback and later stale DCD submissions remain separate problems.
The final README states those boundaries rather than treating the model as proof.

## Personally reproduced executable evidence

Environment: Linux x86_64, Python 3.12.14, GCC 14.2.0. Strict model flags include
C11, pedantic errors, warnings as errors, Wshadow, O1 and no LTO. Sanitized variants
use ASan+UBSan with recovery disabled. LeakSanitizer is excluded under the documented
ptrace restriction; the original failed leak run is retained by the supporting
package, not represented as a passing leak check.

1. I verified the complete supporting source/evidence manifest, copied inputs,
   sources and tools to an isolated directory and ran its frozen final runner.
   All 23 expected executions matched: 12 strict/sanitized runs across original,
   candidate and guard-disabled profiles with 3/8 logical endpoints, plus 11
   deliberately damaged candidates that were compiled and rejected. Original and
   guard-disabled runs successfully demonstrate the unwanted old behavior; these
   are negative controls, not positive device-correctness results.
2. The model executes 26 extracted functions. I inspected extraction and manifests:
   25 bodies are byte-identical; only `dcd_int_handler` receives six ISTR-store and
   three ISTR-read access substitutions. A temporary EP0-open call seam observes
   preconditions and forwards once to the exact original function. EPnR writes
   model rc_w0 and toggle behavior; FIFO, PMA and event sinks are explicitly fake.
   This is not the complete native DCD, real MMIO, TinyUSB core or CDC enumeration.
3. Tests cover all physical slots separately and together, RX/TX/both/no-CTR,
   stale fields in all logical transfer directions, repeated physical-reset
   postconditions, cold/direct helper entry, original slot7-to-EP0 misrouting,
   and fresh EP0/bulk buffer/FIFO primitives after cleanup. An explicit negative
   register test shows that writing zero without reset retains VALID/DTOG state.
4. I added an exhaustive retained-flag supplemental test: all 65,536 RX/TX
   combinations across eight physical slots, for 3 and 8 logical endpoints in
   strict and sanitized builds. All four binaries pass. Checks per binary are
   6,815,745 for logical3 and 7,471,105 for logical8. This shares the reviewed
   supporting register-access model; it is additional state coverage, not an
   independently authored second peripheral model or a concurrency proof.
5. My separate preprocessing test confirms every byte outside the reset body is
   unchanged. Six non-F103 macro controls preprocess identically; the F103 case
   adds exactly the sweep operation and ownership clear. This is conditional
   source invariance, not a build or execution claim for six other MCUs.
6. The supporting tooling regression test passes its seven protected-path cases,
   symlink handling and before/after source/candidate mutation detection. The
   final full matrix records identical input hashes before/after. These tooling
   defects were raised and corrected by the integrator before this review freeze;
   I did not discover or claim to execute the earlier vulnerable runner.
7. Eleven independent patch-tool invocations pass: normal output, existing and
   aliased outputs, symlink/directory cases, source/patch/result corruption,
   concurrent output creation between patch and exclusive-open, and missing output
   parent. Inputs and existing outputs remain unchanged on rejection. This reuses
   my earlier USB-003 tooling test with the three artifact names adapted; it is
   not claimed as newly invented test logic.

## Whole-unit ARM evidence and limits

I reran the author's complete upstream/patched DCD translation-unit compilation
using official ARM GCC 14.2.1, Cortex-M3/Thumb GNU11, -Os, full enums and explicit
pinned include/config paths. Exact object hashes:

- Original: `21065ac3d4295f783d35b08f2fd7389702ce68111c592a9ebb663378f9441f02`.
- Patched: `c5f5f547e9cb1a46703b69fee6aac91875733639a39bbdb44773a8d0380453b3`.

Text/rodata is 2,790 versus 2,802 bytes, data 0 and bss 131 in both. Both compilations
retain five upstream conversion warnings. The patch adds an unresolved `memset`
call; the 12-byte object delta excludes any linked runtime implementation and
cannot establish full firmware fit. Reset's local stack record is 24 bytes,
not its complete call chain or IRQ stack. Disassembly shows DADDR halfword disable,
eight halfword endpoint stores, a 96-byte transfer clear, EP0 allocation/rebuild,
then EF enable. Actual APB ordering/timing, ARM execution and complete linkage
are not measured by this evidence.
