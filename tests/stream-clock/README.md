# Проверка расширения часов потока: только native

Проверенная версия: `87fde951c391c7504234c3dbc346d9f85dbcf89a`.
База: `29e24d879d78731c6c914503c90b5b2462986d79`.
Изменение: только `firmware/platform/mt_live_clock.c` и `.h`, 67 новых строк.

Новый тест вызывает настоящие `mt_live_clock`, INLINE `mt_timebase` и native
`mt_live_device`. Подменяется только MMIO TIM2/RCC регистровой моделью.
Функция `mt_timebase_snapshot` не подменяется. Сам тест не изменяет production.

## Запуск

Нужны Python 3, GCC/совместимый C11-компилятор и доступные ASan/UBSan.
Git для запуска не нужен. Используются исходники репозитория либо его полного
source-export; отдельная вложенная копия прошивки в этот каталог не включена.

Из корня репозитория:

```sh
python3 tests/stream-clock/run.py . --mutations
python3 tests/stream-clock/run.py /path/to/source --out /path/to/new-output --mutations
```

Source root обязателен; каждый входной файл должен совпасть с
source-manifest.json. Без --out создаётся уникальный внешний временный каталог.
Существующий явный output отвергается без перезаписи. Пути с пробелами
поддерживаются. Для запуска из другого каталога укажите полный путь к runner.
`CC` позволяет выбрать компилятор. Результаты, точные команды, версии,
хеши, stdout/stderr и исходники самого теста/runner сохраняются в output.

Три программы запускаются отдельно в strict C11 и ASan+UBSan:
1. `test_live_clock.c`: 137 сценариев в семи группах, включая 70 000
   наблюдений с независимым oracle и чередованием других клиентов TIME
2. Существующий `tests/timebase-inline/test_trace.c`, который также запускает
   прежние TIME и coherent-snapshot тесты
3. Существующий `tests/protocol/live-device/native/test_live_device.c`:
   79 сценариев native endpoint

Санитайзеры работают с `-fno-sanitize-recover=all`,
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` и
`ASAN_OPTIONS=detect_leaks=0:halt_on_error=1`. Проверка утечек не заявлена.
Отрицательные мутации запускаются отдельно в strict-режиме. Для каждой
требуется именно диагностическое сообщение assertion failure; ошибка сборки
или случайный ненулевой exit не считается обнаруженной мутацией.

## Что проверяется

- Один свежий валидированный snapshot: 27 чтений, один CNT и ни одной записи
- Init на новом хранилище, неверные аргументы и остановленный источник
- Все 13 проверяемых RCC/TIM2 регистров до и после CNT, при init и now
- Сохранение последнего принятого состояния только внутри объекта;
  наружу при отказе возвращается `UINT64_MAX`, а не старое время
- Неубывающие миллисекунды, независимые us32/ms32 и переполнения CNT/us32/ms32
- Собственное обслуживание wrapper: 32000 мкс допускается, 32001 мкс
  отвергается, даже когда другие клиенты своевременно обслуживают TIME
- Отдельная проверка ms-разности после алиасинга us32
- Sticky failure, обычный reset/backstep источника и отказ самого TIME
- Точная граница `INT64_MAX` и защита перед переполнением; большой epoch
  внедряется с сохранением согласованности всех младших счётчиков
- Настоящий endpoint отвергает sentinel в step/receive/offer и после write;
  уже выданные байты не объявляются отозванными. Проверен и его отдельный
  запас 500 мс до `INT64_MAX`

13 мутаций проверяют чувствительность этих утверждений: удаление каждой
временной границы, ошибочное равенство на границах, потерю sticky failure,
обрезание до ms32, вывод ms из us32, потерю проверки переполнения, старое
время при отказе, лишний snapshot, пропуск обновления last_us и принятие
некорректного времени самим endpoint.

## Происхождение и пределы

Регистровая модель и прежние регрессии повторно используются без изменений
из указанного SHA: `tests/timebase/test_timebase.c`,
`tests/coherent-clock/test_snapshot.c`, `tests/timebase-inline/test_trace.c`.
Новые wrapper-утверждения и runner написал независимый проверяющий,
не автор реализации. Содержимое точных входов закреплено хешами.

Намеренно показаны три ограничения: пропущенный полный оборот TIM2;
общий оборот us32/ms32; запрещённый reset в неотличимую эпоху. В этих опытах
отказ не обнаруживается. Это подтверждает необходимость заранее заявленных
условий обслуживания/владения, а не надёжность обнаружения любого зависания.
Начальная эпоха wrapper равна наблюдаемому ms32 при init; неизвестные полные
обороты до init не восстанавливаются. Источник нельзя сбрасывать, пока живы
потребители старых отметок; wrapper надо обслуживать независимо от других
клиентов TIME, во всех состояниях устройства.

Не проверены ARM-код, карта/стек, реальные задержки, MCU/кварц, USB/ADC binding,
Windows, плата или сигнал. Новый образ не собирался. Этот результат не
принимает базовое ADC-изменение и не закрывает готовность потока/прибора.

Каждый новый запуск сохраняет receipt.json, provenance.json и логи в своём
output. Независимые первоначальные отчёты и неудачные тестовые предшественники
хранятся отдельно от репозитория; в этот каталог они не включены. Их точные
идентичности и область вердикта приведены в сопровождающем PR. Здесь находятся
переносимые тест, runner и manifest для собственного повторения проверки.
