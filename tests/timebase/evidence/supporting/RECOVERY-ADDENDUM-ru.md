# TIME001: восстановление независимых свидетельств после сброса среды

10.10.2026. По сообщению координатора публикации около 14:18:43 UTC рабочая среда была сброшена; локальный каталог исходного прогона утрачен. После этого выполнено следующее:

- Из сохранённых входов инструментов восстановлены `test_timebase_independent.c`, `run-independent.sh`, `REPORT-ru.md`. Их SHA256 побайтово совпали с зафиксированными до сброса значениями; проверка записана в `RECOVERED-ORIGINAL-SHA256SUMS`.
- `subject/mt_timebase.c/.h` скопированы из снимка независимого Critic-A; оба SHA256 совпали с исходными `b403cc8f…` / `61313596…`. Значения указаны полностью в `RECOVERED-SUBJECT-SHA256SUMS`.
- Сохранённый исходный отчёт оставлен неизменным. Указанный в нём старый полный журнал `b0bc1b44…` относится к досбросовому запуску; оригинальный файл этого журнала не восстановлен и в комплект не включён. Его текст не выдаётся за новый или уцелевший исходный лог.
- Создан отдельный `run-recovery.sh`: исходные тестовые команды сохранены, изменены только явная метка восстановительного прогона, имя нового журнала и путь завершающей проверки `cmp` к восстановленному снимку.
- Выполнен новый фактический прогон. Все 16 групп PASS в строгой GCC 14.2 C11-сборке и ASan+UBSan; GCC `-fanalyzer` без диагностик. LSan отключён, как и прежде. Полный новый stdout/stderr: `logs/independent-host-recovery-run.txt`.

Новый скрипт запускается командой `./run-recovery.sh` из этого каталога. Завершающее сравнение рассчитывает на снимок `/workspace/shared/critic-a-timebase-review-recovered/snapshot/firmware/platform/`; вне данного workspace допускается адаптация только этой проверки пути. Новый manifest `RECOVERY-SHA256SUMS` содержит актуальные файлы и binaries. Отладочный путь входит в бинарник ASan, поэтому его hash после переноса каталога отличается; hashes исходников теста и реализации не изменились.

Ни в исходном, ни в восстановленном наборе этого исполнителя не было сохранённого pre-fix исходника/лога дефекта Stop. Первый успешный snapshot был уже с повторной проверкой gate/reset. Проверяется регрессия исправленной версии; утраченное историческое воспроизведение не выдумывается.

Границы исходного отчёта сохранены: только host-модель, без аппаратного доказательства, утверждения измеренной частоты, непрерывности через сон/debug halt, общего software-ready или вердикта критика. Новые проверки не отменяют обязательный независимый quality-gate.
