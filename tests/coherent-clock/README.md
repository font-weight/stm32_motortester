# Согласованная пара TIM2: программная регрессия

Черновая проверка `mt_timebase_snapshot`. Используется существующая авторская
регистровая модель `tests/timebase/test_timebase.c`; её прежний набор также
выполняется целиком. Дополнительный ожидаемый результат вычисляется из
независимого 64-битного числа прошедших тиков только в тесте. Это не отдельная
аппаратная модель, не измерение длительности callback и не приёмка платы.

Из корня репозитория:

```sh
OUT=/tmp/motortester-coherent-clock-tests sh tests/coherent-clock/run.sh
```

Раннер собирает текущий production `firmware/platform/mt_timebase.c` вместе
с новым тестом. Выполняются strict C11 `-O2` и отдельный ASan/UBSan `-O1`.
LeakSanitizer отключён, проверка утечек не заявляется. Выходы создаются
только в указанном `OUT`; production и исходная модель не переписываются.

Проверяется:

- Одна успешная пара относится к одному чтению CNT, со всеми 27 MMIO-чтениями
  прежнего полного update и без MMIO-записей.
- 10 049 пар сверяются с 64-битным ожидаемым временем: границы миллисекунды,
  перенос остатка, переполнения CNT16, us32 и ms32. Миллисекунды остаются
  самостоятельными и не вычисляются из уже переполненного us32.
- NULL, совпадающие выходные указатели, неинициализированное/остановленное
  состояние, отсутствие callback и sticky fault возвращают отказ без
  публикации выходных значений. Перекрытие выходов с объектом часов запрещено
  контрактом API и здесь не используется.
- Каждая из 13 проверяемых конфигураций RCC/TIM2 нарушается перед snapshot
  и отдельно сразу после чтения CNT. Все 26 случаев отклоняются; счётчики,
  остаток и last_counter не публикуются, восстановление регистра не снимает
  sticky fault.
- Наблюдаемые 32 000 тиков принимаются, 32 001 отклоняются, также через CNT
  rollover. Прежний тест демонстрирует необнаружимый alias пропущенного
  полного оборота, а не объявляет его обнаруженным.
- Модель задержки 5 мс после аппаратного чтения CNT не сдвигает одну из шкал
  отдельно: возвращается согласованная более ранняя пара; следующее чтение
  учитывает задержку. Проверены также границы CNT16/us32/ms32.

Последняя проверка доказывает контракт snapshot, а не весь путь запуска.
Отдельно нужны тесты ADC binding: задержка после пары должна войти в
`first_sample_delay_us`, ошибки snapshot должны отклонять запуск до драйвера,
а guard USB/TIME, проверка CEN и повторяемый Stop должны сохраниться.
Физические тайминги, IRQ, точность генератора и успешный ARM на плате этим
набором не подтверждаются.
