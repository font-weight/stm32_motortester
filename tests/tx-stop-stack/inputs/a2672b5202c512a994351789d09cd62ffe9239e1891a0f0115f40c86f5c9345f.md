# TX002: локальные supporting tests уменьшения стека Stop

Задача: [Issue #70](https://github.com/font-weight/stm32_motortester/issues/70). Проверяется только замена временной полной копии `mt_wire_message` на 12 значимых байтов ABORT с восстановлением сообщения после успешной проверки вместимости и уплотнения очереди. Исходники кандидата и frozen USB005 не изменялись. Публикация, CI, merge и `host/**` не выполнялись.

## Проверки и границы oracle

Оригинальные 14 suites исполняются отдельно на old/new в строгой native сборке и ASan+UBSan. Строгий запуск дополнительно исполняет неизменённый исходный `run.sh`; постоянные бинарники обоих вариантов и полный журнал остаются в evidence.

Differential harness компилирует old/new как отдельные translation units с разными публичными именами функций. Общий production codec остаётся неизменным. При каждом действии сравниваются результаты API, значимые поля активных сообщений, управляющие поля очереди, текущий encoded frame при ненулевой длине, диагностические query API и накопленные фактически принятые байты. После успеха не сравниваются padding, хвост payload за `payload_length`, неактивные slots и frame при `length=0`; они не являются наблюдаемой семантикой API. При отказе `enqueue`/`stop` сравниваются **все байты** каждого объекта с его собственным снимком до вызова. Input messages также должны остаться неизменными. Событие poll без PROGRESS проверяется побайтово.

11 differential suites, всего 11 580 сценариев:

1. 1024 сочетания сохранения всех 12 байтов ABORT и порядка replies. Это **намеренные byte-copy probes**: 256 значений reason и ненулевые reserved patterns не объявляются допустимыми семантическими payload протокола. Очереди создаются публичным API transport, который их допускает.
2. 24 отдельные проверки всех шести штатных причин ABORT (1..6) с `reserved:u16=0`, supplied/NULL fallback и ещё не начатым ABORT после zero acceptance.
3. 256 partial-head вариантов BEGIN/DATA/STATUS/reply с prefix 1..64, сохранением ранее начатого кадра и переносом ABORT.
4. 5 zero-acceptance вариантов, включая уже кодированный ABORT с provisional sequence и `offset=0`.
5. 128 committed END/ABORT вариантов без второго terminal.
6. 45 argument-rejection/atomicity сценариев; queued ABORT позволяет не использовать отсутствующий либо некорректный supplied fallback, как в исходной реализации.
7. 1 сценарий обычного FULL и полного резерва Stop: partial DATA, два replies, ABORT, STOP_ACK, STATUS, ровно шесть слотов.
8. 1 сценарий wrapping time, границы 999/1000 ms, latch fault и HELLO recovery; также проверка NOT_NEGOTIATED без изменения объекта.
9. 10 000 детерминированных последовательностей публичного transport API, seed `0x19700270`. Это проверка достижимых состояний транспортной очереди, не модель полномочий dispatcher и не end-to-end валидатор protocol payload.
10. 3 отдельно помеченных **private-state defensive controls**: искусственно повреждённая длина/тип запроса ABORT и искусственный future-capacity layout. Они не объявляются штатными состояниями или новым контрактом private fields.
11. 93 old-session partial-head случая после HELLO, включая старый STOP_ACK и старый ABORT. Новый session должен получить собственный terminal и STOP_ACK.

Итого 11 577 public-API сценариев (из них 1024 byte-copy probes), плюс 3 private-state controls. Это ограниченное детерминированное покрытие, не исчерпывающее доказательство эквивалентности всех возможных состояний.

10 compile-valid mutations меняют только output snapshots: reason, хвост payload, session, type, zero-init, length, reply flag, сохранение prior replies, capacity preflight и запись `stop_ms` до полного preflight. Mutation засчитывается только если компиляция успешно завершена, отрицательный тест остановлен assertion и внешние входы/toolchain неизменны. Compilation error не засчитывается как обнаруженный дефект.

19 runner controls проверяют existing outputs, вложенные/родительские input paths, lexical и resolved aliases, отдельные backing parents symlinked source/script/evidence, SHA mismatch и отсутствие входа/компилятора до mkdir, чистое compiler environment, binding toolchain hashes, сохранение failure receipt и полное перемещение набора в другой каталог.

## Runtime integration

`runtime_overlay.py` создаёт отдельную копию base и заменяет в этой копии только `mt_tx.c/.h` проверенным кандидатом. Затем запускает неизменённый существующий `runtime-tests/run.py`, 28 сценариев strict и 28 ASan+UBSan. Проверяется SHA именно того TX, который попал в скомпилированный runtime snapshot.

Исполняются реальные RUN001, TIME001, guarded ADC003, acquisition/controller/RX, TX, USB005 adapter/bridge/epoch и TinyUSB core/CDC/FIFO. Моделируются MMIO, DCD/USB completion, IRQ mask и ADC samples. Runtime evidence **не подтверждает** ARM ABI/stack, linker RAM budget, настоящий PRIMASK/NVIC, latency/WCET, плату, электрические параметры, native USB или Windows 10. Уменьшение target stack должно проверяться отдельным ARM build evidence владельца задачи. LeakSanitizer отключён и не заявляется.

## Неизменённые app/control регрессии, обязательное дополнение Issue70

Первый отчёт покрывал TX и runtime, но не заменял прямо обещанные в Issue70 старые app/control suites. По замечанию независимого критика этот пробел закрыт отдельным прогоном. Первоначальные README, RESULTS и manifest сохранены в `evidence/metadata-before-app-control/`; прежние receipts не изменены.

В `pinned-regressions/` восстановлены 47 точных GitHub blobs:

`harness/pinned_regressions.py` исполняет неизменённые исторические shell-скрипты по их reproduction docs, с `bash -x`/`sh -x` для сохранения точных compile/execute команд. SOURCE/OUT явно направлены в свежие отдельные snapshots. Исходные строгие и sanitizer flags сохранены; compiler wrapper, изменение тестов или подстановка более нового controller не использовались. Каждый набор выполнен дважды: с собственным исходным TX и с TX002. В candidate snapshot изменён **только `firmware/transport/mt_tx.c`**; header идентичен. Список изменённых путей и SHA всех исходных/test файлов до/после зафиксированы в receipt. Controller C сохранён от PR35: SHA256 `0ef2f27441c41817867bd91336964aa65daa10732c7203fa85d97650253622ed`.

Исправлен только harness, subsequent r2/r3/r4 прошли. Отдельный намеренный запуск `/usr/bin/false` сохраняет FAIL receipt. Неудачи не удалены и не переименованы в успешные тесты.

## Воспроизведение

Требования: Python 3.12+, системный GCC-совместимый native compiler, существующие неизменённые input trees. Для каждого запуска нужен новый output вне lexical/resolved input roots и backing parents. Все параметры допускают перенос в другую директорию; абсолютные пути ниже — пример текущего расположения.

```sh
T=/workspace/shared/tx-stop-stack-tests
B=/workspace/shared/usb-bridge-publication/base-checkout
C=/workspace/shared/tx-stop-stack-draft
python3 "$T/harness/run.py" --base "$B" --candidate "$C" --original "$T/original" --out "$T/evidence/fresh-strict"
python3 "$T/harness/run.py" --base "$B" --candidate "$C" --original "$T/original" --out "$T/evidence/fresh-sanitize" --sanitize
python3 "$T/harness/negative_controls.py" --base "$B" --candidate "$C" --original "$T/original" --out "$T/evidence/fresh-mutations"
python3 "$T/harness/test_runner.py" --base "$B" --candidate "$C" --original "$T/original" --out "$T/evidence/fresh-runner"
```

Runtime с явными переносимыми путями:

```sh
python3 "$T/harness/runtime_overlay.py" \
  --runtime-tests /workspace/shared/runtime-tests \
  --runtime /workspace/shared/runtime-draft \
  --base "$B" --candidate "$C" \
  --adc /workspace/shared/adc-commit-draft \
  --bridge /workspace/shared/usb-bridge-draft \
  --epoch /workspace/shared/usb-epoch-draft \
  --dependencies /workspace/shared/usb-dependencies \
  --cdc-support /workspace/shared/usb-cdc-tests \
  --bridge-support /workspace/shared/usb-bridge-tests \
  --out "$T/evidence/fresh-runtime"
# Для отдельного sanitized output добавить --sanitize.
```

Supporting tests не являются независимым вердиктом Critic-A и не присваивают оценку приёмки. Следующий шаг: связать их с отдельным ARM stack/map evidence и независимым ревью точного кандидата.
