# ADC-003: допуск финального запуска выборки

Задача: https://github.com/font-weight/stm32_motortester/issues/62.
Автор: Dot A. Черновик; независимой приёмки пока нет.

Добавлен mt_adc_dma_start_guarded и соответствующий guarded initializer
связки контроллера. Старые API сохранены для отдельного driver-level использования.
Они сами по себе не закрывают гонку USB reset → начало выборки.

Подготовка GPIO/TIM/ADC/DMA, стабилизация и калибровка выполняются вне guard.
После подготовки enter сохраняет прежнюю маску прерываний. Чтение времени и
allowed проверяют исходную эпоху команды и актуальное здоровье часов; затем
одна критическая секция охватывает DMA enable, внешний trigger ADC, проверку
тактовой конфигурации, TIM3 CEN, второе чтение времени и readback.
Allowed повторяется после второго чтения времени. Scope не получает новую
эпоху автоматически. Все callbacks должны быть короткими и невложенными;
определение guard не пересекается со storage драйвера и остаётся неизменным.

При отказе допуска используется отдельный внутренний ADMISSION fault.
Перед cleanup восстанавливается прежняя маска: потенциально ожидающий Stop
не выполняется внутри этого guard. Если прежняя PRIMASK уже равна 1,
восстановление оставляет её равной 1: функция не отменяет внешнюю блокировку
прерываний. Вызывающий отвечает за её длительность; «после leave» не означает
безусловно включённые IRQ. Неудачный Stop сохраняет владение и storage.
Новый fault не является изменением wire-контракта.

Guarded start_before_us отмечает начало финального guard после enter.
Поэтому это нижняя граница интервала commit, а не измеренная точка CEN.
Весь измеренный интервал должен укладываться в прежний лимит 20 мкс.
Фактическая длительность на STM32 ещё не измерена.

После leave может немедленно выполниться отложенный USB IRQ. Успешный return
означает допущенный атомарный commit; он не обещает, что эпоха остаётся живой.
Foreground owner должен снова проверять транспорт/часы перед дальнейшими
командами и выводом и своевременно выполнять quarantine/Stop.

Кандидат не предоставляет сам PRIMASK backend, USB/clock allowed callback,
полный owner pump или startup. Их нужно явно связать и проверить отдельно.
Native MMIO/IRQ model, ARM objects, полный ELF и физический опыт являются
разными уровнями доказательств. Само чтение исходников не считается тестом.
