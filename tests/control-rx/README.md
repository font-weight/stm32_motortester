# RX-001: воспроизводимая публикация черновика

Связано с issue #37. База публикации — IO-001 PR39, commit
`aad61d598aa9996b1cd2c0587e936e19118fc087`, tree
`ca4922aa98faba106816cc824cb0612d9b8aae0c`. Все 212 файлов базы сохраняются
с прежними Git blob SHA и режимами. Прибавляются только три файла RX
в `firmware/app/` и `tests/control-rx/**`; существующие тесты IO, платформы
и контроллера не копируются и не меняются.

Dot A лично написал реализацию, документацию API и авторские тесты.
Публикатор не менял их. Поддерживающий проверяющий и Critic-A независимо
написали свои тесты, не исправляя проверяемую реализацию. Их разные
проверки и уровни доказательств не складываются в оценку качества.

## Запуск из корня репозитория

Нужны Bash, Python 3 и совместимый C11-компилятор с ASan/UBSan.
Лично повторено GCC 14.2.0. Все исполняемые результаты создаются вне
исходников; в пакет входят только текстовые исходники, скрипты и логи.

```sh
OUT=/tmp/rx001-check bash tests/control-rx/reproduce.sh
TC=/path/to/toolchain/usr OUT=/tmp/rx001-arm sh tests/control-rx/arm-check.sh
```

ARM-проверка требует существующего toolchain GCC 14.2.1 с newlib headers;
его загрузка/установка не выполняется скриптом и не включена в пакет.
`reproduce.sh` запускает:

- авторский RX и составной RX → controller → ADC/DMA register-model → COBS
  набор strict C11 и ASan/UBSan; команды составного теста идут по 7 байт;
- отдельный поддерживающий RX-набор: 24 сценария / 594167 проверок,
  независимое создание CRC/COBS входов и настоящий controller;
- исходные авторские и 39 независимых регрессий controller;
- те же 39 сценариев через RX: 577333 проверки вместо 576994, с сохранением
  всех утверждений о состоянии/данных/порядке/callback;
- неизменённые два reproducer прежних ошибок Stop;
- самостоятельный oracle Critic-A: 147442 сценария сегментации wrapper,
  настоящий stream/wire и подставленный соседний controller;
- независимый Python wire oracle и точное сравнение двух 20-оконных
  транскриптов: 344 кадра, 98281 байт, 40960 исходных кодов.

Оба транскрипта имеют SHA-256
`f697347414bf21bdddfafe2c091215c147bc9946b6dff40b9e76bb47a2935caf`.
Они генерируются при запуске и не добавлены в репозиторий как бинарники.
ASan/UBSan запускаются с `detect_leaks=0`; LeakSanitizer не проверен.

Для отдельного supporting-набора:

```sh
bash tests/control-rx/independent/run.sh "$PWD" /tmp/rx001-independent
```

Его неизменённый исторический runner по умолчанию ищет `snapshot`, поэтому
в репозиторной упаковке путь к исходникам следует передавать явно.
`independent/prepare_old_rx.py` отличается от сохранённого исходного
генератора только параметрами входной/выходной папки. Он создаёт адаптированный
harness во временной папке. Runner сверяет его diff с историческим
`evidence/supporting/old-controller-rx/adapter.diff`: ровно девять ожидаемых
возвратов IGNORED заменены на документированный суммарный OK wrapper;
production-код и прежний harness не редактируются.

## Provenance и сохранённые попытки

- `evidence/critic-a/CRITIC_A_CONTROL_RX_REVIEW.md` — точный исходный финальный
  локальный отчёт Critic-A, SHA-256
  `59cda7d317ca8f15893156c1b86f8fd81e885588ef554f13ad39bacb79ccdc32`.
  Его формулировка до публикации сохранена; актуальная привязка к immutable
  head публикуется самим критиком в PR и не выдаётся за уже существующую здесь.
- `evidence/supporting/REPORT.md` — отдельный поддерживающий отчёт, без балла.
  Его описания `snapshot/`, `history/`, старых выходных папок и абсолютные
  пути в логах относятся к исходной исследовательской среде. Они сохранены
  как provenance, а не как команды текущей упаковки; пользоваться командами выше.
- Начальный header, начальные тексты Critic-A, обе неудачные строгие компиляции
  supporting-harness с их точными `test-used.c` и логами, второй и финальный
  запуск сохранены. Ошибки были в тестах, не в production-коде: misleading
  indentation/unused helper, затем unsigned-to-byte conversion. Изначальный
  generator ожидал 5 замен вместо фактических 9 и остановился; исправление
  документировано автором supporting-отчёта. Эти попытки не названы PASS.
- `evidence/supporting/deliverable.sha256` — исторический полный manifest
  исходного тестового каталога. Некоторые его файлы намеренно не включены
  (бинарники, snapshot и копии базовых tests); не запускать его как проверку
  полноты этой выборочной упаковки. `publication-manifest.json` перечисляет
  фактически опубликованные добавления с SHA-256 и Git blob SHA.
- Начальный упаковочный runner завершил все тесты, но завершился с exit 1
  на диагностическом `tail -1` с несколькими файлами. Он и лог сохранены
  в `evidence/publication/initial-packaging/`; заменено только на `tail -n 1`,
  итоговый PASS перенесён после вывода результатов, затем весь runner повторён.
- `evidence/publication/` содержит лично повторённые публикатором текстовые
  результаты финальной составной проверки. Исходные evidence не заменяются.

## Границы результата

Вердикт Critic-A: **BLOCKED_EVIDENCE, score null**. В проверенном bounded
локальном модуле не показан P0/P1; это не PASS и не приёмка.
ARM wrapper — 296 байт text; RX owner — 1128 байт, включая stream/message;
feed frame — 48 байт. Известная цепочка Stop с RX — 2992 байта без runtime,
caller и IRQ. ARM object SHA-256:
`2070737496f4dda694277c8a1786544751a3859bc53d6066a3c8a361e204d8c7`.
Это частичные статические данные компилятора, не полный firmware fit.

Открыты реальные USB endpoint/IRQ/loss detection и enumeration, coherent
startup clocks, WCET и сервис ADC строго чаще 2560 мкс, full ELF/linker map,
RAM/Flash/stack/IRQ/runtime, Windows interoperability и физические
низковольтные измерения. Предел 64 байта не доказывает временной предел.
Номинальные 50 kS/s не являются измеренной частотой. Общие gates/Critic-B
не закрыты. CI не запрашивается, workflow в базе отсутствует. Ветка остаётся
draft: без merge, закрытия issue и статусов software-ready,
low-voltage-verified или ignition-verified.
