# Историческое различие A и эмулятора B: исходники воспроизведения

Это неизменённый минимальный программный опыт из issue86, поставленный для
восстановления окружения B. Он воспроизводит **старую пару точных версий**,
а не проверяет последнюю ветку host. Ожидается различие, не готовность прибора.
Точные источники и ограничения — в [PROVENANCE.md](PROVENANCE.md).

## Запуск

Нужны уже установленные native GCC (C11) и Python 3.10+, Linux/POSIX. Проверенная среда:
GCC 14.2 и Python 3.12; Windows/macOS не проверены. ARM-компилятор, Qt,
pyserial, USB/COM и плата не требуются. Ничего не скачивается и не устанавливается.

Из любого cwd, заменив пути на свои абсолютные, выполните один entry point:

```sh
env -i PATH=/usr/bin:/bin HOME=/tmp LANG=C LC_ALL=C TZ=UTC \
  /usr/bin/python3 -I -B "/absolute/checkout/tests/native-host-reproducer/reproduce_early_release.py" \
  --out "/absolute/existing-parent/new-replay"
```

Каталог результата должен быть новым, его родитель уже существовать. Выберите
его вне checkout: runner проверяет absolute/new/parent, но сам не запрещает
пересечение с исходниками. Не используйте симлинки и конкурирующие записи.
Пробелы в путях допустимы. Чистое окружение в команде существенно: subprocess
компилятора иначе наследует настройки вызывающего процесса. Это кооперативный
локальный эксперимент, не hermetic или hostile-filesystem sandbox.

Runner проверяет 30 файлов по REPRO_MANIFEST.json, заново собирает native C
bridge, затем импортирует ровно закреплённые Python-модули B. `-O/-OO`
запрещены: assertions обязательны. Отсутствие GCC, несовпадение входов,
ошибка компиляции или behavioral assertion должны завершать запуск ненулевым
кодом. Не стирайте неудачный output и не выдавайте его за успешный; для повтора
задайте новый каталог. stdout/stderr внешней команды сохраните при необходимости
отдельно, особенно для preflight/timeout, которые ещё не записали compile.log.

Ожидаемый exit0 печатает DEMONSTRATED_DIVERGENCE. RESULTS.json содержит
точные входные hashes, compile argv, обе последовательности и времена;
compile.log — журнал сборки. Локально также создаются executable bridge,
JSON trace и byte captures `.bin`. Они не входят в этот исходный пакет.

Не запускайте run_audit.py напрямую как общую проверку: это сохранённый
исторический helper. Его main обращается к внешним wire-логам, которых здесь
нет. Указанный выше entry point вызывает только два изолированных опыта
раннего RELEASE; старый внешний путь при таком запуске не используется.

## Что показывает опыт

У каждого устройства приняты все 2048 отсчётов DATA и ровно 1 из 46 байт END
при t=100 мс. В t=1099 мс, до остальных байт END, намеренно отправляется raw
RELEASE с правильными ID и CRC **своего** массива. Оставшийся END принимается
при t=1099 мс.

- A: ERROR(BUSY), затем WAIT_RELEASE, начало hold timer=1099; expiry=6099.
  Нового захвата нет.
- Старый эмулятор B: RELEASE_ACK, затем WAITING; hold timer не запускается.

Обычный host должен дождаться полного проверенного END для receipt. Этот опыт
намеренно нарушает такое поведение; из него не следует отказ обычного host.
Синтетические waveform A и B различаются, поэтому CRC различны, но корректны.
Ранее независимый Critic-A также проверил CRC отдельным декодером и нормальный
host control; ссылка в PROVENANCE. Это не новая физическая USB-проверка.

После исправления эмулятора старое ожидание различия должно перестать проходить.
Не заменяйте B fixture новым файлом и не меняйте manifest ради «зелёного» старого
опыта. Новая проверка паритета и её exact tuple оформляются отдельно владельцем B.
Публикация этого пакета не назначает severity, score, общий контракт или merge.
