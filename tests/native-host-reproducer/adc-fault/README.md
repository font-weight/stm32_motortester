# Ошибки АЦП: native-прошивка и закреплённые компоненты ПК

Это воспроизводимый программный опыт из issue91, а не проверка последней
версии приложения B. Он подаёт реальные байты native-сборки PR95 через
неизменённые wire/session/window компоненты PR74
`c44bae42b19ec8208c2ebee4a3e662ce1b7ff240`.
Плата, ARM-код, pyserial, COM/USB, GUI и файлы приложения не запускаются.

## Два отдельных набора исходников

1. Выгрузите целиком **снимок поставки, содержащий этот README и reproduce.py**.
   Его точный SHA берётся из соответствующего PR и отчёта независимого ревью.
   Исходный PR87 сам по себе ещё не содержит эту новую папку. Существующие
   `../snapshots/pr74/host` и C fixture должны оставаться рядом со скриптом.
2. В другом каталоге выгрузите прошивку PR95:

```sh
git clone https://github.com/font-weight/stm32_motortester.git "/absolute/firmware checkout"
git -C "/absolute/firmware checkout" checkout --detach b607392cb4f1cc19918e2795359df4680b645643
```

Поставка опыта и PR95 принадлежат разным веткам. Нельзя подставлять прошивку
из первого checkout по умолчанию. Runner проверяет 14 необходимых C/H по
SHA256, а не объявляет весь произвольный checkout точной копией Git tree.

Уже должны быть установлены Linux/POSIX, Python 3.10+ standard library,
native GCC с C11/libc и ASan/UBSan. Проверенная автором среда: Python 3.12,
GCC 14.2; переносимость Windows/macOS не заявлена. Ничего не устанавливается
и не скачивается во время опыта. Git после выгрузки исходников не нужен.

Из любого cwd:

```sh
/usr/bin/python3 -I -B "/absolute/probe checkout/tests/native-host-reproducer/adc-fault/reproduce.py" \
  --firmware-root "/absolute/firmware checkout" \
  --out "/absolute/existing output parent/new adc host run"
```

Оба аргумента обязательны. Пути абсолютные и нормализованные, без симлинков;
пробелы поддерживаются. Output ещё не существует, его parent уже существует.
Output не может пересекаться ни с одним checkout. Для повторного запуска
нужен другой новый каталог; старые и неудачные результаты не удалять.

## Что проверяется

Матрица: STATUS(ERROR) reason1/2 × есть/нет выделенного окна × есть/нет
предыдущего завершённого окна × порции декодера 1/64 байта × strict/sanitizer.
Всего 32 выполнения, а не 32 физических измерения.

- При выделенном окне приходит ABORT2/3, затем STATUS(ERROR1/2); при ожидании
  без окна только ERROR. Проверяются состояние, счётчик потерянных окон и
  отсутствие повторного запуска прошивки.
- Закреплённый SessionController выбирает ровно один DEVICE_ERROR recovery
  с запросом reset_transport и preserve_fragments; очередь TX пуста.
  ARM/CONFIG/Stop и применимый старый RELEASE отклоняются с STATE.
- Если до ошибки получено полное окно, WindowReceiver проверяет его CRC и
  все 2048 отсчётов. Удерживаемый **тестовым вызывающим кодом** WindowResult
  после ошибки побайтно прежний. Это не проверка сохранности GUI или файла.
- Strict и ASan/UBSan дают одинаковые полные/fault wire bytes и исходы.
  Sanitizer обязателен, без fallback; утечки отключены (`detect_leaks=0`).

Fault вызывается через настоящий controller helper с синхронной fake hardware,
а не физический DMA или полный runtime/USB. Тестовый dispatcher создаёт
WindowReceiver только после BEGIN. Ранний ABORT принимается на уровне сессии;
прямая подача такого ABORT пустому WindowReceiver возвращает ORDER. Это
проверенное условие интеграции, не доказанный дефект реального dispatcher B.
В recovery event числовая причина STATUS отсутствует (`frame/fault=None`);
по этому событию нельзя различить два случая. Реальный outer runtime,
хранение диагностики, применение transport reset и последующий HELLO здесь
не проверяются. Совместная приёмка A/B остаётся отдельной.

## Воспроизводимость и отказы

`inputs.json` закреплён SHA в entry point. Он связывает 14 файлов прошивки,
пять прежних package inputs и новый C adapter. Алгоритмы/исходники B не
изменены и второй host parser не создан. Старые REPRO_MANIFEST и runner
раннего RELEASE не меняются и не вызываются; они не обязательны новому опыту.
Минимальная поставка состоит из 23 файлов в двух корнях: эти 19 прежних
входов и четыре файла этой папки. README не является исполняемым входом.

C adapter заимствует проверенный вспомогательный опыт: изменена лишь строка
include на соседний закреплённый fixture. Root переработал переносимый
entry point: пути, manifests, output, чистое окружение процессов, ограничение
ожидания ответа и сохранение отказов. Поведенческие assertions опыта сохранены;
проверка отсутствующего frame/fault добавлена явно. Автор вспомогательного
опыта и независимый критик не отождествляются. Вердикт относится только к
точной опубликованной редакции, не переносится из старого PR87 автоматически.

Runner требует `-I -B`, отвергает `-O/-OO`, неверные pins и существующий output.
Компиляция ограничена 120 секундами, ответ native child — 5 секундами и 65536
байтами; дочерний процесс при завершении/ошибке закрывается и ожидается.
Сохраняются команды, tool hashes/версии, compile stdout/stderr, case traces,
полные и fault-only wire bytes, частичные данные при отказе и RESULTS.json.
Preflight-отказ ещё не создаёт output: stdout/stderr при необходимости
сохраните внешним перенаправлением. Ненулевой exit не является PASS.

Это не hermetic build: системные headers/libc/sanitizer runtime не поставлены.
Предполагается стабильная кооперативная файловая система и доверенный native
инструментарий. Hash-проверки не являются защитой от одновременной злонамеренной
подмены. Разрешения прошивать плату, аппаратной оценки или совместного
вердикта успешное выполнение не выдаёт.
