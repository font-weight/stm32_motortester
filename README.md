# Диплом: микроконтроллерный мотортестер

Прибор для записи и просмотра сигналов системы зажигания на ноутбуке. **Текущий MVP: STM32F103C8T6, встроенный АЦП, один канал, native USB Full Speed и приложение Windows 10 с тёмной темой.** Автоматический анализ и ML отложены; второй канал — после готовности основы. Сохраняем возможность последующих расширений.

Исходные условия: **до 100 000 KZT, семь месяцев от 23.09.2026**; есть Blue Pill с сообщённой маркировкой STM32F103C8T6, ST-Link V2, мультиметр и источник на модуле DC-DC ZK-4KX, питаемом, по уточнению пользователя, от ноутбучного адаптера с номиналом 19 В; модель/ток адаптера и изоляция цепи питания не подтверждены. Ограниченно доступен осциллограф в вузе. Для измерений планируется отдельный стенд. Nissan Almera 2002 года, предположительно 1,8 л, остаётся дополнительным объектом: тип зажигания пока неизвестен. Подробности — в [требованиях](requirements.md).

## Сейчас

В этом интеграционном черновике объединены текущие A-исходники и рецепты ADC-сборки, регрессионный пакет и уточнения HW/LV. База — main после PR100/103/105; аналоговые исходники PR96, исторический native-host пакет PR103 и отдельный опыт ошибок АЦП PR105 сохранены. Это не приёмка MVP и не утверждение, что данный черновик уже слит в main. Выбор версии — ниже; фактический статус — в [прогрессе](docs/progress.md).

Распределение: Dot A сам пишет код и ведёт прошивку/электронику, Dot B сам пишет и ведёт Windows-приложение целиком. У каждого независимый критик; результат с оценкой ниже **9,5/10** не принимается. Общие решения и релиз проходят обоих критиков по [правилам приёмки](docs/quality-gate.md). Общую интеграцию выполняет A. Исходный пакет передачи — редакция 1.2, архив с суффиксом `v3`; это историческая постановка, последующие указания владельца имеют приоритет.

Для передачи: основной Dot получает [DOT_START.md](DOT_START.md), второй — [DOT_PEER_START.md](DOT_PEER_START.md); обоим нужен доступ ко всему [репозиторию font-weight/stm32_motortester](https://github.com/font-weight/stm32_motortester). Подробное [ТЗ MVP](docs/mvp-spec.md) и [правила совместной работы](docs/coordination.md) — часть задания, а не уже реализованный результат.

Ближайший путь: согласовать протокол, карту выводов и сборку → реализовать сквозной низковольтный захват по USB → завершить приложение и аппаратный тракт. Конкретные питание/соединения платы ещё нужно проверить. Подбор катушки и коммутатора (**HW-001B**) идёт параллельно. G474, внешний АЦП, Ethernet, .dm2 и ML находятся вне MVP; менять платформу без пересмотра задания не нужно.

## Уточнение текущей области

По указанию владельца от 12.10.2026 стенд разрабатывается отдельно; вход
внешней синхронизации и управление стендом исключены. Остаются запуск записи
из приложения и однократная запись полного разряда с горением и затуханием.
Обычный Single и успешное окно не доказывают физическую полноту; параметры
и независимая проверка ещё требуются. См. [требования](requirements.md) и
[актуальную функциональную схему](hardware/functional-diagram/README_RU.md).

Исторический hash-bound пакет analog-source и его экспорты ниже сохраняются
без изменений. Прежние упоминания внешнего запуска в нём не являются текущим
обязательным узлом; [актуальное уточнение области](requirements.md)
не разрешает монтаж или работу с зажиганием.

## Как выбрать исходники

Выбирайте либо целый текущий интеграционный снимок, либо точный исторический SHA по ссылке. Не смешивайте исходники, manifests и результаты разных снимков. Статус слияния и точную проверенную версию определяет соответствующий PR.

- **Повторить проверенную историческую сборку без платы:** [инструкция PR89, SHA `477513d19785d598737c496d719da6f42f061fce`](https://github.com/font-weight/stm32_motortester/blob/477513d19785d598737c496d719da6f42f061fce/firmware/build/BUILD_IMAGE_README.md#синтетическое-воспроизведение-без-платы). Это учебный повтор object → ELF/BIN/HEX с синтетическим паспортом `TEST_ONLY_NEVER_FLASH`. Его независимая проверка относится к этому снимку; изменения PMA/ADC ниже в него не входят. Тестовые 3024/0 не задают инженерный запас для реальной платы.
- **Воспроизвести текущий ADC-черновик:** [object → условный ELF/BIN/HEX](firmware/build/BUILD_IMAGE_README.md#синтетическое-воспроизведение-без-платы). Основа image-рецепта — [PR102, SHA 555ced8](https://github.com/font-weight/stm32_motortester/commit/555ced8bbaf8fdc5bc008c8699ac46348235a069), с отдельно проверенной условной границей 3064 байта. Это не прежний PMA/WAIT_RELEASE пример 3024. [Регрессия WAIT_RELEASE/Stop](tests/wait-release/README.md) перепривязана к ADC-исходникам; она не добавляет ADC fault-сценарии. Для них есть отдельный [native-опыт с закреплёнными host-компонентами](tests/native-host-reproducer/adc-fault/README.md); он не проверяет действующий runtime или GUI B. Результаты компонентов не заменяют проверку точной новой композиции. [Совместная ADC-политика с B/Critic-B](https://github.com/font-weight/stm32_motortester/issues/91) остаётся открытой.
- **Воспроизвести экспорт аналоговых схем отдельно от прошивки:** [исходный пакет в main после PR96, SHA `451f08dd6dfc96c6eb2ab0dc1c7573bdb4b5298e`](https://github.com/font-weight/stm32_motortester/blob/451f08dd6dfc96c6eb2ab0dc1c7573bdb4b5298e/hardware/analog-source/README_RU.md#полная-повторная-проверка-экспорта). Нужны Python 3.12+, KiCad 9 и Inkscape; экспорт создаётся локально в новом внешнем каталоге. В `main` включены исходники, а не готовые PDF/SVG; [PR96 слит 12.10.2026](https://github.com/font-weight/stm32_motortester/pull/96). Проверка полноты экспорта не подтверждает схему или допустимость подключения.

Ни один маршрут не разрешает прошивку платы и не подтверждает аппаратную готовность. [Условия по реальной плате и аналоговому тракту](https://github.com/font-weight/stm32_motortester/issues/29) остаются открытыми; приложение Windows и его реализацию ведёт Dot B. Текущие решения о приёмке проверяйте в соответствующем PR и в [правилах приёмки](docs/quality-gate.md).
