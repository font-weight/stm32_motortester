# Проект последовательности первого низковольтного включения — R8

Статус: черновик A для проверки, не команда подключать или прошивать сейчас.
Экземпляр AH20261017001, исходники firmware96002ce, build20261017.
Точный образ и его hashes — в REGISTRY.json. Окончательный комплект ещё
должен получить применимые совместные заключения и явное решение оператора.

## Границы

Только Blue Pill, ноутбук Windows10 x64, его исправный USB-кабель данных,
имеющийся ST-Link для отдельной записи и мультиметр для DC-уровней.
Источник19В, ZK-4KX, катушка/свеча, автомобиль, генератор и осциллограф
не подключаются. Первый источник сигнала — собственная общая точка платы
для ограниченной проверки нижнего DC-уровня, не амплитудной калибровки.

Питание только через штатный native USB-разъём платы. Силовые выводы
3.3/5.0V программатора и платы не соединяются с другими источниками.
Для SWD используют только уверенно определённые SWDIO/SWCLK/GND; номера
контактов клона по универсальной картинке не назначаются. Если адаптеру
нужен target-reference вход, его назначение сначала подтверждают отдельно;
неизвестный силовой вывод не подсоединяют «для проверки».

## До разрешённой записи

1. Получить полный комплект с совпадающими контрольными суммами и точной
   инструкцией к выбранной версии инструмента прошивки. Не использовать
   прежние TEST_ONLY_NEVER_FLASH и не переименовывать их в рабочие образы.
2. Сверить MCU, штатный кварц8MHz и R8 с паспортом. Повторно снимать фото
   уже установленных надписей не требуется. Проверить именно предстоящую
   карту USB-only/SWD и отсутствие иных источников/нагрузок.
3. Установить безопасные точки общей земли/3V3/VDDA и A0↔PA0 по карте
   этой платы. Модель мультиметра и его DC-диапазон/погрешность записываются
   для будущего сопоставления напряжения и кода, не подставляются условно.
4. Владелец 17.10.2026 подтвердил, что старую прошивку сохранять не нужно.
   Backup не является дополнительным условием. Старая программа будет заменена; сохранение остальных областей
   Flash не обещается: область автоматического стирания зависит от
   установленного backend. Отдельная команда mass erase, обход RDP и
   изменение option bytes этим не разрешены. При защите чтения/записи остановиться.
5. Перед фактической записью отдельно подтвердить выбранный образ/адрес,
   сохранение старого содержимого при необходимости и условия питания.
   Подготовка комплекта сама эту операцию не выполняет.

## Отдельный этап flash/verify, без сигнала

1. Источник сигнала отсутствует. Соединения выполняются при снятом питании.
   SWDIO/SWCLK/GND соединяются согласно проверенной карте. Питание платы
   затем подаётся только её USB; питание ST-Link не дублирует питание платы.
2. Записывается только согласованный BIN по адресу0x08000000 или HEX с его
   адресами штатным инструментом. Выполняется фактический verify/readback;
   сохраняются версия инструмента, журнал, время, ошибки и точные hashes.
   Размер текущего BIN33556B, адресный интервал[0x08000000,0x08008314).
3. Нельзя считать кнопку Run/переход по PC эквивалентом reset: этот firmware
   требует настоящего Flash system reset с исходным MSP/VTOR/масками.
   Предпочтительный последующий переход — отсоединить USB платы и USB ST-Link, затем все
   провода ST-Link, проверить BOOT0=0, затем включить плату только native USB.
   Точный порядок и подтвердившиеся напряжения входят в итоговый протокол.
4. Прежняя успешная запись другой программы полезна, но не заменяет verify
   именно этих байтов. При любой ошибке программирования ARM запрещён.

## Первый USB bring-up, без ARM

Компьютер бодрствует; приложение пока не открывает порт автоматически.
Ожидаемые descriptor значения: VID1209/PID0001, bcdDevice0100, serial
AH20261017001, CDC и расчётный bus-power100mA. Это ожидаемые значения из
образа, а не уже наблюдённые. Их и реальный COM фиксируют средствами ОС.
Идентичность ST-Link/VCP не подменяет native USB STM32. При несовпадении,
неизвестном устройстве, ошибке драйвера, нагреве или просадке — остановиться,
сохранить наблюдение; не перебрать другие порты и не обещать исправление
повторными подключениями.

Пусковой/рабочий ток, поведение при selective suspend и фактические шины
не подтверждены сборкой. Awake host сам по себе не исключает selective
suspend; эти условия должны быть рассмотрены до конкретного сеанса.
Режим сна/пробуждения, внешнее питание без VBUS и remote wake не испытываются
и не объявляются совместимыми. Одно число bMaxPower не является USB-сертификацией.

## Перед первым DC-окном

При снятом питании и отключённом ST-Link соединить только проверенный
ADC1_IN0/PA0 с собственной GND/VSSA платы по утверждённой карте. Не касаться
выводов MCU щупом вместо доступных площадок без отдельной методики.
После отдельного разрешённого включения записать реальные VDDA и ADC_IN,
точки, прибор/диапазон/погрешность, время и условия. Даже для нулевого входа
номинальные3.3V/0V не подставляются в таблицу как измерения.

После перечисленных условий используется явный COM, связанный с этим
экземпляром и наблюдаемым serial, HELLO/CAPS/build и принятый CONFIG.
Предлагаемые настройки: Auto, profile 1, source 0, pretrigger 0, level_code 2048,
rising (edge 0), timeout 1000 мс. Порог — код АЦП, не измеренные вольты.
При постоянном нулевом входе ожидается auto_timeout без trigger index/marker;
это проверяемое ожидание, не основание исправлять фактические метаданные.

Узкий ручной маршрут B принят здесь как проект для независимого рассмотрения:
1. До реального порта провести репетицию на точном доставленном EXE с эмулятором:
   Auto/pre0/1000 мс, имитация фронта выключена; Record, Stop, завершённое Save,
   свежее открытие .mtrec. Проверить 2048 исходных отсчётов полного окна,
   auto_timeout, отсутствие trigger index/marker. Прежний Normal smoke этого
   не заменяет. Зафиксировать SHA EXE, настройки и результат репетиции.
2. Для отдельно разрешённого физического опыта нажать Record один раз.
   Нажать Stop при первом НОВОМ полном окне именно текущей записи либо
   не позднее 5 секунд наблюдения после Record, если окно не появилось.
   Старая демо-кривая или ранее открытый файл не считаются новым окном.
   5 секунд — целевой срок действия оператора, не автоматическое отключение,
   watchdog или гарантия остановки; работа прошивки определяется протоколом.
3. Дождаться совпадающего подтверждения STOP_ACK, завершения записи на диск
   и фактического успешного Save. Затем заново открыть сохранённый .mtrec.
   Сохранить spool, частичные сегменты, события и ошибки без удаления.
   Сверить исходные отсчёты/происхождение и действительное число полных окон.
4. Возможны несколько окон с промежутками и конечный partial/abort-сегмент.
   Число всех сегментов не равно числу полных окон. Не обещается ровно одно
   окно или непрерывная запись. Ошибка завершает попытку без scan/reconnect/retry.

Основание B: https://github.com/font-weight/stm32_motortester/issues/94#issuecomment-6232791455 .
Его source-review относится к app244b. Для app dcafc563 нужна явная привязка
неизменённого recorder/runtime и репетиция реального Windows EXE. Это отдельный
малый ручной опыт, не полный LV-001 с прогревом и 20 попытками и не его приёмка.

Любое несоответствие/ошибка/потеря связи/изменение соединений запрещает
дальнейший ARM. Неизвестный фактический Stop не объявляется успешным по GUI;
при необходимости безопасного обесточивания единственный источникUSB
отсоединяют, поскольку все остальные источники исключены картой. Частичные
файлы сохраняют как неполные, без скрытого повторного запуска.

Этот план ещё содержит незакрытые физические условия и проверку точного GUI-плана B на новом EXE; он не может быть самопринят как законченная инструкция.


## Уточнённые средства и карта по маркировке

Владелец подтвердил Richmeters 102 и STM32Cube-расширение VS Code.
Номер версии расширения/выбранный backend определяются локальной справкой,
не угадываются. У ST-Link V2 используем подписи на реальном корпусе, не
цвет провода и не номер из универсальной картинки:

| ST-Link | Плата, отдельный SWD-разъём | Когда соединён |
|---|---|---|
| GND | GND | только flash/verify |
| SWCLK | SWCLK | только flash/verify |
| SWDIO | SWIO (буквальная маркировка платы) | только flash/verify |
| 3.3V / 5.0V / SWIM / RST | никуда | не подключать |

Маркировка платы подтверждена имеющимися изображениями. Перед подключением
оператор сверяет подпись именно контакта, к которому вставляется провод:
обратная сторона разъёма зеркальна. Не назначать номер контакта клона.
Если конкретный программатор требует VTref, сначала установить его отдельный
вход по документации; выход питания нельзя считать VTref. Для захвата
снимаются все три SWD-провода и USB самого ST-Link.

Доступные точки платы: GND отдельного SWD-разъёма, 3V3 того же разъёма;
A0 на длинной гребёнке — выбранный сигнальный вход. Надписи G/3.3 на длинной
гребёнке и 5V возле USB — дополнительные точки только после проверки их связи.
A0 не является землёй: перемычку A0→GND устанавливают при снятом питании
только после успешной записи/readback выбранного образа и снятия ST-Link.
До записи старой программы эта перемычка не устанавливается.

Перед напряжением нужно один раз установить связь A0↔PA0, GND↔VSSA и
3V3↔VDDA. В LQFP48 STM32F103C8 это соответственно выводы 10, 8, 9 согласно
ST DS5319 Rev20, Figure 8/Table 5. Звуковой сигнал прозвонки сам по себе недостаточен: RM102 подаёт его
при сопротивлении ниже 50 Ω. Для предполагаемой общей сети записать в
режиме Ω сопротивление сомкнутых щупов и проверяемого пути. Установить
прямую дорожку/нулевую перемычку без неизвестного последовательного
элемента; разность с сопротивлением щупов не более 1.0 Ω — лишь
консервативная проверка контакта, не доказательство топологии. При
неизвестной схеме, промежуточном элементе или неоднозначном пути не
приравнивать 3V3 к VDDA и остановиться для уточнения точки.
Проверка сопротивления возможна только на полностью
обесточенной плате, без обоих USB и SWD. Если нет тонкого безопасного щупа
или нельзя уверенно определить вывод по метке первого контакта, к ножкам
MCU не прикасаться: остановиться для выбора доступной площадки. Под
напряжением к ножкам MCU не подлезать. Сам снимок/надпись эту связь не доказывает.

Если связь 3V3↔VDDA не установлена, измерение 3V3 записывается только как
3V3; строка VDDA остаётся неизвестной и ARM не допускается. Если связь
установлена, показание на 3V3 можно записать как измерение общей питающей
сети с указанной точкой, сохранив ограничение: падение на дорожке у MCU
не измерено отдельно. Аналогично GND должен относиться к VSSA этой платы.

## RM102: подготовка и предложенные пределы сеанса

Чёрный щуп — COM, красный — VΩHz; переключатель V, на экране DC, диапазон
6.000 V (автоматический выбор). HOLD должен быть выключен: показание
должно обновляться; режим REL/относительного нуля, если доступен, также
выключен. Не использовать положение тока, даже если
красный щуп физически стоит в том же гнезде. Не замыкать источник щупами в
режиме A/mA. На плате нет никакого другого источника, кроме её USB.

До включения закрепить чёрный щуп на проверенной GND. Красным касаться
только доступной проверенной площадки, не соседних выводов. Для переноса
зажимов/перемычек питание снимать. Записать показания с единицами, диапазон
и признак DC; отсутствие батарейного предупреждения. Не заполнять результат
словами «номинально 3.3/0».

Предлагаемые рабочие окна показаний — консервативные условия именно этого
сеанса, не новые паспортные пределы STM32 и не утверждение точности прибора:

| Измеряемая сеть относительно GND | Допуск показания для продолжения |
|---|---|
| VBUS на проверенной 5V-площадке | 4.80…5.20 V |
| 3V3, затем VDDA по проверенной общей сети | 3.15…3.45 V |
| A0 после его перемычки на собственную GND | модуль показания не более 0.020 V |

При выходе за эти окна, нестабильном показании, ошибке режима/единиц,
запахе/заметном нагреве, сообщении USB overcurrent, отключении устройства
или сомнении убрать единственное USB-питание. Ничего не переключать под
питанием ради подбора результата. После ошибки продолжение требует разбора.

Указанная в RM101/RM102 инструкции DC-погрешность — ±(0.5% показания +
3 единицы младшего разряда). Для 3.300 V на диапазоне 6 V это ±0.0195 V,
а не ±0.001 V. Это опубликованная спецификация, не подтверждение калибровки
имеющегося экземпляра. При 0.000 V разрешение/погрешность также не доказывают
идеальный ноль. На первом опыте сохраняются raw ADC codes, не калиброванные V.

Ток и пусковой выброс этой процедурой RM102 не измеряются: не вскрывать
USB-кабель и не переставлять прибор в последовательную цепь наугад.
Применимость ограниченного USB-only опыта опирается на отдельно проверенный
расчётный бюджет 100 mA и перечисленные условия; фактический ток/inrush,
USB suspend и полная USB-сертификация остаются непроверенными. Это ограничение
должно быть явно принято при final plan review. Сон/пробуждение не испытывать;
при suspend/disconnect/ошибке закончить попытку без reconnect/retry. Бодрствующий
компьютер сам по себе не доказывает отсутствие selective suspend.

Источники: ST DS5319 Rev20, https://www.st.com/resource/en/datasheet/stm32f103c8.pdf .
Брендированная инструкция RM101/RM102 доступна через зеркало
https://manuals.plus/m/8b9b77dc5d55ae307604961c80a3fc0ec7fc30996264dace301ddccf9cafe890_optim.pdf ;
производительский сайт при проверке не ответил. Это оригинальная модель 102,
не автоматическая подстановка спецификации 102+/Pro. Reference conditions
и traceable calibration этой инструкцией не установлены.

## Запись из существующего STM32Cube tooling

Использовать установленный STM32CubeProgrammer CLI, выбранный локальным
STM32Cube bundle/CubeCLT; не F5/Run проекта. Стандартный debug workflow может
запустить preBuild и прошить другой project binary. Точный путь/версия CLI
фиксируются до аппаратных действий. Современный cube: сначала --help и --list,
затем --resolve programmer, только если эта операция есть в справке.
Для старого CubeCLT существует STM32CubeCLT_metadata -j. Установка или
обновление набора автоматически не выполняются.

Будущая последовательность с выбранным по serial ST-Link и проверенным CLI:
- проверить BIN SHA-256/33556 B;
- NORMAL SWD connection, reset=SWrst, журналы и проверка MCU/Flash;
- -w «точный BIN» 0x08000000 -v;
- -u 0x08000000 33556 «новый readback.bin»;
- сравнить размер и SHA-256 readback с исходным BIN, сохранить оба и журналы;
- снять питание, убрать SWD, BOOT0=0, дальнейший power cycle по карте.

Ожидаемый SHA-256 BIN/readback:
bae2ef0461d26b8dd5c92496fcc621b5b84b2dbe4e6fb175cc4aa120d49fe041.
Диапазон: [0x08000000, 0x08008314). Не использовать -r32 вместо -u: его
ограничение 32 KiB меньше нашего образа. Не использовать -g как reset.
Полные PowerShell-блоки включены в соседний FLASH_SEQUENCE_RU.md,
SHA-256 e8c5948dc96ce89eef4924feaf984101b6aa13e917dc647af5bf4b446d0c09ff.
Они проходят независимую проверку вместе с этой редакцией. Это не
разрешение запуска аппаратной команды; локальные CLI/version/help
остаются предпроверкой до подключения. Сроки ожидания и безопасное
прекращение команды заданы в конце FLASH_SEQUENCE_RU.md.

Официальная CLI-справка:
https://dev.st.com/stm32cube-docs/prog/2.23.0/en/docs/markup/CubeProg_Command_Lines.html
https://dev.st.com/stm32cube-docs/stm32cubecli/latest/en/docs/markup/STM32CubeCLI_Command_Reference.html

Точный B manual R3 для dcaf: https://github.com/font-weight/stm32_motortester/issues/94#issuecomment-6233222469 .
Его applicability review не заменяет репетицию actual delivered Windows EXE.
До разрешения физического сеанса остаются final exact-kit review, проверенные
команды/карта, выбранный реальный tool и результаты соответствующей стадии.

Перед любой перестановкой SWD/щупов/перемычек отключаются ОБА USB: платы и ST-Link. Лишь после этого провода перемещаются; один отключённый USB платы не исключает подпитку через SWD.

Штатное завершение после успешного Save и свежего открытия: закрыть приложение, отсоединить native USB платы и закончить опыт. Не оставлять плату постоянно подключённой или без наблюдения. ST-Link на этой стадии уже полностью отсутствует. Сохранённые файлы и spool не удалять. Следующее включение — отдельный этап, не автоматический повтор.


Операторские сроки окончания: после Stop ждать matching STOP_ACK и готовности
Save не более 30 секунд; после команды Save и затем свежего открытия файла —
не более 60 секунд на каждое действие; после Close — не более 10 секунд.
При сообщении об ошибке прекращать попытку сразу. Эти сроки — предельное
наблюдение человеком, не новый программный watchdog. При превышении снять
native USB платы, сохранить видимый текст ошибки, пути spool и все имеющиеся
файлы как неполные; не выполнять новый Record/Connect и не выдавать зависшую
запись за успешно сохранённую. ST-Link и другие источники на этой стадии
отсутствуют, поэтому native USB — единственный источник питания.

В exact dcaf session.py задан RESPONSE_TIMEOUT_MS=1000 для отслеживаемого
ответа протокола. Его выполнение зависит от работы event loop; он не задаёт
гарантированное wall-clock время завершения Windows I/O/fsync/GUI close.
Для дисковой операции этот план не приписывает приложению несуществующий
гарантированный cutoff: именно поэтому задано отдельное наблюдение оператора.
После аппаратного отключения не удалять spool и частичные файлы и не запускать
повторный опыт. Зафиксировать состояние и разобрать незавершённый результат.
